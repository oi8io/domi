# 025 仓库只能影响提示词，能执行的东西只来自用户配置

- 日期：2026-09-16
- 状态：已采纳（PRD-M7-002 · PRD-M7-003 · INV-03 · INV-06）

**Context**：要支持仓库自带的规矩（AGENT.md）与项目级 Skill（`.domi/`），也要支持钩子。
其它工具的做法是让仓库里的配置文件声明钩子与权限——克隆一个仓库就等于同意它在你机器上跑命令。

**Decision**：
- 仓库里能被 domi 读取的只有两类**不可执行**的东西：`AGENT.md`（兼认 `AGENTS.md`）与 `.domi/skills/*/SKILL.md`。
- 两者都要经过**工作区信任**：第一次在某个仓库根打开会话时问；非交互默认不信任且不记住。
- 钩子、权限规则、MCP server、插件只在 `~/.domi/config.yaml`。代码里没有任何从仓库读取这些配置的路径。
- 钩子以用户身份、在会话 cwd 下 `sh -c` 执行，不沙箱（它就是用户写的命令）。在权限之后、执行之前（pre）与之后（post）运行，
  超时强杀并按拦截处理（fail-closed）。
- domi 不会自己创建 `.domi/`：只有 `domi init --project` 或会话里经 fs.write 确认才会出现。

**不选的**：仓库级 `.domi/config.yaml`（等于仓库提权）；给钩子加沙箱（钩子的用途就是跑用户的工具链）。

**Consequences**：团队想共享钩子需要各自写进自己的配置（或共享一个脚本、各自引用）。这是刻意的摩擦。
