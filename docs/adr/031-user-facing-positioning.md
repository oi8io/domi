# 031 对外定位改为面向使用者

- 日期：2026-10-19
- 状态：已采纳（用户 2026-10-19 拍板：README 介绍产品而不是介绍项目；定位句、目标用户、MIT 许可证、发 v0.1.1）
- 修改：`PRD-VISION.md` §1 一句话定位、§2 目标用户（v1.3 → v1.4）

**Context**：旧定位「会积累人格的、你能看见它每一步在想什么的本地 Agent 运行时」是站在项目内部写的。
「运行时」「事件流」「投影」是开发者词汇，用 domi 干活的人不关心。旧的目标用户写「有 CLI 习惯的开发者，明确不服务非技术用户」，
与「通用型 AI Agent，能协助用户完成各种复杂任务」（2026-10-15）对不上。README 也一直是维护者的开工手册，不是产品介绍。

**Decision**：
- 一句话定位改为：**domi 是一个通用 AI Agent，正在向 personal Agent 进化。** 它能帮你处理复杂任务：会做计划、懂编排，可中断、可恢复，每一步可跟踪、可追溯。场景包括但不限于编程、设计、办公。
- 三个支点不变，对外改用使用者能拿到的好处来说：Soul → 「可以定义人格，越来越懂你」；轨迹 → 「每一步看得见、能叫停、能回头查」；本地优先 → 「数据仅存本地，隐私无忧」。
- 目标用户改为实际使用 domi 把事做完的人，不限于开发者；删去「明确不服务非技术用户」。目前安装与使用仍需要会用终端，这是阶段性限制，不是定位。
- 对外文档（README、文档站 intro / quickstart、宣传主站）不出现事件流、daemon、投影、INV 编号等内部概念。原 README 的维护者内容迁到 `DEVELOPMENT.md`。
- 以 MIT 许可证发布。

**Consequences**：不变量（§5）与工程原则不动，它们约束的是实现，不影响对外说法。
「设计、办公」目前主要靠文件读写、命令、MCP 与 Skill 完成，还没有 browser use / computer use；对外照写场景，被问到时据实说明。
触发重新决策的条件：出现明确的非终端用户群（例如 Desktop 成为主入口），或 domi 改为以 SDK / 嵌入为主要用法。
