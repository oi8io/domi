# 024 编码工具：精确替换 + 过期写保护，搜索优先用 ripgrep

- 日期：2026-09-16
- 状态：已采纳（PRD-M7-001 · INV-03 · INV-05）

**Context**：domi 只有整文件写。真实仓库里改一行要重写整个文件，模型容易把没看到的部分写坏；搜索只能拼 shell。

**Decision**：
- `fs.edit` 用「old 恰好出现一次」的精确替换（抄 Claude Code / Codex 的编辑工具）。不用行号补丁：行号在多次编辑间会漂移，
  而字符串匹配失败时能明确告诉模型「没找到 / 有好几处」。
- 过期写保护：记本会话读到的内容哈希，写之前比对磁盘。只拦「读过之后被外部改了」，不强制 fs.write 先读（SPEC 取舍-2）。
- 文件清单走 `git ls-files -co --exclude-standard`；非 git 目录退回内置排除表。
- 搜索：`rg --json` 存在就用，没有就用 TS 逐行正则（用户拍板：没装也能用，装了自动用）。两个后端同一个输出结构。
- 后台命令：job 表在会话里，查询归 `fs.read`、终止归 `shell.exec`（PRD v1.9.1）。

**不选的**：unified diff 补丁（模型生成的 hunk 头经常算错）；随包带 rg 二进制（发行版每个平台多几 MB）；
自己解析 .gitignore（嵌套规则、全局 excludes 都要重做一遍，且会和用户的 git 不一致）。

**Consequences**：编辑失败率低、失败原因可读；代价是 old 需要足够长才能唯一，模型偶尔要重读一次。
