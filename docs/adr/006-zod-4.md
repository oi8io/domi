# 006 契约层用 zod 4

- 日期：2026-09-14
- 状态：已采纳

**Context**：`ENGINEERING.md` §4 定了"契约用 zod"，但没定大版本。脚手架装的是 3.25.76，而 latest 是 **4.6.5**。契约层是全项目改动成本最高的地方——目前只有 9 个事件类型、4 个消息类型、3 份 legacy fixture 和一份 `.api.md` 快照，迁移面正是最小的时候；等 M2 事件类型翻倍、用户数据落地之后再迁，成本是另一个量级。

**Decision**：升到 zod 4。三处 API 变化已落地：
- `z.object({...}).passthrough()` → **`z.looseObject({...})`**。语义不变（已知类型 + 未来新增字段必须保留，见 SPEC-M0-004），写法更明确
- `z.record(z.unknown())` → `z.record(z.string(), z.unknown())`（v4 要求显式 key 类型）
- 内省入口从 `_def.typeName` 变成 **`_zod.def.type`**，`scripts/gen-api-snapshot.ts` 相应重写

**Consequences**：换来解析性能与类型实例化开销的改善（事件类型会一直增长，后者比前者更重要），以及"现在迁比以后迁便宜"。代价有两条：
1. **`gen-api-snapshot.ts` 依赖 zod 的私有内省 API**。所以每次升 zod 大版本，这个脚本必然先红——**这是它该做的**：契约读不出来了，说明契约的读法变了，必须有人看一眼，而不是静默产出一份错的快照。已把这句话写进脚本注释。
2. `.passthrough()` 在 v4 仍可用但已废弃，未来版本可能移除；本项目统一用 `looseObject`，不混用。

**触发重新决策的条件**：① zod 5 发布且 4.x 停止安全更新；② `gen-api-snapshot` 因私有 API 变动连续两个版本无法适配——那时换成 `z.toJSONSchema()` 之类的公开出口重写快照生成。
