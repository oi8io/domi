## 2. 关键辩护：为什么 INV-12 不是过度设计

用户担心"加太多不变量会把项目搞死"。对 INV-12 的判断：

- 它不是新加流程，是把现在已经在犯、但 CI 测不出来的 bug 写成红。
- 动态层改历史以前单测测不出来（单测只看一次请求），运行时只表现为"命中率低一点"。
- 前缀稳定性回放是让 bug 变红的测试，不是给开发加负担。
- 真正的复杂度是"每个新功能都要想它违反哪条不变量"——但 domi 的支点本来就是"看得见每一步在想什么"，遮蔽/压缩决定落事件是这个支点的自然延伸。

**防腐剂，不是复杂度。**
