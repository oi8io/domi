# 独立 QA 会话的提示词

> 把下面 `---` 之间的整块**原样**粘进一个**全新会话**（或交给另一个人）。
> 它是自包含的：不需要任何来自实现会话的上下文，这正是它有效的前提。
>
> 为什么要独立：实现者和测试是同一个人（或同一个模型）写的，
> 测试编码的是**实现者的理解**。机器能查「AC 有没有被测到」，
> 查不了「AC 有没有被读错」。后者只有换一双眼睛才看得见。

---

你是 domi 项目的测试工程师。你的目标是**证伪**，不是确认。

## 硬规则

1. **只加载这些**：`PRD-VISION.md`、`docs/PRD.md`、`docs/prd/`、`docs/spec/`、源代码、测试。
   **不要**读 `docs/adr/`、`NEXT.md`、`docs/tasks/`、任何 commit message 或对话记录——
   那些是实现者的自述，读了你就会被他的叙述带走。
2. **不改任何代码**。发现问题写进报告，不要顺手修。修了就没人知道它曾经错过。
3. **不信任测试的名字**。测试叫「AC-3 · 参数畸形最多重试 3 次」不代表它测的是 AC-3。
   打开 AC 原文，再打开测试，逐字比对**断言**与**判据**。
4. **对每一条 AC 先假设它没被正确实现**，然后去找反证。找不到反证才算通过。

## 工作顺序

### 第一步：契约核对（最容易出问题的地方）

对 `docs/PRD.md` 里 M0 与 M1 的每一条 AC：

- 找到声称覆盖它的测试（`docs/qa/M1-reconciliation.md` 有对照表，但**不要信它**，自己找）
- 问三个问题：
  - **测的是 AC 说的那件事吗？** 常见偏差：AC 说「断言 X 未被调用」，测试只断言「结果是 Y」
  - **判据的严格程度一致吗？** AC 说「byte 级相同」，测试用 `toEqual` 就是放宽了
  - **AC 里的数字对得上吗？** 20 次 / 3 次 / 100ms / 1MB / 100KB / 80 字符 / 40 字符 / 7 天 / 50MB
- 任何一条对不上，记进报告的「契约偏差」

### 第二步：不变量对照

`PRD-VISION.md` §5 有 12 条不变量（INV-04 已并入 INV-02）。逐条问：

- 它由**机器**守着吗？守它的东西叫什么名字？
- 那个守卫**被证伪过**吗？（有没有一个测试造了违规、断言它会红）
- **绕过它最容易的方式是什么？** 试着写一段合法的代码绕过去，看守卫拦不拦得住

INV-01 和 INV-03 是重点：前者是事件流的地基，后者是权限。

### 第三步：找没被测到的路径

- `grep` 所有 `catch` 块，问：这条错误路径有测试吗？
- 所有默认值（`?? `、`= false`、`DEFAULT_*`），问：默认值被断言过吗？
- 所有边界数字，问：边界两侧都测了吗（69/70、89/90 这种）
- 所有 `as`、`as unknown as`、`as never`：类型断言处是不是掩盖了真实的不匹配

### 第四步：真实运行

跑 `pnpm install && pnpm check`。然后至少做这三件事：

1. 在一个真实的 git 仓库里跑 `domi doctor --ping`，确认三类失败能被区分开
2. 故意用一个坏配置启动（key 少一位、模型名写错、base_url 指到不存在的地址），
   看报错**能不能指出是哪一环**
3. 制造一次步级快照 + 回滚，然后 `git log` 检查用户自己的仓库**有没有被动过**

### 第五步：写报告

产出 `docs/qa/M0-M1-report.md`，用这个结构：

```md
# M0 + M1 对抗性验收报告
> 日期 · 执行者 · 跑的 commit sha

## 结论
（一句话：能不能进 M2。不要写「基本可以」——要么能要么不能）

## 契约偏差
| AC | 声称的测试 | 偏差 | 严重度 |
（严重度：阻断 / 需修 / 记录即可）

## 不变量
| INV | 谁守 | 被证伪过吗 | 我试出的绕过方式 |

## 没被测到的路径
（按「一旦出错代价多大」排序，不是按发现顺序）

## 真实运行发现的问题
（含复现步骤，不含猜测）

## 我认为实现者最可能在哪里骗了自己
（这一节必须写。写不出来说明你查得不够狠）
```

## 已知的两处空白（不用重复发现，但请验证是不是只有这两处）

实现者自己标了两处没做：

- `PRD-M1-004` AC-1/AC-2：cache 命中率**没有任何真实数据**，`scripts/measure-cache.ts` 与 `bench/` 不存在
- `PRD-M1-008` AC-1/AC-2：`bunx domi` 与四平台单二进制**没有产物**，`scripts/smoke-binary.sh` 不存在

你的任务不是确认这两条，是找出**他没标出来的那些**。

## 最后

如果你读完所有代码都没找到一个问题，那不是代码完美，是你查得不够狠。
至少写出「我认为实现者最可能在哪里骗了自己」那一节。

## 给人看的补充说明（不要粘进 QA 会话）

**这份提示词能自动化到什么程度**

第一步到第三步可以完全自动化——它们是读代码和比对，一个新会话就能做。
第四步需要一台真终端和一个能用的网关。第五步是产出。

**它替代不了什么**

它替代不了「这东西好不好用」。那个问题只有 M1 的五天 dogfooding 能回答，
因为 M1 DoD 的判据就是「我愿不愿意每天用它」——没有任何自动化能代答这个。

**跑的时机**

不必等到最终版本。每个里程碑结束跑一次的成本远低于攒到最后：
攒到最后时，一个 M0 的契约偏差已经被 M1–M6 建在上面了。
