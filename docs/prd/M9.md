> 触发：用户 2026-09-18 提出三个需求点（模型探测与 Provider 配置、中英双语、TUI 输入区），逐条澄清拍板

## 1. 为什么是这一章

M8 收口后九个里程碑的功能全部落地。这一章是第一批**体验与配置补强**，针对三个已暴露的日常摩擦：

1. **模型选择链路还停在"手填 + 硬编码清单"**：模型下拉的清单是 `modelCatalog` 拼出来的（配置的 models + 价目表前缀 + 内置 known models），不探测真实可用模型；且对话内现在**能切 provider**（Composer 手填 `模型名 [provider]`、TUI `/model 名 provider`），与"provider 是配置概念"的定位冲突。
2. **Provider 配置过于简单**：设置页硬编码 3 家 + 1 个网关，每项只有 api_key / base_url 两栏；没有厂商名、协议、启用/默认开关，也没有增删改。
3. **三端文案全中文硬编码**，无英文界面。
4. **TUI 输入区**：有占位提示与 `›` 提示符、无边框、对话流无滚动条、聊天框不固定。

## 3. 不做什么

- **不做模型能力运行时探测**（toolCall/vision/reasoning 维持 `capability.ts` 静态声明，PRD-M1-001 AC-2 不回退；探测本身是一次请求，违反"发请求前抛错"）
- **不引入第三方 i18n 库**——自写轻量 `t(key, params)` + 两份 locale 文件，独立 package 三端共用
- **对话内不再提供 provider 切换入口**：删掉 Composer「其他…」手填的 `[provider]` 语义与 TUI `/model` 的 provider 参数
- **不做协议扩展**：google 等一律经 OpenAI 兼容端点接入，`ProviderKind` 收敛为 `anthropic | openai`
- 不新增模型微调 / 自研模型（PRD-VISION §4 既有边界，不回退）

## 4. 需求条目

### PRD-M9-001 · 模型探测（GET /v1/models）

- **用户价值**：模型下拉列出**真实可用**的模型，不用手填模型名、不用维护价目表前缀
- **验收标准**：
  - AC-1: daemon 对每个 `enabled` 的 provider 调用 `GET {baseUrl}/models`；OpenAI 兼容协议带 `Authorization: Bearer <key>`，Anthropic 协议带 `x-api-key` 与 `anthropic-version: 2023-06-01`；成功时返回该 provider 的可用模型 id 列表
  - AC-2: 探测失败（网络错误 / 401 / 超时 / 非 2xx）时，该 provider **降级到本地清单**（`providers.<id>.models` + 内置 known models + 价目表前缀认出的模型 + 当前默认模型），不阻塞模型下拉
  - AC-3: 探测结果有缓存（默认 10 分钟），设置页提供「重新探测」按钮手动刷新
  - AC-4: 探测是真实出站调用，**不进 CI 门禁**（与 INV-08 同源：测试用 mock fetch 断言请求头、路径与降级行为）
  - AC-5: 探测结果与本地清单合并去重，模型下拉展示并集；provider 停用时不探测、不展示
- **验收方式**：`bun test`（mock fetch 断言请求头/路径/401 降级/缓存）+ 设置页与对话下拉手工走查
- **层级**：Negotiable
- **优先级**：P0

### PRD-M9-002 · Provider 配置模型升级

- **用户价值**：一个 provider = 厂商 / 协议 / base url / api key / 启用 / 设为默认，配置页可完整管理（增删改）
- **验收标准**：
  - AC-1: 配置结构升级：`providers` 每项含 `id`（唯一标识）、`name`（厂商名，如 OpenAI / Anthropic / DeepSeek / 自定义）、`protocol`（`openai | anthropic`）、`baseUrl`、`apiKey`、`enabled`（默认 true）、`default`（默认 false）
  - AC-2: 设置页「模型供应商」tab 支持**新增 / 编辑 / 删除** provider，七个字段齐全；删除后该 provider 从模型下拉消失、不参与探测
  - AC-3: `enabled: false` 的 provider：不出现在模型下拉、不参与探测、不能被设为默认
  - AC-4: `default` 全局唯一：把某 provider 设为默认时自动取消其他 provider 的 default；新会话默认使用 default provider 的默认模型
  - AC-5: **旧配置兼容**：现有 `model.provider` / `model.name` / `providers.<id>（旧结构）` 仍可读取；`domi doctor` 提示迁移到新结构并给出迁移命令
  - AC-6: `protocol` 决定适配器：`anthropic` → createAnthropic，`openai` → createOpenAI / createOpenAICompatible；能力矩阵按协议给静态默认值（用户可在 `model.capabilities` 覆盖）
- **验收方式**：config schema 单测（新结构校验 + 旧结构兼容）+ doctor 迁移测试 + 设置页走查
- **层级**：Negotiable
- **优先级**：P0

### PRD-M9-003 · 对话内模型选择（只选模型，不切 provider）

- **用户价值**：对话里一个下拉选模型，模型自带 provider 归属；provider 是配置概念，不在对话里出现
- **验收标准**：
  - AC-1: Web Composer 模型下拉**扁平列出全部已启用 provider 的可用模型**（探测结果 + 本地清单），模型名为主、provider 仅作归属标注（分组或后缀），provider 本身不可作为切换对象
  - AC-2: Composer「其他…」手填的 `[provider]` 语义移除：只能填模型名；模型名无法归属到任何已启用 provider 时提示去设置页配置
  - AC-3: TUI 提供等价入口：`/model` 命令去掉 provider 参数，只接受模型名；模型归属由 daemon 解析，无法归属时同样提示去设置页
  - AC-4: 切换模型仍产生 `model.switch` 事件、能力差集提示保留（PRD-M1-002 AC-2 不回退）
- **验收方式**：组件测试 + TUI 命令解析测试 + 手工走查（含跨 provider 模型混排）
- **层级**：Negotiable
- **优先级**：P1

### PRD-M9-004 · 国际化（中文 / English）

- **用户价值**：英文用户可读；切换语言不重装不重启（Web 即时生效）
- **验收标准**：
  - AC-1: 设置页「界面语言」三选一：**跟随系统 / 中文 / English**，默认跟随系统；手动切换立即生效（Web 即时，TUI/CLI 下次启动生效并提示）
  - AC-2: Web / TUI / CLI 的静态 UI 文案（按钮、标签、提示、空态、确认框、状态栏、按键提示）全部改走 i18n key；zh / en 两份 locale 覆盖同一 key 集合（CI lint 检查缺 key / 多 key）
  - AC-3: **面向用户的错误消息**（现有 `error.*` messageKey 体系，如 `error.invalid_api_key`、`error.unsupported_capability`）按当前语言渲染；内部日志、事件流内容、轨迹摘要、soul、prompt 层不翻
  - AC-4: i18n 实现为独立轻量模块（零第三方依赖），三端共用同一份 key 定义；key 缺失时降级显示 key 本身并在 `domi doctor` 标注
- **验收方式**：CI lint（key 一致性）+ 单测（t() 渲染与参数插值）+ 中英双语走查
- **层级**：Negotiable
- **优先级**：P1

### PRD-M9-005 · TUI 输入区与滚动

- **用户价值**：输入区干净、有明确边界、固定在底部；对话流长内容可滚动
- **验收标准**：
  - AC-1: 空输入框**不显示占位文字、不显示 `›` 提示符**，只保留光标
  - AC-2: **Enter 发送；Shift+Return 换行**（kitty 键盘协议主路径）；**Ctrl+J 兜底换行**（非 kitty 终端）；Alt+Enter 保留与否由实现定，行为与 Ctrl+J 一致
  - AC-3: 输入区**上下各一条边框线**（四边不闭合，配色跟随主题）；多行输入时边框行为正确（边框在输入区外缘，不随内容错位）
  - AC-4: **对话流区域独立滚动**并显示滚动条；**输入框固定在底部**，不随对话流滚动
  - AC-5: PageUp / PageDown 滚动对话流；输入框获得焦点时按键优先服务输入（换行/发送），滚动由专用键位触发
- **验收方式**：组件测试（editAction 纯函数：Enter/Shift+Enter/Ctrl+J 映射）+ kitty 与普通终端手工走查
- **层级**：Negotiable
- **优先级**：P1

## 5. 引用的全局不变量

| 不变量 | 影响 | 守卫 |
|---|---|---|
| INV-02 架构边界 | 探测、配置读取、语言解析都在 daemon / apps 侧；`kernel` 零 IO 不回退；新增探测调用不得进 kernel | 既有 dependency-cruiser（CI） |
| INV-03 权限默认拒绝 | 探测是只读网络请求，不改变文件、不产生权限事件；不新增权限决策面 | 单测默认值断言不回退 |
| INV-08 真实 LLM 调用不进 CI | 探测是真实出站调用，**不进 CI**；测试用 mock fetch | CI 配置审查 + PRD-M9-001 AC-4 |
| INV-11 用户数据不出本机 | 探测只请求用户显式配置的 provider baseUrl，属于"用户显式配置的模型 API" | 出站域名白名单测试（若探测走独立 fetch 通道则加入白名单） |
| INV-10 任务引用 PRD | 后续 SPEC / TASK 引用本册 PRD-M9-00x | 任务 lint（CI） |

**未触及**：INV-01（事件流）、INV-05（Tool/Skill 原语）、INV-06（不可信数据）、INV-07（main 可运行）、INV-09（Soul）、INV-12（压缩）、INV-13（评估回放）。

## 6. 预算

- 估算：**P0 约 2 天**（探测 1d + Provider 配置升级 1d）；**P1 约 2 天**（选择入口 0.5d + 国际化 1d + TUI 输入区 0.5d），合计约 **4 天**。
- 超出 20%（≈4.8 天）砍 P1 中优先级最低者（建议先砍 TUI 滚动条的翻页键位，只保留滚动条 + 输入框固定）。
- 本册不设 P2。

## 7. 待 SPEC 阶段明确的实现细节（记录，不阻塞 PRD）

- Anthropic `/v1/models` 响应的分页（`after_id` / `before_id`）是否需要跟随；探测仅取第一页可接受时在 SPEC 取舍记录里写明
- 探测并发策略：多个 provider 并行探测，单个失败不影响其他；超时上限（建议 10s，对齐 `mcp.timeoutMs`）
- 缓存失效口径：配置变更（增删改 provider / key / baseUrl）即失效
- 「设为默认」与旧 `model.provider` 的优先级：新结构存在时以 `default` 为准，旧字段仅作迁移读取
- Gemini 用户的 OpenAI 兼容端点默认值（`https://generativelanguage.googleapis.com/v1beta/openai/`）写入内置 known base url
