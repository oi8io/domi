## 1. 为什么是这一章

M8 收口后九个里程碑的功能全部落地。这一章是第一批**体验与配置补强**，针对已暴露的日常摩擦：

1. **模型选择停在「手填 + 硬编码清单」**：下拉清单是 `modelCatalog` 拼出来的（配置的 models + 价目表前缀 + 内置 known models），不探测真实可用模型；对话内还能切 provider（Composer `模型名 [provider]`、TUI `/model 名 provider`），与「provider 是配置概念」冲突。
2. **Provider 配置过于简单**：设置页硬编码 3 家 + 1 个网关，每项只有 api_key / base_url；没有名称、协议、启停，不能增删。
3. **三端文案全中文硬编码**，无英文界面。
4. **TUI 输入区与对话流**：有占位提示与 `›`、只有上边框；对话流全量渲染在 Ink 动态区，长会话闪烁、输入框跟着跳。

## 3. 相对 v0.1 改了什么（理由见复核报告）

| v0.1 | 现在 | 理由 |
|---|---|---|
| `providers` 改成带 `id` 的数组 | 保持以 id 为键的 map，每项加字段 | 与 `secrets.yaml` 同构；旧配置零迁移，不需要迁移命令 |
| provider 有 `default` 开关 | 默认是一个模型 | 原设计与 `model.provider` 是两个真相源，且没有「默认模型」字段 |
| 能力按协议给默认值 | 按厂商模板给、挂在 provider 上 | openai 协议覆盖 OpenAI 到 llama.cpp，按协议给要么放宽 fail-closed 要么让 DeepSeek 用不了工具 |
| `createOpenAI / createOpenAICompatible` 没说判据 | 厂商模板 = OpenAI 用官方适配器，其余用兼容适配器 | 官方适配器走 Responses API，第三方只认 Chat Completions |
| Anthropic 分页「只取第一页可接受」 | `limit=1000` 并跟随 `has_more` | 默认一页 20 条，只取第一页会静默丢模型 |
| 降级清单含价目表前缀、内置 known models | 只含手填模型 + 默认模型 | 前缀 → 厂商的映射在 provider id 可自定义后失效 |
| 同名模型「选了自动带出 provider」 | 身份是 `(provider, 模型)`，多处命中给候选 | 官方 + 网关同时提供 `gpt-4o` 很常见 |
| 探测结果全量展示 | 过滤非对话模型 + 下拉可搜索 | OpenAI 会返回 embedding / tts / whisper，OpenRouter 三百多个 |
| 翻译在哪一端没说 | 端上按 `messageKey + params` 渲染，daemon 不感知语言 | 一个 domid 可同时连中英两个端 |
| 缺 key 由 doctor 标注 | 由 `guard:i18n` 在 CI 拦 | 缺 key 是构建期问题 |
| — | 内置 identity 层要求模型用用户的语言回复 | 否则英文界面下被中文系统提示带着回中文 |
| TUI Shift+Enter / Ctrl+J 待做 | 已由 PRD-M8-014 AC-5 交付，本章只要求不回退 | 现状 |
| 对话流滚动 0.5 天 | 双渲染器，约 2.5 天 | Ink 没有原生滚动，要窗口化 + 备用屏 |
| — | 会话切过的模型重开后丢失 → 修（PRD-M9-003 AC-6） | 复核时发现的潜伏缺陷，`model.switch` 不带 provider |

## 4. 不做什么

- **不做模型能力运行时探测**（PRD-M1-001 AC-2/3 不回退：探测本身是请求，违反「发请求前抛错」）
- **不引入第三方 i18n 库**：自写 `t(key, params)` + 两份 locale，独立包三端共用
- **对话内不提供 provider 切换入口**（Composer 手填的 `[provider]`、TUI `/model` 的 provider 参数都删掉）
- **不扩协议**：`protocol` 只有 `openai | anthropic`；去掉 `@ai-sdk/google`，Gemini（含 embedding）走 OpenAI 兼容端点
- **TUI 不做应用内鼠标拖选复制**：fullscreen 下用「倒进原生回滚区」（Ctrl+O）替代；需要原生选择的人切 classic
- 不做模型微调 / 自研模型（PRD-VISION §4）
