## 1. 本里程碑要回答的问题

**agent 干了一阵之后，用户能不能不翻对话就知道：做到哪了、改了什么、产出了什么、它此刻看得见什么？**

现状只能翻对话：计划内联在对话里，被后面的内容推走；改动条只在隔离工作区的任务里出现，自由会话和没隔离的任务改了文件看不到 diff；产物散落在工具卡片里；上下文只有状态栏上一个百分比。

右侧栏是**事件流的第二种投影**：对话按时间讲经过，右侧栏按「东西」盘点。四个 tab：**进度 / 改动 / 产物 / 上下文**。

## 4. 不做什么

- **不把 Trajectory 收进右侧栏**（拍板 c）；右侧栏不重复做全量轨迹
- **不做文件编辑器、终端面板**：点文件只提供「用默认程序打开 / 在访达中显示 / 复制路径 / 引用」
- **不做自由拖拽分栏**：右侧栏只有一列，可调宽、可折叠、可展开占满主区（建议 h）
- **行评论不自动发送**（拍板 d）：进输入框，用户自己发
- **右侧栏不自己弹开**（建议 g）
- **不改已有事件的语义**：`fs.snapshot` 照旧；`model.request.tokensIn` 名实不符记缺陷、不在本册改
- **本册不做**（留后续，届时另起条目）：跟随（面板跟着 agent 当前动作走）、时间旅行（四个 tab 一起看「截至第 N 步」）、插件 tab 槽（`plugin.ui` 声明 inspector tab）、Desktop 弹出独立窗口、显式「标记为交付物」、PR / CI 状态、浏览器 / computer use 实时画面、侧问
- **不做 hunk 级「带回」**：带回仍按 PRD-M8-006 / M7-006 整体带回；hunk 级只做丢弃（005 AC-7）

## 5. 需求条目

### PRD-M14-001 · 右侧栏骨架与开关（Web）

- **用户价值**：会话页右边多一列，随时看进度、改动、产物、上下文；不想看就收起来，不占地方
- **验收标准**：
  - AC-1: 会话页变三列（左侧栏 / 会话 / 右侧栏）；右侧栏顶部四个 tab：进度、改动、产物、上下文，各带徽标（进度：已完成 / 总步数；改动：文件数；产物：个数；上下文：占用百分比）
  - AC-2: 宽度可拖，范围 320–720px，默认 400px；收起后留一条窄条，仍显示四个 tab 的图标与徽标，点任一个 = 展开到该 tab
  - AC-3: 每个 tab 统一「列表 → 详情」两级，详情有返回；详情页可「展开」：右侧栏临时占满会话区（输入框仍可用），`Esc` 或再点一次收回（建议 h）
  - AC-4: 默认开关按会话类型：**自由会话默认关、任务默认开**（拍板 b）；用户在某个会话里手动开 / 关后，这个会话记住；宽度与上次所在 tab 全局记住（存端上偏好，不进事件流）
  - AC-5: **不自动弹开**：任何事件（新计划、新改动、新产物）只更新徽标；唯一的打开方式是用户操作或 AC-4 的默认值（建议 g）
  - AC-6: 视口宽度 < 1200px 时，右侧栏改为覆盖在会话区上的抽屉（点外面关闭），不挤压对话
  - AC-7: 快捷键开关右侧栏与切 tab（键位 SPEC 定，不与浏览器和现有快捷键冲突）；可用键盘完成 tab 切换、列表上下选、进详情、返回
  - AC-8: 状态栏现有的改动入口（`ChangesBar`）退化为一个 `+12 −3` 指示，点它 = 打开右侧栏的改动 tab；原 ChangesBar 的展开审阅整体搬进 005
  - AC-9: 四个 tab 的数据全部是 client-core 的纯函数投影或 daemon RPC 的结果；Web 组件不计算任何业务数据（INV-04）
- **验收方式**：Web SSR / 组件测试（三列布局、收起窄条、默认开关按类型、手动开关记住、抽屉断点、不自动弹开：灌入新计划 / 新改动事件后断言右侧栏开关状态不变）+ client-core 偏好 store 单测
- **层级**：Negotiable（INV-04 部分按不变量守）
- **优先级**：P0

### PRD-M14-002 · 右侧栏与对话双向联动

- **用户价值**：在右侧栏看到一个改动 / 一个步骤 / 一次压缩，一点就能回到对话里它发生的地方；反过来对话里提到的文件一点就在右侧栏看到详情
- **验收标准**：
  - AC-1: 右侧栏里每个条目（计划步骤、改动文件、产物、压缩点、读过的文件）都带它在事件流中的位置；点「在对话中定位」→ 对话滚到那里并短暂高亮；目标还没加载（窗口化，PRD-M11-009）时先补拉再定位
  - AC-2: 对话里的工具卡片（`fs.write` / `fs.edit` / `shell.exec`）、计划卡片、文件路径可点 → 打开右侧栏对应 tab 的详情（右侧栏关着就先打开）
  - AC-3: 联动不改变 AC-4 之外的默认开关：从对话点进来打开的右侧栏，按「用户手动打开」记住（PRD-M14-001 AC-4）
- **验收方式**：client-core 定位函数单测（seq → 窗口内 / 需补拉）+ Web 组件测试（两个方向各一条）
- **层级**：Negotiable
- **优先级**：P0

### PRD-M14-003 · 步级快照接进 daemon（改动的数据来源）

- **用户价值**：不管是任务还是自由会话、不管文件是被写文件工具还是被命令改的，都能看到这一轮 / 这一步具体改了什么
- **说明**：接手 PRD-M1-011 AC-1 在 daemon 运行路径上的接线（§3 #1）。影子仓库算法与回滚库已在 M1 交付，这里只做接线、事件与读取 RPC。worktree 任务同样打快照（「本轮」「某一步」范围要用）
- **验收标准**：
  - AC-1: 每一轮第一次执行会改文件的工具（`fs.write` / `fs.edit` / `shell.exec`）**之前**，对会话工作目录打一个基线快照；之后每次这三类工具成功返回后打一个快照；快照 id 落进事件流（新事件，暂名 `fs.checkpoint`，带快照 id 与对应工具调用 id）
  - AC-2: 快照仓库位置、`.gitignore` 与内置排除表、大文件只记指纹，全部沿用 PRD-M1-011 AC-1 / AC-2 / AC-5；断言工作目录自己的 `.git` 在快照前后 HEAD / index / reflog 不变
  - AC-3: 新 RPC（暂名 `checkpoint.diff`）：入参 `sessionId` + 可选 `fromSeq` / `toSeq` / `path`，返回与 `worktree.diff` 同形的文件列表（path / status / patch / truncated），供「本轮」「整个会话」「某一步」三种范围使用；diff 在 daemon 算，端上不算（INV-04）
  - AC-4: 降级明示：系统没装 git、快照失败或超时时，不阻断工具与本轮，落一条可见记录；改动 tab 显示「这一步没有快照」，并退回到只列 `fs.snapshot` 里出现过的文件名（无 diff 内容）——不静默装作没有改动
  - AC-5: 性能：快照不计入工具耗时；在 domi 自身仓库规模下单次快照的耗时基准由 SPEC 定，并进 bench
  - AC-6: 自由会话的沙盒目录同样适用（拍板 e）
  - AC-7: 协议只增不改：新事件与新 RPC 升 `SCHEMA_VERSION`，补 legacy fixture；旧端不认识新事件时跳过不崩；评估回放（INV-13）遇到 `fs.checkpoint` 按普通事件重放，L1 不依赖影子仓库存在
- **验收方式**：runtime 单测（基线快照时机、三类工具后各打一次、失败降级不阻断）+ checkpoint 集成测试（带 `.gitignore`、untracked、`sed -i` 改文件的 fixture 仓库：shell 改动能出现在 diff 里）+ daemon RPC 单测（三种范围）+ 协议快照 + legacy fixture + bench
- **层级**：Invariant（INV-01、INV-12）
- **优先级**：P0

### PRD-M14-004 · 进度 tab

- **用户价值**：一眼看出计划做到第几步、哪步在跑、每步花了多少、子任务怎么样了，不用往上翻对话找计划卡片
- **验收标准**：
  - AC-1: 显示最后一条 `plan.update` 的步骤：已完成（勾 + 划线）、进行中（高亮 + 已用时）、未开始（灰）、跳过（灰 + 标「跳过」）；`dependsOn` 用缩进表示，不画图
  - AC-2: 每一步可展开看这一步干了什么：工具调用次数、改了哪些文件（点了跳到改动 tab 的「某一步」范围）、耗时、token；「这一步」= 该步变成进行中到变成完成之间的事件区间（区间规则 SPEC 定，含计划被整份替换时的对齐）
  - AC-3: 子 agent（`task.spawn`）与 DAG 节点（`task.node`）挂在发生时所处的步骤下，显示目标、状态、耗时；点击打开子会话（只读）
  - AC-4: 底部固定区：验收状态（`verify.required` 第几次、是否最后一次）、排队中的补充条数（PRD-M13-001）、「计划还剩 N 步 · 继续」（与 `ResumeBar` 同一个动作，被打断时突出）
  - AC-5: 没有计划时（自由会话常见）不显示空白，改为「本轮动作摘要」：本轮工具调用按类别计数 + 最近 5 个动作
  - AC-6: 对话里的计划卡片保留（不搬走），右侧栏是它的常驻视图
- **验收方式**：client-core `planView` 投影单测（步骤状态、区间切分、计划整份替换、子任务归属、无计划时的摘要）+ Web 组件测试
- **层级**：Negotiable
- **优先级**：P0

### PRD-M14-005 · 改动 tab（diff 高亮）

- **用户价值**：在 domi 旁边就能审它改的每一行，范围想看哪段看哪段，不满意的当场丢掉
- **验收标准**：
  - AC-1: 范围切换：**本轮**（默认，最近一次 `user.input` 起）/ **整个会话** / **对比基线**（只有隔离工作区的任务有，数据沿用 `worktree.diff`，即原 ChangesBar 的视图）/ **某一步**（从进度 tab 点进来时出现，可清除）；切换范围只换数据，不丢当前选中的文件（该文件在新范围里不存在时回到列表）
  - AC-2: 自由会话、没隔离的任务、隔离任务都有本 tab（拍板 e），数据来自 PRD-M14-003
  - AC-3: 文件列表：状态（新增 / 修改 / 删除 / 重命名，沿用现有配色）+ `+N −M`；按目录折叠；顶部合计
  - AC-4: diff 渲染：默认统一视图；展开模式（PRD-M14-001 AC-3）下可切左右对照；**行内词级高亮**；代码按文件类型做语法高亮（复用 PRD-M11-003 AC-9 的轻量高亮，不另引高亮库）；上下文行默认 3 行、可展开
  - AC-5: 大 diff 与特殊文件：超过阈值的文件默认折叠并标行数；锁文件 / 生成文件默认折叠；二进制只显示大小变化；图片显示前后对照；「内容未快照」的大文件按 PRD-M1-011 AC-5 明示
  - AC-6: 运行中实时更新：本轮有新的改动时列表增量刷新，不打断正在看的文件（正在看的文件有更新时出一条「有新改动 · 刷新」）
  - AC-7: 丢弃：整份 / 单文件 / 单个改动块三级；隔离任务沿用 `worktree.discard`（可撤销）；非隔离会话的丢弃 = 把该文件恢复到所选范围起点的快照内容，丢弃前自动打快照，因此可撤销；每次丢弃落一条事件、可审计（INV-03）；运行中不能丢弃（与现状一致）
  - AC-8: 带回（squash / merge / 只留分支）在「对比基线」范围下保留，行为不变（PRD-M8-006 AC-2 · PRD-M7-006）
  - AC-9: 文件右键 / 更多：用默认程序打开、在访达中显示、复制路径、引用到输入框（引用格式同 PRD-M14-008）
- **验收方式**：client-core `changesView` 单测（范围切换、增量合并、选中保持）+ diff 渲染组件测试（统一 / 对照、词级高亮、折叠规则、二进制 / 图片 / 未快照）+ daemon 丢弃单测（非隔离会话丢弃与撤销、运行中拒绝、事件落盘）+ `worktree.*` 回归
- **层级**：Negotiable（丢弃的审计按 INV-03 守）
- **优先级**：P0（AC-7 的单个改动块丢弃为 P1）

### PRD-M14-006 · 上下文 tab

- **用户价值**：知道 domi 此刻看得见什么、窗口被什么占满、什么时候会压缩、压缩掉了什么——不再是状态栏上一个摸不透的百分比
- **验收标准**：
  - AC-1: 用量：一条堆叠条，分段为 系统提示（内置层）/ Soul / 项目规矩（AGENT.md）/ 技能目录 / 计划 / 工具定义 / 对话历史 / 压缩摘要 / 附件；总量 = 最近一次请求模型返回的真实提示词 token（与状态栏同口径，BUG-M13-002）；分段为字符估算并标「约」，分段之和与真实总量的差额单列「未归类」，不按比例硬凑（建议 j）
  - AC-2: 数据来源：每次模型请求落一份分段（`model.request` 增加可选字段或新事件，SPEC 定；只增不改，INV-01）；按层取自 `prompt.assemble()` 的层清单（§3 #6）
  - AC-3: 同区显示：窗口大小、缓存命中率、距自动压缩阈值还差多少（与 `context.strategy` / 压缩阈值同口径；策略不是 compact 时显示「不自动压缩」）、本会话花费与预算（`budget.warn` / `budget.decided`）
  - AC-4: 压缩记录：本会话每次 `ctx.compact` / `ctx.cleanup` 一行（时间、触发方式、前后 token、覆盖的区间）；点开看结构化摘要原文（意图 / 改过的文件 / 关键决定…）与清理分类削减量；可「在对话中定位」到被覆盖的区间（PRD-M14-002）
  - AC-5: 加载了什么：当前生效的提示词层清单（含是否进缓存前缀）、项目规矩文件路径（未信任时显示「未信任，未加载」）、技能目录条数与本会话 `skill.load` 过的技能、可用的 MCP server 与工具数、本会话引用的其他会话片段（`ctx.ref`）、附件
  - AC-6: 读过的：本会话 `fs.read` / `fs.glob` / `fs.grep` 涉及的路径（去重、按次数排序）与 MCP 工具调用（server / 工具名 / 次数）；点击定位到对话
  - AC-7: 本会话的记忆写入（`memory.write`）：每条显示 diff 文字版；可撤销 / 否决（复用记忆层已有的删除与审阅能力，不新造写入路径）——**P1**
  - AC-8: 所有数字与状态栏、`session.metrics` 同源；同一时刻两处显示的总量、命中率不一致视为缺陷
- **验收方式**：prompt 层分段单测 + runtime 单测（每次请求落分段）+ client-core `contextView` 单测（分段、未归类差额、压缩记录、加载项、读过的去重）+ 与 `session.metrics` 一致性断言 + Web 组件测试 + 协议快照
- **层级**：Negotiable（INV-01 / INV-12 部分按不变量守）
- **优先级**：P0（拍板 f；AC-7 为 P1）

### PRD-M14-007 · 产物 tab

- **用户价值**：domi 这次做出来的东西集中在一处，点开就能预览，不用在对话里一条条找
- **验收标准**：
  - AC-1: 产物 = 本会话里新建的文件（快照 diff 状态为新增且到当前仍存在；被删掉的不算）；用户上传的附件单列一组「你给的」（建议 k）
  - AC-2: 卡片：类型图标、文件名、大小、产生于哪一步（可定位，PRD-M14-002）
  - AC-3: 内嵌预览：Markdown（复用 `MarkdownView`）、图片、代码（语法高亮）、CSV / TSV（表格，前 N 行）、PDF、HTML；其他类型只给信息与打开方式
  - AC-4: HTML 预览放进无同源沙箱 iframe（同 `plugin.ui` 规矩），并**禁止网络请求**——产物内容是不可信数据（INV-06），预览不得让本机数据出站（INV-11）
  - AC-5: 动作：用默认程序打开、在访达中显示、复制路径、引用到输入框；隔离任务里还没带回的产物标「未带回」
  - AC-6: 「会话转任务」时，产物列表随会话一起可见（不丢）
- **验收方式**：client-core `artifactsView` 单测（新建 / 后被删 / 被改名 / 附件分组）+ 预览组件测试（各类型、HTML iframe 的 sandbox 与 CSP 断言）
- **层级**：Negotiable（INV-06 / INV-11 部分按不变量守）
- **优先级**：P1

### PRD-M14-008 · diff 行评论进输入框；审查发现锚到行

- **用户价值**：看 diff 时对哪一行有意见就在哪一行写，攒好了一起交给 domi；审查结果直接标在出问题的那一行
- **验收标准**：
  - AC-1: diff 里点行号（可拖选多行）→ 写一条评论；可攒多条，右侧栏显示待交条数
  - AC-2: 「交给 domi」= 把这些评论变成输入框里的一组引用（每条：文件、行范围、新旧侧、被评论的代码片段、评论文字），**不自动发送**（拍板 d）；用户可在输入框里删改、补文字后自己发
  - AC-3: 引用类型扩展：`PendingRef` 增加文件行引用；发送后进入用户消息的方式与现有对话片段引用一致（协议只增不改）；模型看到的是带文件路径与行号的结构化引用
  - AC-4: `review.findings` 有 `line` 的条目锚在 diff 对应行上（severity 配色），带「修这一条」——同样是放进输入框，不自动发；文件已不在当前范围里的发现留在列表里并标「不在当前改动中」
  - AC-5: 未交出的评论在切范围、切文件时保留；关掉会话后丢弃前提示
- **验收方式**：client-core 评论 store 单测（攒、删、跨范围保留、转引用）+ 协议快照（新引用类型）+ runtime 单测（文件行引用进上下文的形态）+ Web 组件测试
- **层级**：Negotiable
- **优先级**：P1

### PRD-M14-009 · TUI 右侧栏

- **用户价值**：终端里一样能看进度、改动、上下文、产物，同一套概念
- **验收标准**：
  - AC-1: 终端宽度 ≥ 140 列时右侧分栏，否则全屏覆盖层；一个快捷键开关（键位 SPEC 定，避开 §3 #13 已占的键）；数字键 1–4 切 tab
  - AC-2: 四个 tab 用与 Web 相同的 client-core 投影，内容一致；默认开关规则同 PRD-M14-001 AC-4
  - AC-3: 改动 tab：文件列表 + 统一 diff，`+ / −` 着色与语法高亮复用现有 TUI 渲染；词级高亮、左右对照、图片预览不做
  - AC-4: 产物 tab 只列清单与路径，不做内嵌预览（Markdown 除外）
  - AC-5: 行评论不做（TUI 里用现有的引用方式）
- **验收方式**：TUI 组件测试（分栏 / 覆盖层断点、tab 切换、四个 tab 的渲染快照）+ 按键测试 + parity checklist 更新
- **层级**：Negotiable
- **优先级**：P1

### PRD-M14-010 · 回到这一步（三选一回滚）

- **用户价值**：某一步之后改坏了，可以从右侧栏直接退回那一步——只退文件、只退对话、或都退
- **说明**：PRD-M1-011 AC-3 / AC-4 的回滚库与 `revert` 事件已在 M1 交付，003 接线后可直接用；这里只做入口与确认
- **验收标准**：
  - AC-1: 进度 tab 的步骤、改动 tab 的「某一步」范围上提供「回到这一步之前」，三选一：只回文件 / 只回对话 / 都回（同 PRD-M1-011 AC-3）
  - AC-2: 确认框明示快照**不覆盖**的副作用（已执行命令的外部效果、网络请求、已 push 的提交），同 PRD-M1-011 AC-6
  - AC-3: 回滚前自动打快照，回滚本身可回滚（PRD-M1-011 AC-4）；运行中不可用
  - AC-4: 「只回对话」走 `revert`（scope `conversation`），不删除事件（INV-01 / INV-12）；被作废区间在对话与右侧栏里都标「已回滚」但可读
- **验收方式**：daemon 单测（三种粒度、连续两次回滚回到初始、运行中拒绝）+ Web 确认框文案断言
- **层级**：Invariant（INV-01、INV-12）
- **优先级**：P2
