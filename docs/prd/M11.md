## 1. 为什么是这一章

M10（会话体验与运行控制）已 COMMITTED 且开发基本完成。用户在使用/走查中又提出七条，全部围绕**会话阅读体验**与**执行控制**：

1. **进入会话默认滚动到底**：Web / TUI 打开旧会话应直接看到最新内容，而不是停在顶部。
2. **运行中自动贴底**：有内容输出时自动滚到最底，让用户感知进行中的状态（已有部分基础，需补齐）。
3. **Markdown 渲染**：模型回复目前是原文输出（`whitespace-pre-wrap`），没有代码块 / 标题 / 列表的视觉区分。
4. **展开后显示全文**：点击展开后仍看到省略号 / 截断内容——展开态必须给完整内容。
5. **审核接受模式**：始终询问 / 按需确认 / 全部允许等会话级档位；同类命令一次「始终允许」不用重复确认（用户原话：不想确认一大堆，又不希望 AI 自动执行危险指令，**边界要设计好**）。
6. **桌面端自启后台进程**：单进程判断——已有进程则连接，没有则自己拉起。
7. **TUI 会话支持中断**：对话运行中能中止当前轮，而不是只能退出程序。
8. **会话窗口化加载**（2026-09-22 追加，PRD-M11-009）：进入会话不全量拉回，长会话按屏动态分页、滚动触发取更早历史。

## 4. 不做什么

- **不改事件流**：本册所有渲染优化（滚动 / Markdown / 展开 / 折叠）都是纯展示层，不产生、不修改事件（INV-01）。
- **不做权限规则的自动改写**：档位是「会话级检查策略」，不落盘改 `permissions.rules`；规则仍是唯一审计事实（INV-03）。
- ~~**不做「无差别全部允许」**：危险能力（删除、覆盖、shell、网络发布等）在**任何档位**下都不能免确认——这是第 5 条的硬边界（用户原话「不希望 AI 自动执行危险指令」）。~~（2026-09-23 划掉：「全部放行」改为用户显式选择的跳过所有确认；「不让 AI 自动执行危险指令」由默认的「按需」档承担——没写规则的危险能力仍拒）
- **Markdown Web + TUI 都做**（2026-09-21 复核更新）：Web 走 react-markdown，TUI 复用 remark 解析器自写 mdast→ANSI 渲染层；两端共用同一解析器，都不做代码块语法高亮增强。
- **不进本册**：终止 / 恢复方案（S1–S4：墙钟语义、ask 超时、终止消息、断点续跑）待用户拍板后按回写门处理；TUI 中断（第 7 条）的语义与它绑定，本册只记录需求、占位 AC，不写实现细节。

## 5. 需求条目

### PRD-M11-001 · 进入会话默认滚动到底

- **用户价值**：打开任何会话直接看到最新消息，不翻页
- **验收标准**：
  - AC-1: Web 打开会话（含长历史）后视口初始位置在底部（最新一条可见）；用户上翻后不再被强制拉回
  - AC-2: TUI 打开会话默认 `follow: true`（现状），进入即底部；回归断言不回退
  - AC-3: 纯展示层：不产生事件，滚动状态不入 store（与 M9 fullscreen 的 `ScrollState` 同机制）
- **验收方式**：Web 组件测试（长列表初始 scrollTop）+ TUI `viewport.spec` 回归
- **层级**：Negotiable
- **优先级**：P1

### PRD-M11-002 · 运行中自动贴底与状态感知

- **用户价值**：输出进行时自动跟到底，全程看到内容；用户上翻离开底部时不丢「有新消息」的感知
- **验收标准**：
  - AC-1: 模型 / 工具输出追加时，若视口在底部（阈值内）自动贴底，跟随最新内容
  - AC-2: 用户上翻离开底部后，**不再自动拉回**；有新输出时出现「N 条新消息」提示（Web 补齐；TUI 已有 `unseen`，回归）
  - AC-3: 点击「新消息」提示回到底部并清除计数
  - AC-4: 纯展示层，不产生事件
- **验收方式**：Web 组件测试（追加事件 + 上翻 + 提示出现/清除）+ TUI 回归
- **层级**：Negotiable
- **优先级**：P1

### PRD-M11-003 · 会话 Markdown 渲染（Web + TUI）

- **用户价值**：代码块、标题、列表、表格、行内代码有正常视觉层次，不再是一坨原文
- **验收标准**：
  - AC-1: Web 消息区（assistant 文本）用 Markdown 渲染：代码块（含语言标注）、标题层级、有序/无序列表、行内代码、粗体/斜体、链接、表格
  - AC-2: 渲染失败（非法 Markdown / 渲染器异常）时降级为原文显示，不白屏、不丢内容（内容永远在 DOM 里）
  - AC-3: 复制能力不回归：代码块内容可选中复制（现有 `break-all whitespace-pre-wrap` 的复制语义不回退）
  - AC-4: XSS 安全：渲染器配置禁掉 HTML / 危险协议（INV-06 不可信数据），渲染前有净化
  - AC-5: reason（思考）保持折叠 + 纯文本摘要，不进 Markdown 渲染（折叠行是摘要不是正文）
  - AC-6: TUI 消息区（assistant 文本）用 Markdown 渲染：代码块、标题层级、有序/无序列表、行内代码、粗体、引用、链接、表格有 ANSI 视觉区分（终端没有字号，用颜色/粗细/前缀区分层级）
  - AC-7: TUI 纯文本消息（不含 Markdown 语法的普通回复）渲染结果与现状逐字一致（不破坏既有 golden 快照）
  - AC-8: TUI 原文里的 HTML 不被解释成标签（remark 不解析 HTML，渲染层跳过 html 节点）；渲染异常降级为纯文本，内容不丢
  - AC-9（2026-09-23）: 代码块语法高亮（Web + TUI 同一份分词、同一份配色）：Primer 语法色，深浅主题各一套，在代码底色上对比度 ≥ 4.5:1；只认常用的十几种语言，不认识的语言、没写语言不猜、不染色；Web 按需加载高亮器，不进首屏包，加载前先按纯文本显示
  - AC-10（2026-09-23）: 排版对齐原型（回复里的 Markdown 是对话里的一段说明，不是一篇文档）：标题小阶梯（Web 16 / 15 / 14 / 13px，h1 / h2 带细分隔线；TUI 不带 #，靠粗细明暗分层）；代码块与工具调用卡片同一套外观（语言头 + 复制按钮 + 12px 等宽正文；TUI 语言头 + 左边线）；表格是卡片、只留横线、宽度跟着内容（TUI 按显示宽度对齐中文）；引用与「思考」同一个样子；列表序号 / 圆点用次要色；TUI 块与块之间空一行
- **验收方式**：Web 组件测试（各语法样例渲染）+ 安全用例（恶意 HTML / javascript: 链接被净化）+ TUI 渲染层单测（mdast→ANSI 各语法样例 + 纯文本回退）+ 手工走查
- **层级**：Negotiable
- **优先级**：P1
- **范围**：**Web + TUI**（2026-09-21 复核更新）。TUI 复用 remark 解析器自写 mdast→ANSI 渲染层，与 Web 共用同一解析器；~~两端都不做代码块语法高亮~~（2026-09-23 用户拍板做轻量高亮，见 AC-9 / ADR-028）

### PRD-M11-004 · 展开后显示完整内容

- **用户价值**：点开就不该再看到省略号——展开态给全文
- **验收标准**：
  - AC-1: Web tool 调用 `<details>` 展开后显示**完整参数原文**（现状显示截断 `summary`，改回 `row.call.text` / 完整 payload）；result 展开显示完整结果（`result.text`，不因存在 summary 而截断）
  - AC-2: 展开后内容过长时**容器内滚动**（现状 `max-h-[260px] overflow-y-auto` 保留），而不是截断省略
  - AC-3: reason 折叠展开显示全文（现状已满足，回归）
  - AC-4: TUI 对应入口（若有折叠/截断）同步：展开即全文，长内容在视口内滚动
- **验收方式**：Web 组件测试（tool 展开含完整参数断言）+ TUI 核查
- **层级**：Negotiable
- **优先级**：P1

### PRD-M11-005 · 审核接受模式（会话级档位 + 一次「始终允许」）

- **用户价值**：用户原话——「大部分都交给 AI 自动执行，而不是要确认一大堆；又不希望 AI 自动执行危险的指令，边界要设计好」「同一组或者类似的命令，最好有一个 Always Allow 只需要确认一次」
- **拆成两个子需求**：

#### 5.1 会话级审核档位

- **说明**：会话（或全局）设置一个审核档位，控制「未显式规则覆盖时」的默认行为：
  - `始终询问`：任何无规则 / ask 能力都弹确认（fail-closed 不回退）
  - `按需确认`（**默认**，用户拍板）：只对**危险能力**（见 §7 危险清单）与规则标 ask 的能力确认；其余显式 allow 的能力自动放行
  - `全部允许`：除危险能力外全部自动放行（危险能力**仍必须确认**，不可关闭）
- **验收标准**：
  - AC-1: 档位写入配置（`permissions.mode` 扩展或新键，SPEC 定），Web 设置页可改，TUI 设置入口（M10-004 已有）可改
  - ~~AC-2: 危险能力清单在**任何档位**下都不被自动放行：无规则 → 拒绝（fail-closed）；规则 ask → 弹确认；规则 allow → 仍弹确认（档位只收紧不放松，INV-03 立场一致）~~（2026-09-23 划掉，改为 AC-6）
  - AC-6（2026-09-23）: 危险能力：无规则 → 拒绝（fail-closed，按需 / 每次都问）；规则 ask → 弹确认；规则 allow → 按需放行、每次都问仍弹确认；「全部放行」档跳过所有确认，只剩显式 deny 与父范围
  - AC-3: 档位变化只影响后续检查，不追溯已发生事件；审计事件记录档位（`permission` 事件可追溯来源）
  - AC-4: **默认档位 = 按需确认**（用户拍板）。不配置时行为 = 「按需确认」：显式 allow 的非危险能力自动放行、规则 ask 与危险能力弹确认、无规则拒绝——与现状 fail-closed 立场一致（回归：不配置时安全立场不回退）
  - AC-5: 子 agent 继承父会话档位（范围收窄逻辑不回退，INV-03）
- **验收方式**：`capability/test/permission.spec.ts` 扩展（三档 × 能力矩阵）+ 配置 schema + Web 设置页走查
- **层级**：Negotiable
- **优先级**：P1

#### 5.2 一次「始终允许」（同类命令 / 能力）

- **说明**：现状 `session-grant`（M8-016）只能按**能力 + 路径目录**授权，且 `shell.exec` / `mcp.*` / `plugin.*` 不可 grant（参数无法静态限定）。用户要的是「同一组或类似命令，确认一次就够了」——需要**命令级**匹配。
- **验收标准**：
  - AC-1: 确认框提供「始终允许」选项，粒度 = **命令指纹：可执行文件 + 参数首词/前缀**（用户拍板，够用），而非整个能力
  - AC-2: 指纹匹配规则可解释、可审计：授权事件记录指纹与匹配方式；同指纹后续调用自动放行（source: `session-grant`），不同指纹仍确认
  - AC-3: 危险操作（删除、覆盖、外发）默认**不提供**「始终允许」（`grantable` 收紧，SPEC 列清单）
  - AC-4: 授权只在本会话生效（与 M8-016 同生命周期）；重开会话需要重新授权（现状行为）
  - AC-5: 匹配规则**宁可少放行不可误放**：前缀匹配范围有上限（参数首词 / 同子命令，SPEC 定细节），模糊匹配默认拒绝
- **验收方式**：权限引擎单测（指纹矩阵：精确 / 前缀 / 模糊 / 危险）+ 审计事件断言
- **层级**：Negotiable
- **优先级**：P1（重，**先做 5.1 再做 5.2**；同册完成，不分册）

### PRD-M11-006 · 三端自启后台进程（确认 + 补齐）

- **说明**：`ensureDaemon`（launcher.ts）已实现「已有进程则连接，没有则 detached 拉起」，TUI / CLI 已接入。用户拍板**三端都需要**：desktop（Tauri 壳）/ TUI / Web 都接入。本条目 = TUI/CLI 确认 + desktop、Web 补齐接入
- **验收标准**：
  - AC-1: **TUI / CLI**（已接入）：已有 domid → 直接连接（`spawned: false`）；无 → 自己拉起（`spawned: true`），锁文件写 pid + 端口；回归
  - AC-2: **desktop（Tauri 壳）**：启动时走同一 `ensureDaemon` 路径，连接或拉起后台 domid
  - AC-3: **Web**：前端启动时经后端 / 桌面壳确保 daemon 在跑（Web 无 Node 进程，由 desktop 壳或 daemon 侧保证，SPEC 定接线方式）
  - AC-4: 拉起后终端关闭不影响任务继续（daemon 独立存活，M3 DoD 不回退）
  - AC-5: 重复启动不产生第二个 daemon（锁文件互斥，`LockHeldError` 路径）
- **验收方式**：launcher 既有测试回归 + desktop 启动冒烟 + 手工（起两次 / 关终端）
- **层级**：Negotiable
- **优先级**：P1

### PRD-M11-007 · TUI 会话中断

- **用户价值**：对话跑着的时候能中止当前轮（模型生成 / 工具循环），而不是只能退出程序
- **说明**：与「终止问题」（S1–S4）绑定——中断后的语义（保留已做部分、可恢复、消息提示）待用户拍板后再定实现。**本条目先记录需求，不写实现细节**
- **验收标准**（占位，语义确定后补全）：
  - AC-1: TUI 运行中按中断键（如 Esc / Ctrl+C 语义待定）中止当前轮，事件流完整（已生成内容保留）
  - AC-2: 中断后提示可恢复方式（与 S3 终止消息方案一致）
  - AC-3: 中断是「停这一轮」不是「退出程序」；二次确认或明确提示
- **验收方式**：待定
- **层级**：Negotiable
- **优先级**：P1（先定语义）

### PRD-M11-009 · 会话窗口化加载（动态分页，按屏预算）

- **用户价值**：进入会话不全量拉回，长会话按屏动态加载、滚动触发取更早历史——打开快、滚动顺、不卡（用户 2026-09-22 提出："不应该一下全把会话全拉回来，内容太多了，应该是动态加载的，滚动的时候触发内容拉取"）
- **说明**：现状 `session.subscribe` 首次 `fromSeq: 0` 时服务端 `readEvents(0)` **全量读库回传**，客户端 store 全量投影、Web 全量渲染——长会话网络与渲染成本都大。本条目改为**尾部窗口 + seq 锚点分页**：
  - 分页粒度**按轮**（一次 `user.input` 到下一次，语义完整单元），不拆轮（用户拍板）
  - 预算**按屏**：主预算 = 预估渲染行数（视口行数 × 系数：首屏 2.5 屏、翻页 1.5 屏），内容字节 / 事件条数作兜底；短轮多装、长轮少装，每页"看起来一样多"（用户拍板）
  - 短会话（总量 < 预算）直接全量，不进分页逻辑（用户拍板）
  - 兜底最少 1 轮，不白页（用户拍板）
  - 单轮超大**不拆轮**：完整返回，超预算部分展示层压缩为摘要行（summarize 机制延伸，与 PRD-M11-004"展开显示全文"不冲突）
  - 服务端算权重（它有全量事件，最准）并返回「本页包含哪些轮的 seq 区间」，客户端只展示不猜
- **验收标准**：
  - AC-1: 进入会话只拉尾部窗口（按轮），视口初始在底部（与 PRD-M11-001 一致）；短会话全量、行为与现状一致（回归）
  - AC-2: 向上滚动接近顶部自动触发加载更早一页（按 seq 锚点前翻），加载中顶部有占位/指示，加载完无缝衔接；占位可点击兜底
  - AC-3: 分页接口按「轮」返回（每页返回轮的 seq 区间）；服务端按预算（行数主、字节/事件兜底）决定每页轮数
  - AC-4: 单轮超大不拆：该轮完整返回或展示层压缩为摘要行，不做轮内截断；最少 1 轮，不白页
  - AC-5: 实时增量不回退：新事件仍经现有订阅追加到窗口尾部（INV-01，`session.subscribe` 增量推送不动）
  - AC-6: 依赖全量事件的功能（搜索、`ctx.ref` 跨会话引用、分支/回退、轨迹面板）不受窗口化影响——走独立接口或服务端计算，SPEC 列清单
  - AC-7: TUI（fullscreen 用 `transcriptLines` 精确行数）与 Web（按字符/类型估算）都按屏预算；Web 长会话打开耗时显著下降（基准：千事件会话首屏 < 300ms 或较现状可度量下降，SPEC 定阈值）
- **验收方式**：分页接口单测（预算 × 轮权重矩阵）+ Web 组件测试（滚动触发/衔接/占位）+ TUI 回归 + 长会话基准
- **层级**：Negotiable
- **优先级**：P1（与 001/002 同交互面，建议一并排期）

## 6. 危险能力清单（§5.1 的边界，先列草案待用户确认）
