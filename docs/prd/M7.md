## 1. 为什么是这一章

`PRD-VISION.md` §3 的 M1 判据是「连续 5 个工作日用 domi 完成真实开发任务」，这条至今没有达成。
原因不在内核，在工具面：domi 现在只有三件编码相关的工具——`fs.read`、`fs.write`（整文件写）、`shell.exec`。
在真实仓库里，它改一行要重写整个文件、找代码要让模型拼 grep、跑一次 `pnpm check` 的输出能占掉大半上下文，
而且「改完了」和「测过了」之间没有任何约束。M7 补的就是这一段。

## 4. 进入前钉死的判据（Invariant 级）

1. **INV-03 · 新工具不开新口子**：`fs.edit` / `fs.glob` / `fs.grep` / 后台 job 全部归入已有能力类别，现有权限规则不改一行即生效。
2. **INV-03 / INV-06 · 仓库内容不能提权**：规矩文件只进提示词，不能注册钩子、权限规则或免确认命令；
   未信任的工作区连提示词都不进。克隆一个陌生仓库 ≠ 让它在你机器上执行东西。
3. **INV-03 · 原工作区不被悄悄改动**：隔离模式下，改动带回原仓库必须经过人工批准。
4. **INV-01 · 新事件只增不改**：`workspace.trust`、`hook.run`、`verify.required`、`plan.proposed` / `plan.decided`、
   `worktree.*` 进协议时 SCHEMA_VERSION 9 → 10，附 legacy fixture。
5. **INV-08 · 历史出题与运行不进 CI**：沿用 `scripts/check-ci-no-l2.ts`。
6. **INV-13 · 不新增埋点**：验证三态与预算只从事件投影计算。

## 5. 已知代价

- **不替用户 push / 开 PR**：DoD 的终点是本地提交。远程操作由用户做，这是刻意的边界。
- **代码理解只做 TS/JS**：其它语言只有文本搜索。多语言要么接 LSP、要么接 tree-sitter，都是大块头，留到 M7 之后按需评估。
- **钩子以用户身份运行**：钩子是用户自己写的命令，domi 不沙箱它（与插件不同）。所以才要求钩子只能来自用户配置。
- 规矩按老样子：**先推进功能，测试验证类最后统一查漏补缺**（每条 AC 的 spec 放 TASK-M7 的最后一项）。
