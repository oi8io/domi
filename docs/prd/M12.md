## 1. 为什么是这一章

M9（模型配置）/ M10（会话体验与运行控制）/ M11（会话体验深化，含 009 窗口化加载）均已 COMMITTED 且开发完成。用户在使用/走查中提出四个修改点，全部是对**已交付功能**的修订，不是新章节：

1. **对话框取消手动输入模型**：只支持下拉菜单选；会话切过模型则展示会话当前模型，没切过展示默认模型（现状 Web 有「手填…」分支，TUI 有 `/model <名字>` 手填路径）。
2. **人工确认三档改为会话级**：不是全局通用的；设置页不能再出现，应该在对话框里做选择；形态照图 1（三档列表式：标题 + 一句描述）；**命名不叫 review**（安全相关谨慎命名，斜杠 `/review` 会让人以为是 review 代码）；相关修改一次性改到位，不留残留。
3. **计划/执行模式取消（B 方案）**：系统直接产出计划，需要确认时弹框（多少个问题就多少个 tab，每题 abcd… + 自定义输入），确认后直接执行；没有需要确认的，除非用户信息中有阻止执行的提示，否则直接开始执行。
4. **最右上角命名与侧边栏不一致**：已确认复现路径——改的是**会话标题**，侧边栏展示新值、右上角（会话页 header）未更新。

## 5. 需求条目

### PRD-M12-001 · 模型切换纯下拉 + 会话级展示

- **用户价值**：模型是会话内的选择，不是自由输入——下拉只列已启用 provider 的模型，选错/手填的歧义（同名模型归属哪家、名字不存在）不再发生；下拉展示跟随会话实际状态
- **说明**：
  - Web `ModelSwitch` 删除「搜索 / 手填…」分支（`custom` 状态、`input + datalist`、`client.resolveModel` 调用），只保留 `<select>` 按 provider 分组
  - TUI `/model <名字>` 手填路径收口（见定案 a）
  - **展示逻辑**：会话**切换过模型**（事件流有 `model.switch`）→ 下拉显示会话当前模型；**没切过** → 显示默认模型（配置的 model.name / 默认 provider）；切换后立即更新为会话当前模型
- **验收标准**：
  - AC-1: Web 模型切换只有下拉，无任何可输入框；选项 = 已启用 provider 的模型（按组，同名模型各占一行，M9-003 AC-2 不回退）
  - AC-2: 下拉里不再出现「搜索 / 手填…」入口；`model.resolve` 手填语义在 Web 端无调用路径（RPC 是否删除见疑点 a）
  - AC-3: 下拉展示逻辑：新会话（无 `model.switch`）显示默认模型；会话中途切换后显示会话当前模型（`status.model`），重开会话保持（事件流恢复）
  - AC-4: 清单为空（无已启用 provider）时下拉的呈现 = 禁用 + 提示去设置页启用（复用 CredentialNotice 引导），不出现输入框
  - AC-5: 切换成功仍写 `model.switch` 事件（INV-01），对话里能看到切换记录（现状行为不回退）
  - AC-6: TUI `/model`（无参）打开模型列表选择器（现状）；`/model <名字>` 的处理按疑点 a 定案
- **验收方式**：Web 组件测试（无 input 断言、分组渲染、空清单态、默认/已切换两态展示）+ TUI 命令测试回归 + 手工走查
- **层级**：Negotiable
- **优先级**：P1
- **定案**（2026-09-23）：
  - a. `model.resolve` RPC 与 TUI `/model <名字>`：**两端都不要手填**。Web 删手填分支、TUI `/model` 只开选择器；`model.resolve` RPC 无调用方，连同测试一起删
  - b. 下拉不放「管理模型…」入口（最小改动）；清单空时禁用 + 引导去设置页

### PRD-M12-004 · 计划流改造：取消 plan/act，系统直接产出计划（B 方案）

- **用户价值**：不再有「计划模式 / 执行模式」两套心智；系统先想清楚、把不确定的点问明白（每题一个 tab，abcd… + 自定义），确认后直接执行；没疑问就直接开跑，不被模式切换打断
- **说明**（B 方案，用户 2026-09-23 拍板）：
  - **取消 plan/act**：删除权限引擎 plan 分支（`permission.ts` L146-152、`PLAN_MODE_READONLY`、`PLAN_SUBMIT_CAPABILITY` 语义）、`session.ts` mode 字段/setMode/AUTO_PLAN_REASON、Composer ModeToggle UI；`mode.switch` 事件语义移除或改造（新档位事件另立，见 PRD-M12-002）
  - **新流程**：系统（新任务或复杂请求时）直接产出计划 → **需要与用户确认的点**整理成确认弹框（多少个问题就多少个 tab；每个问题给 abcd… 选项 + 自定义输入）→ 用户确认 → 直接执行
  - **无确认点时**：除非用户信息中有**阻止执行的提示**（如「先别动 X」「不要删除 Y」），否则直接开始执行计划
  - 保留能力：计划可拆步骤转长任务（现状 plan.submit 的 asTask 语义平移进新流程）；执行前审批由「确认弹框」承担（取代 elicit 表单审批）
- **验收标准**：
  - AC-1: 全仓无 plan/act 模式概念残留：权限引擎无 plan 分支、session 无 mode/setMode、Composer 无 ModeToggle（grep 可证）；`plan.submit` 能力移除或改造为新流程入口
  - AC-2: 需要确认时：确认弹框按问题数分 tab，每题 abcd… 选项 + 自定义输入；用户确认后系统按确认结果执行
  - AC-3: 无需确认时：用户信息无阻止提示 → 直接执行计划；有阻止提示 → 停下来先问（阻止提示优先级最高）
  - AC-4: 新任务创建流程（M8-005 依赖自动 plan）改走新流程：产出计划 → 按需确认 → 执行，行为等价不倒退
  - AC-5: 转长任务能力保留：计划可拆步骤 → 后台长任务（现状语义不回退）
  - AC-6: 危险能力确认不回归：新确认弹框同样遵守危险清单（任何档位都要确认，与 PRD-M12-002 一致）
- **验收方式**：权限引擎测试改造（删 plan 分支后矩阵回归）+ runtime 新流程测试（有/无确认点、阻止提示、转长任务）+ Web/TUI 组件测试（确认弹框多 tab 渲染）+ 协议快照 + 任务创建回归
- **层级**：Negotiable
