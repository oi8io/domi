- 笔记: 两套编号的对法——**对外只有视图 seq**。一个会话的视图前缀（父链到分叉点）一旦建好就不再变，

  压缩、指标都走视图，只有追加写的是自己。`session.branch` 收到的 atSeq 若落在祖先那一段，
  就直接从那个祖先分（「从这条消息分支」和这条消息属于哪一段无关）。编号规则写进了 `session.subscribe` 的协议说明。
  已知不对等：`domi trace` 读的仍是会话自己的事件（不带父链），记 OPT-M3-007

### BUG-M3-014 · 一轮在上限处停下时，没跑的工具调用没有结果

- 现场: 写 kill -9 恢复时发现的。模型一批返回多个调用，第 20 次到上限（或参数解析连续失败、流在调用之后中断）就停，
  剩下的 tool.call 没有 tool.result。buildContext 照样把它们拼进 assistant 消息，下一轮请求会被 Anthropic 以
  「tool_use 没有对应 tool_result」拒掉——用户看到的是「再说一句就报错」
- 测试: kernel/loop.spec.ts「停下时没来得及跑的调用也配上结果」（修之前红）

### BUG-M3-015 · 分层提示词从来没有发给模型
- status: fixed
- 现场: 修 BUG-M3-012 时发现的。packages/prompt 能拼、`domi prompt dump` 能看，但 runtime 调 runTurn 时不带任何提示词，
  kernel 的 buildContext 也只拼对话本身——身份层、**注入防护层**（PRD-M2-006 AC-1）在真实会话里一次都没生效过。
  权限层照常拦截，所以没有越权；但「模型把工具结果当指令」的概率比设计的高
- 修法: kernel 新增 `withPrompt`：system 放最前，会变的部分（工作目录）只接在最后一条 user message 上（PRD-M1-004 AC-3）；
  DomiSession 每轮用「内置层 + 配置层」拼好交给 runTurn；提示词不进事件流。
  AI SDK 不收 messages 里的 system，适配层改为走 `instructions`
- 已知代价: 工作目录接在「最后一条 user message」上，上一轮的那条下一轮就不带了——prompt cache 的前缀在对话历史里会断一次。
  工作目录其实不常变，要不要挪进稳定前缀，等 cache 命中率的 nightly 数据（PRD-M1-004 AC-2）再定

### OPT-M3-001 · 每个 token 一条事件
- status: recorded
- 说明: model.delta / model.reason 逐 token 落库、逐 token 推送。事件库体积与推送量都随 token 数线性增长。
  合并落库会改变「事件即真相」的粒度，要和 L1 回放、压缩一起想，不是 UI 层能修的

### OPT-M3-007 · `domi trace` 看分支会话时不带父链
