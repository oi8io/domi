## 实现笔记（2026-09-24）

- **协议多了一个字段**：`user.input.noteIds`（可选）——正常收场后才到的补充由 daemon 拼成下一轮的 user.input，
  端上凭它把本地排队的补充认作「已送达」，不然重连对账会把它当退回、在输入框里重复出现。SPEC-M13-001 取舍-4 已补记。
- **daemon 的 ActiveTurn 从占住「忙」那一刻就建好**（不是等宿主开跑）：校验窗口里来的补充也能排上；
  校验失败 / 还没开跑就被中断 → 按异常收场退回。
- **kernel 的三个检查点只看外部 signal**；所有 `stop()` 现在都写 `error.stopReason`，中断时再带 `by`。
  没开始的调用补 `interruptedResult`（reason = interrupted），不是 `notRunResult`。
- **spawn 子 agent 接上了 ctx.signal**（原来不看 signal，父轮中断要干等子 agent 跑完）。
- **Web 的旧测试改了口径**：`render.spec` 里「忙的时候发送按钮不可点（PRD-M3-004 AC-3 的前端那一半）」
  改为「忙的时候发送变成补充」（PRD-M13-001 AC-9）。daemon 侧 `session.submit` 忙时仍回 SESSION_BUSY，M3-004 AC-3 本身不变。
- `mergeDraft`（退回的补充怎么放回草稿）放在 client-core，Web / TUI 共用。
- 未做：真终端 / 浏览器手测（进 DoD）；M13 进 `check-ac-coverage` 强制范围（与 M11 / M12 一起补）。
