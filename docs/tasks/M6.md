## 实现说明（2026-09-15）

- **插件形态**：`domi-plugin.yaml`（api: 1），四类扩展点 tool / skill / mcp / ui。工具名即能力 id：`plugin.<插件>.<工具>`，
  config 模板里给了 `plugin.*` → ask 的示例规则。
- **权限快照**：`~/.domi/plugins/installed.json` 记 manifest 的 sha256 与确认过的 read / write / net；
  manifest 被改过 → 插件停用（doctor 与 `domi plugin list` 都会显示）。非交互安装直接拒绝。
- **沙箱**：Linux 用 bwrap（无网络、只读根、工作区不挂载），macOS 用 sandbox-exec（未真机验证，记在 008）。
  插件代码只经 stdio JSON 行向宿主要 readFile / writeFile / fetch / log，宿主按快照核对，越权落 permission 事件。
  单文件发行版里用 `BUN_BE_BUN=1` 起 runner。没有沙箱时带代码的插件不加载，除非 `plugins.allowUnsandboxed: true`。
  超时杀整个进程组；崩溃落 `plugin.error`（SCHEMA_VERSION 9，legacy-v9 fixture）。
- **冒烟**（桩模型）：文件 / 网络各 5 条逃逸全被拦，声明过的读能用，越权有 permission 事件；超时 1s 被杀；崩溃有 plugin.error；
  没有残留 runner。改 manifest → 停用。scaffold 出的三类模板自带测试并通过。
- **门禁**：guard:api 覆盖 `packages/plugin/.api.md`；新增 guard:docs（文档里的 ```ts run 例子要跑通）、
  guard:repo（CONTRIBUTING 与 good first issue 草稿）、guard:l2（L2 不进门禁），三道都先造违规确认会红。
  `bun test` 排除 `eval/l2/tasks/**`（题目工作区里故意放着会红的测试）。
- **L2**：20 道题，每道都验证过「改之前 check 失败、放入 solution 后通过」。`domi eval l2 [--rounds 3] [--only id]`
  真跑模型，报告写 `eval/l2/reports/`，只进 nightly / 手动。

## 缺陷登记

### BUG-M6-001 · `domi eval l2 --rounds N` 的选项从来没生效
- status: review
- 发现：2026-09-16，做 TASK-M7-008（`domi eval mine --out …`）时
- 原因：CLI 用 parseArgs(strict:false) 解析，不认识的 `--rounds` 被当成布尔丢掉，值 `3` 掉进位置参数，
  eval 子命令里 `args.indexOf('--rounds')` 永远是 -1——轮数总是默认的 3，而 `3` 还会被当成题 id 过滤掉全部题
- 修复：ParsedCli 增加 rawArgs（子命令之后的原始参数），eval 用它自己解析选项
