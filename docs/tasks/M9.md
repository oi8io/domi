## 缺陷与待优化登记

### BUG-M9-001 · 会话里切过的模型，重开会话就丢了
- status: fixed
- 发现：2026-09-18 复核（读代码）。`session.ts` 构造时只读 `config.model.*`，全仓没有回放 `model.switch`；事件也不带 provider，想恢复也恢复不出来。修在 TASK-M9-004。

### BUG-M9-002 · 切到没配 key 的 provider 时，把默认 provider 的 key 发给了别家
- status: fixed
- 发现：2026-09-18 复核（读代码）。`session.ts` `buildProvider`：`apiKey: other?.apiKey ?? m.apiKey`，注释写「没配就沿用默认的」。
  后果：例如切到 deepseek 而没配它的 key，请求带着 Anthropic 的 key 发往 api.deepseek.com。修在 TASK-M9-000。同类：`DOMI_API_KEY` 曾对所有 provider 生效，一并收窄到默认那一家。

### BUG-M9-003 · 探测失败时，手填的模型标成了 manual 而不是 fallback
- status: fixed
- 发现：2026-09-19 TASK-M9-012 补 daemon 层 `model.list` 测试时（照 AC 写断言，红了）。PRD-M9-001 AC-2 要求降级来的本地清单标 `source: fallback`；
  `ModelCatalog.list` 不管探测成败都把 `providers.<id>.models` 标成 `manual`，`model-probe.spec.ts` 当时照着实现写了 `manual`，没照 AC。
- 修：探测失败时整份本地清单标 `fallback`，探测成功时手填的仍是 `manual`（补充）。runtime 测试改回 AC 的说法，daemon 层两种情况都断言。
