## 2. 取舍记录

### SPEC-M14-003 · 步级快照接进 daemon

**取舍-1 · 快照触发点放在 runtime，包一层 ToolRunner，kernel 零改动**
- 候选：①在 `capability` 的 `ToolRegistry.run` 里加 ②runtime `session.ts` 在 `LoopDeps.tools` 外包一层 ③kernel loop 加端口。
- 选 ②。① 会让 capability 依赖 `@domi/checkpoint`（git IO），污染共享层；③ 让 kernel 碰 IO，违反 INV-02。
- 做法：runtime 新增 `checkpoints.ts` 的 `CheckpointController`（持有 `ShadowRepo`，workTree = 会话 cwd）。
  会话构造时可选注入；`submit()` 开头 `resetTurn()`；`LoopDeps.tools` 换成包装后的 ToolRunner：
  `before` 在调用 `this.tools.run` **之前**（该轮第一个改文件工具 → 基线），`after` 在其返回**之后**（成功 → 快照），
  产生的 `fs.checkpoint` 事件并入 outcome.events，由 kernel 统一按因果顺序落盘（与权限事件同一条纪律）。
- 改文件工具名单 = `fs.write` / `fs.edit` / `shell.exec`（PRD AC-1 原文；M7-001 已把 edit 归 fs.write 能力，此处按工具名拦截）。
- **不拦截**：`fs.read / fs.glob / fs.grep / shell.output / shell.kill / outline / diagnostics / ask-user / plan.update / skill.load / task.spawn / memory.*` 等只读或非文件工具。

**取舍-2 · 基线 = 该轮第一个改文件工具调用前取一次；after = 每次成功返回后取**
- 基线随第一个改文件工具的调用 id 落盘（`fs.checkpoint{phase:'baseline', toolCallId}`），与 PRD 原文「每一轮第一次执行…之前」一致。
- 工具**失败 / 被拒**（`ok:false`，含 `user_denied` / `permission_denied` / `invalid_args`）不取 after——没有改动，取是浪费；权限被拒的调用仍可能先落了基线（空快照，允许为空提交，无害）。
- 中断（interrupted）：执行中被打断的工具按 kernel 语义结果照录、reason=interrupted——after 仍取（结果已经落盘，改动已经发生）；`notRunResult` / `interruptedResult` 补的调用没有执行，不取。

**取舍-3 · 无变化跳过：after 前先 `git diff --quiet HEAD`，无变化复用上一快照 id**
- 空提交（`commit --allow-empty`）每轮每工具一次是纯浪费：`shell.exec` 常常只是读 / 跑测试。
- 判定：`git diff --quiet HEAD` 返回 0（工作树与 HEAD 一致）→ 不产生新快照，`fs.checkpoint` 的 `id` 复用上一个快照 id（客户端 diff 出来为空，语义正确）；非 0 → 快照。
- 基线同理：与上一快照无差异时复用，不产生空提交。
- `ShadowRepo.snapshot()` 已用 `--allow-empty` 且每步都提交的语义保留——供显式场景（如 010 回滚前快照）使用；本册的 003 路径走「无变化跳过」。

**取舍-4 · 降级明示，不阻断**
- git 不可用（`GitUnavailableError`）/ 快照抛错 / 单次超时（SPEC 定 5s，用 `Promise.race` 包）→ 落 `fs.checkpoint{phase, toolCallId, ok:false, id:null, message}`，**不阻断工具与本轮**（AC-4）。
- 端上：改动 tab 该范围显示「这一步没有快照」，回退到只列 `fs.snapshot` 出现过的文件名（无 diff 内容）。
- 注意 `fs.checkpoint{ok:false}` 也要照常落盘——「没快照」这件事本身要可见、可审计。

**取舍-5 · 新事件 `fs.checkpoint`，不扩 `snapshot` / `fs.snapshot`**
- `snapshot`（M1-011 事件）只记 id/label/files，没有工具调用关联与成败；`fs.snapshot` 是内容指纹、无快照 id。
- `fs.checkpoint` schema（全部必填，仅 message 可选）：
  ```
  { t: 'fs.checkpoint', phase: 'baseline' | 'after', toolCallId: string,
    id: string | null, files: number, ok: boolean, message?: string }
  ```
  - `id`：影子仓库快照 id（`null` = 降级没取到）；`files`：快照文件数（降级 0）；`message`：降级原因（git 未装 / 超时 / 失败原文）。
- 反悔成本：低。事件新增；删除功能后旧事件照常解析、照常进上下文忽略。

**取舍-6 · `checkpoint.diff` RPC：daemon 从事件流重建「快照 ↔ seq」索引，diff 在 daemon 算**
- RPC `checkpoint.diff { sessionId, fromSeq?, toSeq?, path? }` → 与 `worktree.diff` 同形的 `{ available, reason?, files: [{path, status, patch, truncated?}] }`。
- 索引 = 本会话事件流里所有 `fs.checkpoint`（`id` 非空）的投影：`{ seq, id, phase, toolCallId }`。重启后可重建（事件不丢）。
- **区间规则**（端上只传 fromSeq/toSeq，快照选择在 daemon）：
  - 给定 `[fromSeq, toSeq]`，先找 `turnStart` = 最后一个 `user.input` 的 seq ≤ fromSeq；`baseline` = 该轮内第一个 `fs.checkpoint`（seq ≥ turnStart）——若 fromSeq 之前没有该轮内的 checkpoint，取轮内第一个。
  - `from` = 最后一个 `fs.checkpoint` 且 seq ≤ fromSeq，但**不小于** baseline.seq；若该区间内没有任何 checkpoint → `from` = baseline。
  - `to` = 最后一个 `fs.checkpoint` 且 seq ≤ toSeq（不小于 from）。
  - `from == to` 或没有 checkpoint → `available:false`。
- 范围换算：
  - **本轮**：`fromSeq` = 最后一个 `user.input` 的 seq，`toSeq` = head。
  - **整个会话**：`fromSeq` = 1（= 会话起点），`toSeq` = head——`from` 取会话第一个 checkpoint，`to` 取最后一个。
  - **某一步**：`fromSeq` = 该步 in_progress 事件的 seq，`toSeq` = 该步变 done/skipped 的 seq（见 SPEC-M14-004 取舍-2 的区间规则），`toSeq` 缺省为 head（步还在进行中）。
- diff 内容：`ShadowRepo.diff(from, to)` 返回文件列表，再对每个文件 `git diff --no-color from to -- <path>` 取 patch（镜像 `worktreeDiff` 的 `clipPatch`，截断 200k）；大文件（`contentNotSnapshotted`）只列路径与状态、patch 空、标 truncated。
- `path` 可选：只取该文件的 diff。

**取舍-7 · 非隔离丢弃 = `fs.discard` 事件 + `checkpoint.discard` / `checkpoint.discard.undo` RPC**
- 隔离任务沿用 `worktree.discard / worktree.restore`（回收站语义，可撤销）——不动。
- 非隔离会话（自由会话 / 没隔离的任务）：丢弃 = 把该文件恢复到**所选范围起点**的快照内容。
  - 流程：先 `repo.snapshot('丢弃前自动快照')` 拿 undoSnapshotId（可撤销的保证，AC-7）→ `repo.restorePath(rangeStartSnapshotId, path)`（见下）→ 落 `fs.discard` 事件。
  - `fs.discard` schema：`{ t: 'fs.discard', path, rangeStart: string, undoSnapshotId: string, reason?: string }`（reason = 用户选择或「整份丢弃」）。
  - 整份丢弃 = 对当前范围内每个文件各做一次单文件丢弃（每文件一条事件，审计粒度一致）。
- `ShadowRepo` 新增 `restorePath(id, path)`：目标快照里有该文件 → `git checkout <id> -- <path>`（含 staged）；没有 → 从工作树与索引移除（`git rm --cached --ignore-unmatch` + 删文件）。与 `restore()` 同纪律：不动 HEAD、只动索引与工作树。
- `checkpoint.discard.undo { sessionId, eventSeq }`：按 `fs.discard` 事件的 `undoSnapshotId` 做 `restorePath`——与 worktree 的「撤销丢弃」对等。
- 运行中（busy）拒绝丢弃（与现状一致）。

**取舍-8 · bench：快照耗时基准进 bench，不进 CI 门禁**
- `bench/shadow-snapshot.ts`：在 domi 自身仓库（`packages/checkpoint` 的 `__dirname` 上溯到仓库根）上跑 N 次 `snapshot()` 与「无变化跳过」路径，输出中位数 / P95。
- 只报告不 gate：git 版本与机器差异太大，进 CI 门禁会变成假阳性（SPEC 记录，不为此改 CI）。

  - 产物：`artifactsView` 的 `artifacts.length + uploads.length`
  - 上下文：`contextView` 的占用百分比（同 `session.metrics.contextPercent` 口径）

### SPEC-M14-005 · 改动 tab

**取舍-1 · 范围与数据源**
| 范围 | 数据源 | 谁有 |
|---|---|---|
| 本轮（默认） | `checkpoint.diff`（turn 区间） | 全部会话 |
| 整个会话 | `checkpoint.diff`（1..head） | 全部会话 |
| 某一步 | `checkpoint.diff`（步区间，从进度 tab 点入，可清除） | 全部会话 |
| 对比基线 | `worktree.diff` | 仅隔离任务（有 `worktree.create`） |

- 降级（`available:false` 或 git 没装）：显示「这一步没有快照」，回退列出该范围内 `fs.snapshot` 出现过的文件名（无 diff 内容，AC-4 的可见降级）。

**取舍-2 · diff 渲染**
- 统一视图为默认；展开模式（001 AC-3）下可切左右对照（老 → 新）。
- 行内**词级高亮**：client-core 纯函数 `wordDiff(oldLines, newLines)`（LCS 分词），输出可渲染的 added/removed span 结构，Web 与 TUI 共用（009 不做词级，见 009 取舍）。
- 语法高亮复用 `client-core/highlight.ts` 的轻量高亮（PRD-M11-003 AC-9，不引新库）。
- 上下文行默认 3 行、可展开（diff 头/尾的未变行）。
- 折叠规则（AC-5）：patch > 100KB 或文件 > 5MB → 默认折叠标行数；锁文件 / 生成文件（`pnpm-lock.yaml`、`package-lock.json`、`yarn.lock`、`bun.lock*`、`dist/`、`build/`、`*.min.js`）默认折叠；二进制（patch 空且有二进制标记）只显示大小变化；图片（扩展名匹配）显示前后对照；「内容未快照」的大文件按 M1-011 AC-5 明示。

**取舍-3 · 实时更新（AC-6）**
- 订阅事件流；出现新的 `fs.checkpoint` / `fs.snapshot` 事件 → 该范围列表增量刷新（client-core `changesView` 纯函数重算，组件 diff 后 patch）。
- 正在看的文件有新改动 → 该文件行出现「有新改动 · 刷新」（不自动替换，避免打断阅读）。

**取舍-4 · 丢弃（AC-7，P0 = 整份 + 单文件；单个改动块 P1）**

- 非隔离：`checkpoint.discard`（见 SPEC-M14-003 取舍-7），每次落 `fs.discard` 事件；可撤销（`checkpoint.discard.undo`）。
- 运行中（busy）丢弃按钮禁用（与现状一致）。
- 带回（AC-8）：仅「对比基线」范围显示，三选一沿用 `worktree.apply`（squash / merge / branch），行为不变。

**取舍-5 · 文件右键 / 更多（AC-9）**
- 用默认程序打开（`shell.open` 类能力，桌面端；Web 里 = `window.open(file://…)` 不可行 → 只提供「在访达中显示 / 复制路径 / 引用」+ 打开目录。SPEC 记录：Web 的「默认程序打开」受浏览器限制，仅 Desktop 提供；Web 提供「复制路径 / 引用 / 在访达中显示」）。

### SPEC-M14-004 · 进度 tab

**取舍-1 · `planView` 投影：只看最后一条 `plan.update`，但步骤区间要回溯**
- 状态映射：`done` → 勾 + 划线；`in_progress` → 高亮 + 已用时（head − 该步开始 seq 的 ts）；`pending` → 灰；`skipped` → 灰 + 标「跳过」。
- `dependsOn` 用缩进（深度 = 依赖链长度），不画 DAG。
- **区间规则（AC-2）**：对最后一条 plan.update 里的每个步骤 S：
  1. 从最新往前找第一条 `plan.update`，其中 S（按 id；id 被替换后按 text 匹配）的 status = `in_progress` → `startSeq` = 该事件的 seq；找不到 → S 没跑过（区间空）。
  2. `endSeq` = 之后第一条使 S 的 status ≠ `in_progress` 的 `plan.update` 的 seq − 1；若 S 在最后一条仍 in_progress → `endSeq` = head。
  3. 该步的「干了什么」= `[startSeq, endSeq]` 区间内的事件：工具调用（`tool.call` 计数 + 摘要）、改过的文件（该区间 `fs.checkpoint` / `fs.snapshot` 的路径，点了跳改动 tab 的「某一步」范围）、耗时（`ts(endSeq) − ts(startSeq)`）、token（该区间 `model.usage` 聚合）。
- **计划整份替换**：步骤 id 变了 = 新步骤；旧 id 消失且没有 done = 视为「未开始」（不造假状态）。步骤 id 相同、text 变了 = 同一步骤（id 优先）。

**取舍-2 · 子 agent 与 DAG（AC-3）**
- `task.spawn`（子会话）与 `task.node`（DAG 节点）按 seq 落在对应步骤区间下；显示目标（spawn.goal / node 标题）与状态、耗时。
- 点击子会话：打开子会话视图（只读——沿用现有会话只读打开方式）。

**取舍-3 · 底部固定区（AC-4）**
- `verify.required`：第几次 / 是否最后一次（事件投影）；排队中的补充条数（`$notes`，M13 已有）；「计划还剩 N 步 · 继续」（与 `ResumeBar` 同一个 action，`plan.interrupted` 时突出）。

**取舍-4 · 无计划时的动作摘要（AC-5）**
- 没有 `plan.update`（自由会话常见）→ 不显示空白：本轮（最后一个 `user.input` 起）工具调用按类计数（fs.* / shell.* / memory.* / task.* / skill.* / mcp.* / 其他）+ 最近 5 个动作（工具名 + 摘要参数）。

### SPEC-M14-006 · 上下文 tab

**取舍-1 · 分段数据：`model.request` 加可选 `ctx`，kernel 纯计算**
- `model.request` 加可选字段：
  ```
  ctx?: { layers: Array<{ id: string, role: 'system' | 'user', cacheable: boolean, approxTokens: number }>,
          tools: number, history: number }
  ```
  - `layers`：`assemble()` 的层清单（`PromptParts` 增加可选 `layers`，runtime `prompt()` 填；kernel 原样透传）。
  - `tools`：`deps.tools.schemas()` JSON 序列化文本的 token 估算（kernel 算，纯计算零 IO）。
  - `history`：`buildContext` 结果消息 JSON 序列化文本的 token 估算（kernel 算）。
  - **估算口径**（全仓唯一，`@domi/protocol` 的 `estimateTextTokens`；回写自 BUG-M14-001）：中日韩字符（含全角标点）每字按 1 token，其余字符每 4 个按 1 token，向上取整。
    原来的「字符数 / 4」对中文低估 3–4 倍：一个汉字在各家分词器里约 0.7–1.5 token，却只算 0.25。仍不引 tokenizer（ADR-008），只修口径。
- 只增不改：旧事件没有 `ctx` 照常解析（AC-2）。
- **总量** = 最近一次请求的 `model.usage`（`metrics.contextTokens` 同源，BUG-M13-002 口径）；`ctx` 里是**估算**，端上标「约」，差额 = 未归类（建议 j，不按比例硬凑）。

**取舍-2 · 分段映射（AC-1 的九段）**
| 段 | 来源 |
|---|---|
| 系统提示（内置层） | `ctx.layers` 中 id ∈ {identity, guardrail, conventions, workspace} 之和 |

| 压缩摘要 | 端上投影：该会话最近一次覆盖当前范围的 `ctx.compact.tokensAfter`（约） |
| 附件 | 端上投影：当前窗口内 `user.input.uploads` 的 size/4 + 图片数 ×1600（约；size 是字节数、拿不到正文，按字节 /4 估——UTF-8 汉字 3 字节，约 0.75 token/字，与上面的口径同量级，不改） |

## 3. 接口契约

### 3.1 事件（SCHEMA_VERSION 16）

```ts
// 新增
fs.checkpoint   { t, phase: 'baseline' | 'after', toolCallId: string, id: string | null, files: number, ok: boolean, message?: string }
ctx.fileref     { t, path: string, lineStart: number, lineEnd: number, side?: 'new' | 'old', text?: string }
```

- `PromptParts`（kernel/preamble.ts）加可选 `layers?: Array<{ id, role, cacheable, approxTokens }>`（结构类型，不 import @domi/prompt）。

### 3.2 RPC（PROTOCOL_VERSION 不变）

```ts
'checkpoint.diff'          { sessionId, fromSeq?, toSeq?, path? } → { available: boolean, reason?: string, files: [{ path, status, patch, truncated? }] }
'checkpoint.discard'       { sessionId, path, fromSeq, toSeq } → { ok: boolean, eventSeq: number }
'checkpoint.discard.undo'  { sessionId, eventSeq } → { ok: boolean }
'session.context'          { sessionId } → { trusted: boolean | null, rules: string[], skillsTotal: number,
                                             mcp: [{ server, tools: string[] }], context: { strategy: string, thresholdPercent: number | null } }

```

- `session.submit.refs` 扩为 `RefLink | FileRef`（见 SPEC-M14-008 取舍-2）。

## 5. 明确留白

1. **TUI 偏好不持久化**：TUI 按会话类型默认开 / 关，手动开关只活在当前进程。
2. **「默认程序打开」Web 受限**：浏览器不允许 `file://` 打开，Web 只提供复制路径 / 访达 / 引用；Desktop 提供完整动作。
3. **上下文分段里的「压缩摘要 / 附件」是端上投影的约数**：它们的内容混在对话历史里，不单独拆事件；若实测偏差大，后续再让 buildContext 输出更细的分段（不改事件语义）。
4. **`model.request.tokensIn` 名实不符**（PRD §3 #7）：本册不改（避免改已有事件语义），上下文 tab 不用它，用 `ctx` + usage。
5. **单个改动块丢弃（005 AC-7 的 hunk 级）与记忆撤销（006 AC-7）为 P1**：超出 20% 预算时先砍这两个（PRD §7）。
6. **跟随 / 时间旅行 / 插件 tab 槽 / Desktop 独立窗口 / artifact.mark / 侧问**：PRD §4 明确不做，另起条目。
7. **产物「产生于哪一步」对 shell 创建的文件是兜底 seq（约）**：没有 fs.snapshot 可精确定位，不为此改 fs.snapshot 语义。
8. **checkpoint 快照的「无变化跳过」用 `git diff --quiet HEAD`**：对超大型工作树（十万级文件）每次判定也有成本，本册以 domi 自身规模为准进 bench，不提前优化。
