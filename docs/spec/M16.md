## SPEC-M16-001 · 会话列表排序：最后一条消息

### 1. 现状问题（探查实证，2026-10-09）

`packages/store/src/sessions.ts` 的列表 SQL 是 `ORDER BY s.updated_at DESC, s.created_at DESC`，
`updated_at` 由 `sqlite-event-log.ts:123` 在**每次事件落库**时刷新。两条实证结论：

1. **`updated_at` 是"最后任意事件"**：tool.call / permission / ctx.note / fs.snapshot 等都会把会话顶到列表最上，
   与"会话列表按最近对话排序"的用户直觉不符（豆包等聊天产品以最后一条消息为准）。
2. **`upsert` 零时间戳 bug**：`upsert` 不带 `updatedAt`/`createdAt` 时 `now = 0`，而 `ON CONFLICT` 分支无条件写
   `updated_at = excluded.updated_at`——切模型 / 自动起标题的 upsert 会把该会话 `updated_at` **清零、沉到列表底**；
   同批发现 daemon 创建会话先 `upsert` 再 `append`，`created_at` 也是 0（`created_at DESC` 兜底键实际失效）。

### 2. 决策

**排序键 = 最后一条消息**（`user.input` / `user.note` / `model.delta` 的最新落盘 ts），无消息会话按创建时间，
同刻按创建时间倒序。本轮不做置顶。

- 实现为 `list()` 查询时**派生列 `lastMessageAt`**（读时计算，与 `first_input` 同先例），
  排序 `ORDER BY lastMessageAt DESC, created_for_sort DESC`。
- **不动 `updated_at` 语义**：它仍是"最后任意活动"，被 `usage.summary` 粗筛（runtime-host.ts:680）
  与项目 `recentTasks`（projects.ts:111）依赖。
- 消息白名单含 `user.note`（M13 运行中补充，用户产出的内容，端上已渲染为消息）。

### 3. 取舍记录

| # | 取舍 | 选择 | 理由 |
|---|---|---|---|
| 1 | lastMessageAt 放哪 | **读时派生列**（list() SQL 子查询），不复用/收窄 `updated_at` | ①`updated_at` 被 usage 粗筛与 recentTasks 消费，收窄会波及用量统计；②读时算与 first_input 先例一致、INV-12（投影由事件流算出）、无缓存漂移 |
| 2 | "消息"事件集合 | `user.input` + `user.note` + `model.delta` | 用户输入 / 运行中补充 / 助手回复构成"对话"；`model.reason`（思考）与 tool/permission/ctx 等不算；M15 起 model.delta 按段切条，多条 delta 同属一条回复，取**最后一条 delta 的落盘时间** |
| 3 | 存量 `created_at=0` 怎么修 | 根因修复（upsert 注入 clock）+ **读时兜底**（SQL `CASE WHEN created_at=0 THEN MIN(events.ts)`），不做数据迁移 | `check-migrations.ts` 白名单禁止 UPDATE 类迁移（只许新增形状）；该列只被列表排序消费，读时兜底等价且零运维 |
| 4 | 无消息会话的时间 | 回退**创建时间**（含读时修复后的有效创建时间） | 新会话（刚创建、还没说话）应排顶；回退到"最后活动"会让纯工具活动把无消息会话浮起来，违背"只按消息排"的口径 |
| 5 | `lastMessageAt` 协议字段 | RPC 会话摘要新增**可选** `lastMessageAt` | 老 daemon 不给，客户端回退 `updatedAt`；TUI 的排序与相对时间显示（`ago`）与列表同源 |

### 4. 契约增量

- `store` `SessionSummary` 新增 `lastMessageAt: number`（每行都有值：无消息 = 有效创建时间）。
- RPC `session.list` 摘要新增可选 `lastMessageAt: int`。
- **事件契约不变**：SCHEMA_VERSION 仍 17，无新事件、无字段变更（INV-01 不破）。

### 5. 测试要点（测试先行）

- 非消息事件（tool.call / permission / ctx.note / session.kind / model.request）不改变列表序与 `lastMessageAt`；
- `user.input` / `user.note` / `model.delta` 任一落盘才刷新；
- 同刻（相同 ts）按创建时间倒序；无消息会话按创建时间；
- 存量 `created_at=0` 行读时用首事件时间兜底（排序与 `lastMessageAt` 均正确）；
- `upsert` 不带时间戳 → `created_at`/`updated_at` 为真实时钟（回归）；
- TUI 会话浮层组内按 `lastMessageAt` 排、相对时间显示 `lastMessageAt`。
