## 2. 取舍记录

- **取舍-1 · 厂商模板放 config，不放 model**。Web 要显示模板（名称、默认地址、能力），而 apps 不许 import model（`no-logic-in-apps`），
  model 又带 AI SDK。模板是**纯数据**（没有 SDK），放 `config/src/vendors.ts`；model 的 factory 只按模板里的 `adapter`（`openai-official | anthropic | openai-compatible`）选 SDK 构造器；
  Web 经 `provider.vendors` 拿，不自己写一份。`guard:providers` 的允许文件改为 `config/src/vendors.ts` 与 `model/src/factory.ts`、`model/src/probe.ts`，扫描范围扩到 config / daemon / runtime / cli / apps / client-core。
  反悔条件：模板需要带代码（例如某家要自定义 header 构造）→ 那一部分挪进 model，模板仍是数据。
- **取舍-2 · 运行期只有 `providers` 一个真相源**。`loadConfig` 结束时把旧写法（`model.api_key / base_url / capabilities`）并入
  `providers[model.provider]`，再把每一项规整成 `ResolvedProvider { id, name, vendor, protocol, baseUrl?, apiKey?, enabled, models, capabilities, inferred }`。
  `DomiConfig.model` 只剩 `{ provider, name }`（类型上保留旧字段为只读兼容，runtime 不再读）。session 的 `buildProvider` / `checkCredential` 只查 `providers[id]`，
  **找不到 key 就报缺凭据，绝不回落到别家的 key**（BUG-M9-002：现状会把默认 provider 的 key 发给别家的地址）。
  用户没写任何 provider 时，默认模型所在的那一家按模板隐式存在（保证零配置 + 环境变量能跑）。
  （2026-09-20 回写：`DOMI_BASE_URL` 的 env 覆盖入口删除——它让 base_url 随终端环境漂，两次把请求打到 `/anthropic/chat/completions` 的 404 上；base_url 只认配置文件。）
- **取舍-3 · id 规则与旧键**。id 正则 `^[a-z0-9][a-z0-9-]{0,31}$`。旧键 `openai-compatible` 合法，推断为 `custom`；`google` → `gemini`（地址用模板默认）。
  推断只发生在读的时候，不改用户文件；`inferred: true` 给 doctor 列出。
- **取舍-4 · 模型身份 = (provider, name)**。`model.list` 条目、`session.switchModel`、`model.switch.provider` 都带 provider id。
  手填解析顺序：默认 provider → 唯一命中 → 多处命中给候选 → 无命中报 `MODEL_UNRESOLVED`。「命中」查的是 `model.list` 的同一份清单（探测 + 降级），所以离线时也能按手填清单归属。
- **取舍-5 · 会话恢复读事件，不读 sessions 表**（v0.2 按实现改）。sessions 表的 `model` 列没有 provider，而事件流是唯一真相（INV-01）。
  `recover()`（打开会话时本来就调）回放最后一条 `model.switch`：有 `provider` 且该 provider 启用 → 用它；v11 老事件没有 provider →
  按默认那一家算（M9 之前的代码除非显式指定 provider，都是在默认那一家下换模型）；provider 已停用 / 删除 → 默认模型，并**追加一条** `model.switch`（带 reason）。
  v0.1 写的是「不追加事件、走 `session.notice` 推送」，改掉的理由：模型确实换了，这是事实；项目里进程级提示本来就落事件（`deliverNotices`），
  另开一条不落盘的推送通道等于两套提示机制；追加之后最后一条就是它，下次打开不会重复提示。协议因此不新增 `session.notice`。
- **取舍-6 · 探测放 runtime，协议细节放 model**。`probe.ts` 只做「给 protocol + base + key → Request」「给 Response JSON → ids / 下一页游标」和非对话模型规则，全是纯函数；
  `ModelCatalog`（runtime）持有注入的 fetch、10s 超时（`AbortSignal.timeout`）、`Promise.allSettled` 并发、缓存。
  缓存键 = provider id；指纹 = `protocol|baseUrl|sha256(key)|enabled`，指纹变了即失效；TTL 10 分钟，时钟可注入。domid 启动时不预探测（首个 `model.list` 才探），避免无网环境启动变慢。
- **取舍-7 · 翻译在端上**。daemon 发出的错误统一带 `data.messageKey` 与 `data.params`（`InvalidInputError` 增加这两个字段；`fail()` 的其它调用逐个补 key）。
  i18n 包是纯 TS（浏览器可用），client-core 暴露 `formatError(err, t)`；CLI 在进程里直接用 `t()`。key 命名 `<域>.<名>`，错误统一 `error.<名>`（沿用现有 `error.missing_credential` 等）。
  zh 为源：`en.ts` 的类型是 `Record<keyof typeof zh, string>`，缺键 typecheck 就红；`guard:i18n` 额外查参数名一致与「端代码里没有中文字面量」。
- **取舍-8 · 双渲染器共享一套条目渲染**。`Line`（现 `Transcript.tsx` 里的单行组件）不动；fullscreen 与 classic 只是摆放方式不同：
  - fullscreen：`render(..., { alternateScreen: true, incrementalRendering: true })`；`viewport.ts` 纯函数把条目展开成「显示行」（CJK 宽度用 `string-width`——Ink 本来就依赖它，这里只是在 apps/tui 里显式声明，锁文件不引入新包），
    按 `scrollTop / height` 切片；滚动条 = 一列，滑块高 `max(1, round(h * h / total))`。鼠标：开 SGR 1006 + 1002，自己解析 stdin 里的滚轮序列，Ink 的 `useInput` 不会看到它们（先于 Ink 摘掉）。
  - classic：已完成条目进 `<Static>`，进行中的一条与底部区域在动态区。
  - Ctrl+O：卸下 fullscreen 实例（离开备用屏）→ 把全部条目按 classic 格式一次写进 stdout → 等任意键 → 重新挂 fullscreen。
  - 失败回退：fullscreen 首帧前抛错 → 写 `~/.domi/state/tui-fallback`（一行时间戳），本次与之后都用 classic，直到用户显式设 `tui.renderer: fullscreen` 或 `DOMI_TUI_RENDERER=fullscreen`。
  反悔条件：Ink 的备用屏在某些终端（tmux -CC、Windows ConPTY）表现不稳 → 那些终端识别出来直接 classic。

## 3. 协议增量

| 方法 / 事件 | 变化 |
|---|---|
| `model.list` | params 加 `refresh?: boolean`；条目改为 `{ provider, providerName, name, source: 'probe' \| 'fallback' \| 'manual', vision, toolCall }`；result 加 `providers: [{ id, name, status: 'ok' \| 'fallback', error? }]` |
| `model.resolve`（新） | `{ name }` → `{ provider, name }` 或 `INVALID_PARAMS`（`reason = MODEL_UNRESOLVED`，或 `AMBIGUOUS` 带 `candidates`） |
| `provider.vendors`（新） | 厂商模板列表（只读，无凭据） |
| `session.switchModel` | 不变（`provider` 仍可选；端从条目带上） |
| `config.get` | `providers` 以规整后的形状返回（`apiKey` 仍只给掩码与来源） |
| `config.set` | 白名单见 PRD-M9-002 AC-8；`providers.<id>: null` = 删除整条（同时删 secrets 里的 key） |
| 错误 | 所有 `INVALID_PARAMS` / `INTERNAL` 的 `data` 带 `messageKey`、`params` |
| `model.switch` 事件 | 追加可选 `provider`（v12） |
