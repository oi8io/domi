## 2. 插件 API 从哪些内置能力归纳而来（PRD-M6-001 设计前置约束）

| 内置能力 | 形态 | 归纳出的扩展点 |
|---|---|---|
| fs.read / fs.write / shell.exec | Tool：zod 参数 + capability + execute | **tool**：名字、描述、JSON Schema、能力 id、执行入口 |
| memory.search / memory.recall | Tool，读宿主的数据 | tool 的执行要经**宿主 API**拿数据，而不是自己开库 → `ctx.readFile` / `ctx.fetch` |
| skill.load + 三个官方 Skill | SKILL.md（frontmatter + 正文） | **skill**：一个目录一个 SKILL.md，格式不变 |
| task.spawn | Tool，但需要会话上下文 | 插件 tool 拿不到会话对象——需要会话的能力不开放给插件（本轮不做） |
| MCP 模板（browser / computer） | config.yaml 的 `mcp.servers` 条目 | **mcp**：同一个 `McpServerSchema`，名字加插件前缀 |
| Web 的 Soul 面板、长任务面板 | 页面里的一块区域，数据走协议 | **ui**：静态 HTML，在隔离 iframe 里渲染，**不给**协议访问（本轮只做展示） |

共 10 个内置能力、4 类扩展点。「需要会话上下文的 Tool」与「能调协议的 UI」两类没有抽成扩展点：
内置的例子各只有一个，不够归纳。

## 3. 条目

### SPEC-M6-001 · manifest 与扩展点

`<插件目录>/domi-plugin.yaml`：

```yaml
name: word-count            # 小写字母数字与 -；工具名前缀、能力前缀都用它
version: 0.1.0              # semver
api: 1                      # 插件 API 主版本
description: 统计文件的行数与字数
permissions:                # 必填，哪怕是空的 {}（缺了安装失败）
  read: ["**/*.md"]         # 相对工作目录的 glob；宿主代读
  write: []
  hosts: []                 # ctx.fetch 可访问的主机，支持 *.example.com
contributes:
  tools:
    - name: count           # 注册为 plugin.word-count.count，能力 id 同名
      description: 统计一个文件
      entry: tools/count.ts # default export: { execute(args, ctx) }
      input: { type: object, properties: { path: { type: string } }, required: [path] }
      timeoutMs: 10000
  skills: [skills/counting] # 目录，里面有 SKILL.md
  mcp: []                   # McpServerSchema，name 会被加上 <插件名>- 前缀
  ui: [{ id: panel, title: 字数统计, entry: ui/panel.html }]
```

- API 版本：`api` 只写主版本。宿主支持的主版本列表在 `PLUGIN_API_VERSIONS`；不支持的主版本安装失败。
  弃用的字段登记在 `DEPRECATIONS`（字段、自哪个版本弃用、哪个版本移除），加载时命中就打一条 warn（AC-2）。
- **进程内插件**：官方内置能力用 `definePlugin({ name, tools, skills })` 在进程内注册，不进沙箱（它们本来就是 domi 的代码）。
  M6-001 AC-3 的两个「改写为插件形态」：官方 Skill（skill 型）与 memory.search（tool 型）。

### SPEC-M6-002 · 安装与权限快照

- `domi plugin install <目录>`：校验 manifest → 逐条列出权限 → 交互确认（非交互直接失败）→
  复制到 `~/.domi/plugins/<name>/` → 在 `~/.domi/plugins/installed.json` 记下 `{name, version, manifestSha256, granted}`。
- 加载时比对 manifest 的 sha256：不一致 = 被改过 → 停用并提示重新安装（比 AC-4 的「重启前不生效」更严：重启后也不生效）。
- 运行时的每次宿主调用都按 `granted` 核对。越权：拒绝，并落 `permission{capabilityId:'plugin.<name>.read|write|net', decision:'deny', source:'default', matchedRule:'plugin-manifest'}`。

### SPEC-M6-003 · 沙箱

- 每次工具调用一个子进程：`bwrap`（Linux）或 `sandbox-exec`（macOS）包着 `bun <runner>`。
  沙箱里只有：bun 可执行文件、运行时库、插件目录（只读）、runner 脚本（只读）、一个空的 /tmp。**没有网络、没有用户文件、没有环境变量**。
- runner 与宿主之间是 stdio 上的 JSON 行：runner 发 `call`（readFile / writeFile / fetch / log）与最后的 `result`，宿主回 `reply`。
- 超时（默认 30 秒，manifest 可调小不可调大于 120 秒）：杀进程组，确认进程已回收后返回失败（AC-3）。
- 子进程异常退出、输出不是协议、runner 报错：工具结果失败，并落 `plugin.error{plugin, tool, message}`（AC-2）。
- 都没有时：`plugins.allowUnsandboxed: false`（默认）→ 带代码的插件不加载，skill / mcp / ui 照常。

### SPEC-M6-004 · 示例、脚手架与文档

- `plugins/word-count`（tool 型）、`plugins/git-workflow`（skill 型）、`plugins/mcp-filesystem`（MCP 包装型，包官方的 `@modelcontextprotocol/server-filesystem`，只开放工作目录下的 `docs/`）。
- `domi plugin scaffold <tool|skill|mcp> [目录]`：生成 manifest、入口、README 与一个自带假 ctx 的 `bun test` 用例。
- `docs/site/` 四篇；代码块标 ```ts run 的会被 `scripts/test-docs-snippets.ts` 抽出来执行。

### SPEC-M6-005 · L2

- 一题一个目录：`eval/l2/tasks/<id>/task.yaml`（prompt、超时、允许的能力）+ `workspace/`（初始文件）+ `check.ts`（在工作区里跑，退出码 0 = 通过）。
- 每题复制到一个新的临时目录跑（AC-2），用独立的临时事件库。
- 报告：每题 pass/fail、token、金额、耗时；三次重复给出通过率的 min–max 区间，宽度 > 20% 标「判别力不足」（AC-5）；
  失败题的会话导出成 L1 fixture 格式（AC-6）。
- `domi eval l2 [--repeat N] [--only id]`，不进 `pnpm check`；`scripts/check-ci-no-l2.ts` 扫 CI 配置与 package.json（AC-4）。

## 4. 取舍记录

- **取舍-1 · 宿主代理 I/O，而不是把用户目录绑进沙箱**：绑进去的话越权访问只会表现为 ENOENT，
  宿主不知道发生过，AC-3 要的「产生事件」就做不到；代价是插件不能用 node:fs，只能用 `ctx`。
- **取舍-2 · 没有沙箱时默认不跑，而不是退化成「JS 层锁一锁」**：Bun 没有权限模型，JS 层的封锁（删全局、拦 import）
  都有已知绕法，给人一种「有隔离」的错觉比没有更糟。
- **取舍-3 · 每次调用一个进程**：冷启动 ~50ms，换来调用之间零状态残留、超时就是杀进程。等到有插件真的在乎这 50ms 再做进程池。
