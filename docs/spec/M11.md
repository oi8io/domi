## 2. 取舍记录（本文档最有价值的部分）

### SPEC-M11-000 · Web 测试沿用 bun:test + SSR 静态渲染，不引 vitest/jsdom

- **候选 A**：加 `vitest` + `@testing-library/react` + `jsdom`，像 PRD 原设想那样测真实 DOM 滚动
- **候选 B**：沿用 M10 已建的 `apps/web/test/`（`bun:test` + `react-dom/server` 的 `renderToStaticMarkup`）
- **选 B**。理由：基建 M10 已经建好（8 个 spec，根 `pnpm test` 跑 `bun test`），再叠一套 vitest 是重复基建；SSR 渲染恰好适合本册大部分断言——Markdown 样例输出 HTML、展开后完整 JSON 出现、浮条「N 条新消息」存在性，全是 HTML 字符串断言。
- **代价（诚实记录）**：`renderToStaticMarkup` 不执行 `useEffect`，**真实滚动行为（初始 scrollTop=底、点击浮条回底）SSR 测不到**。对策：
  1. 距底判定抽成纯函数 `shouldStickToBottom(distanceFromBottom)`（bun:test 直接测）；
  2. 初始贴底 / 浮条点击这类交互，进 DoD 用户手测清单（M10 一贯做法：Web 行为类验收靠用户手测）。
- **反悔成本**：低。将来真要测交互再加 jsdom。
- **触发重新决策的条件**：001/002 的滚动逻辑纯函数覆盖不住、要断言「切换会话强制贴底」这类时序行为时。

### SPEC-M11-001 · 滚动态放组件局部，不入 client-core store

- **候选 A**：跟随态（跟随/上翻/未读数）写进 client-core 的 SessionStore atom
- **候选 B**：状态留在 `SessionView` 的 `useRef` + `useState` 局部
- **选 B**。理由：PRD-001 AC-3 明文「滚动状态不入 store」；它是纯展示态，TUI 的 `follow` 也是组件局部（viewport.ts）。跨端一致。
- **反悔成本**：极低。
- **触发重新决策的条件**：将来要做「其它端打开同一会话时看到你停在第 N 条」这类跨端状态，再上 store。

### SPEC-M11-002 · Markdown 用 react-markdown，不自写渲染器

- **候选 A**：自写一个「够展示」的极简 Markdown 渲染（正则切代码块/列表）
- **候选 B**：`react-markdown` + `remark-gfm`（表格）
- **选 B**。理由：§6 引用优先——这是「可直接引用的真库」，自写正则解析器必然在边界 case（嵌套列表、表格、代码块里出现 ``` ）上漏；react-markdown **默认不渲染原始 HTML**（`rehype-raw` 不加就是安全的），INV-06 天然满足。
- **不做**：代码块语法高亮（不引 highlight.js / shiki，AC-3 只要可复制）；TUI 不渲染（用户拍板）。
- **反悔成本**：中。换掉要改 `Transcript` 里的一个 `<Markdown>` 组件，但它是叶子。
- **触发重新决策的条件**：bundle 体积敏感（desktop 壳加载慢）或渲染性能不达标（长会话 >1 万 token）。

### SPEC-M11-003 · 完整原文走投影新字段 `detail`，不改事件

- 现状：`tool.call`/`tool.result` 事件里有完整 `args`/`payload`，但投影层（`store.ts`）只留 80 字 `summary`。
- **选**：`TranscriptItem` 加可选字段 `detail?: string`（`JSON.stringify(ev.args)` / `JSON.stringify(ev.payload)`），展开时渲染它。
- **为什么不改事件**：INV-01 事件只增不改；这是纯投影，回放时从事件现算（INV-13 不新增埋点）。老会话历史事件里本来就有 args/payload，detail 自动有值，不需要迁移。
- **反悔成本**：低。
- **触发重新决策的条件**：单事件 payload 巨大（>1MB）撑爆 atom——那时改成「展开时再按 seq 拉事件原文」，但本轮不做。

### SPEC-M11-004 · 审核档位键：新键 `permissions.review`，不扩 plan/act

- 现状：`permissions.rules`（三态）；plan/act 是**会话级运行值**（`status.metrics.mode`），不是配置。
- **选**：新配置键 `permissions.review: 'always-ask' | 'on-demand' | 'allow-all'`，默认 `'on-demand'`。
- **理由**：plan/act 回答「这个会话现在只读还是执行」；review 档位回答「没规则的能力默认怎么办」。混进一个键会让两个维度纠缠。默认 `on-demand` = 现状 fail-closed 行为（显式 allow 放行、ask/危险问、无规则拒），升级零风险（INV-07）。
- **反悔成本**：低（一个 schema 字段 + 引擎一个函数）。
- **触发重新决策的条件**：用户用下来发现「档位」和「plan/act」在界面上是一个旋钮的两个维度，再合并。

### SPEC-M11-005 · 危险清单是代码常量，不进配置

- 用户拍板「先内置固定」。落在 `packages/capability/src/dangerous.ts`：`DANGEROUS_CAPABILITIES: ReadonlySet<string>` + 前缀规则（`mcp.` / `plugin.` 前缀）。
- **为什么是常量不是配置**：INV-03 的硬边界是「危险能力任何档位都不能免确认」——写成配置就可能被一条 YAML 关掉；常量 + 单测锁定，未来想放宽必须改代码并过测试。
- 初始清单（实现时按真实能力 id 核对，§5 列）。
- **反悔成本**：低。
- **触发重新决策的条件**：用户真的要自己加/减危险项（PRD 明说本轮不做，再议）。

### SPEC-M11-006 · 「始终允许」指纹 = argv[0] + argv[1]（首词）

- 现状 `grantable()` 把 `shell.exec` / `mcp.*` / `plugin.*` 全否了。5.2 要给 shell 开一个**受限**口子。
- **指纹定义**：对 `shell.exec`，把命令行拆成 argv（按词），fingerprint = `argv[0] + ' ' + argv[1]`（如 `git status`、`git diff`）；无 argv[1] 则指纹只有 `argv[0]`（裸 `git` 太宽——规则：**必须有首词才算可 grant**）。
- **危险词拒绝**：argv 任一词命中危险词表（`rm`/`delete`/`drop`/`mkfs`/`sudo`/`mv`/`cp` 覆盖语义……实现时定）→ 不提供「始终允许」（确认框 `grantable=false`）。
- **为什么不按整条命令**：用户拍板「可执行文件 + 参数首词/前缀够用」；整条命令太脆（多一个空格就失配），只按 argv[0] 太宽（`git` 放行 = `git push --force` 也放行），首词是平衡点。
- **反悔成本**：中（指纹函数在 capability，有单测）。
- **触发重新决策的条件**：用户实测发现 `git status` 和 `git log` 被当成两个指纹太烦，或 `npm run build` 这种带子命令的经常误配。

### SPEC-M11-007 · desktop 自启：与 ADR-021 冲突，本轮不动壳

- 现状：`apps/desktop` README 引 **ADR-021「桌面端不自己拉起 domid，先在终端跑一次 domi」**；本机无 Rust 工具链（README 明说 TASK-M5-008 未验证）。PRD-M11-006 拍板三端自启。
- **取舍**：PRD 更新（2026-09-21）推翻了 ADR-021 的旧决定，但**本轮不改 Rust 壳**（本机改不了、构建不了、验证不了——改了就是 INV-07 裸奔）。任务文件记 blocked，待有 Rust 环境或壳重构时再做；Web 侧本轮只做「连不上 daemon 时的清晰指引」。
- **反悔成本**：——（留白，见 §6）。
- **触发重新决策的条件**：装了 Rust / desktop 壳重新设计时。

## 3. 接口契约

### 3.1 滚动（SessionView，Web 局部状态）

```ts
// 距底判定纯函数（SPEC-M11-000）：bun:test 直接测，组件里只调它
export function shouldStickToBottom(distanceFromBottomPx: number): boolean
//   distanceFromBottomPx = scrollHeight - scrollTop - clientHeight
//   < NEAR_BOTTOM_PX(160) → true（沿用现状阈值）

// 跟随态：
// - following=true：新内容（距底<160）自动贴底
// - following=false（用户上翻离开底部）：新内容不贴底，未读数 +1，底部浮条「N 条新消息」
// - 点击浮条 → 回底、清未读、恢复 following=true
// 会话切换（sessionId 变）→ 强制贴底一次（following=true，清未读）
```

纯 React `useState`/`useRef`。真实滚动交互（useEffect 时序、点击回底）进 DoD 手测；纯函数与浮条渲染用 SSR 断言。

### 3.2 Markdown（Web 新组件）

```tsx
// apps/web/src/Markdown.tsx —— 唯一渲染入口
// props: { text: string }
// - react-markdown + remark-gfm；不加 rehype-raw（不渲染 HTML，INV-06）
// - 渲染抛错/异常 → catch 后退回 <div className={TEXT}>{text}</div>（AC-2 降级）
// assistant 文本走它；reason 折叠摘要、user 输入保持现状纯文本（AC-5）
```

依赖新增：`react-markdown`、`remark-gfm`（运行依赖；**不加**测试框架——沿用 M10 的 bun:test SSR 基建）。

### 3.3 投影扩展（client-core，纯展示）

```ts
export interface TranscriptItem {
  // …既有字段不变
  /** 展开后的完整原文：tool.call=JSON(args)，tool.result=JSON(payload)。纯投影，回放现算 */
  detail?: string
}
// store.ts applyEvent：tool.call → push({ …, detail: JSON.stringify(ev.args) })
//                   tool.result → push({ …, detail: JSON.stringify(ev.payload) })
```

### 3.4 危险能力常量（capability）

```ts
// packages/capability/src/dangerous.ts
export type ReviewMode = 'always-ask' | 'on-demand' | 'allow-all'
/** 任何档位都不能自动放行（AC-2/AC-3）。实现时按下述真实 id 核对落表 */
export const DANGEROUS_EXACT: ReadonlySet<string>
export const DANGEROUS_PREFIX: readonly string[] // mcp. / plugin. 前缀
export function isDangerous(capabilityId: string): boolean
/** shell.exec 的命令指纹（5.2）：argv[0] + ' ' + argv[1]；危险词命中返回 null（不可 grant） */
export function commandFingerprint(argv: readonly string[]): string | null
```

### 3.5 引擎扩展（capability/permission.ts）

```ts
export interface PermissionConfig {
  // …既有不变
  /** 会话级审核档位（SPEC-M11-004）：每次检查现取 */
  reviewMode?: () => ReviewMode
}
// check() 新语义（on-demand = 现状，回归基准）：
//   1. scope / plan 检查不变
//   2. isDangerous(id)：任何规则结论都收紧到 ask（有人则问，无人则 deny）——AC-2
//   3. 无规则时：
//        always-ask → ask（有人问，无人 deny）
//        on-demand  → deny（现状 fail-closed）
//        allow-all  → allow（危险能力已在 2 拦下）
//   4. 规则 allow 且非危险：按档位外的现状放行
```

### 3.6 配置 schema（config/schema.ts）

```ts
permissions: z.object({
  rules: z.array(PermissionRuleSchema).default([]),
  // SPEC-M11-004：默认 on-demand = 现状行为
  review: z.enum(['always-ask', 'on-demand', 'allow-all']).default('on-demand'),
}).default({ rules: [], review: 'on-demand' }),
```

### 3.7 「始终允许」指纹授权（5.2）

- 确认框 `grantable` 判定扩展：非危险能力 +（路径类现状不变；shell.exec 现在 `commandFingerprint` 非 null 即可 grantable）。
- `SessionGrant` 新形态：`{ capability, scope?, fingerprint? }`；`covers()` 增加 fingerprint 精确匹配分支。
- 授权事件记录 fingerprint（审计可解释，AC-2）。只活在本会话内存（AC-4，与 M8-016 同生命周期）。

## 4. 数据契约

- **不改协议**：本册全部是投影/引擎/配置/渲染，`protocol.schema.json` 不变（INV-01 快照测试自然过）。
- 新配置键 `permissions.review`：老配置缺省 = `on-demand`，无需迁移。
- 指纹授权是会话内存态（与 session-grant 同），不落盘、不进事件流 schema；授权**事件**里带上 fingerprint 字段值（permission 事件的 payload 是自由 JSON，不加新事件类型）。

## 6. 明确留白（故意不设计）

1. **desktop 自启壳改造**：与 ADR-021 冲突 + 本机无 Rust。PRD 拍板方向已知（三端自启），实现等 Rust 环境/壳重构，任务 blocked 留痕。
2. **Web 真自启**：浏览器无 Node 进程，spawn 不了 daemon。本轮只把「连不上」变成有操作指引的提示；真自启依赖 desktop 壳（留白 1）。
3. **TUI Markdown**：用户拍板只做 Web。
4. **TUI 中断（007）**：等终止方案 S1–S4，本册不写。
5. **危险词表的完整清单**：`commandFingerprint` 的危险词集合实现时定，单测锁定，这里不枚举到字。
6. **代码块语法高亮**：本轮不做。
