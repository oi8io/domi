## 2. 取舍记录

- **取舍-1 · 会话 / 任务是 kind，不是两张表**。两者的事件流、订阅、渲染完全相同，差别只在工作目录、上下文层与权限范围。
  用 `session.kind` 事件（首条之后立即落）+ sessions 表的 `kind` `project_id` 列。反悔成本低：合并 kind 只需忽略一列。
  重新决策的条件：两者的界面分叉到一半以上的组件不共用。
- **取舍-2 · 项目按路径归属，不按 git 根**。用户可能想把 monorepo 的子目录当项目。归属规则：任务的 cwd 与某个项目路径相同或在其下 → 最深的那个；
  都不是 → 用 cwd 自动建项目（名字 = 目录名）。重新决策的条件：出现大量「同一仓库被拆成多个自动项目」的反馈。
- **取舍-3 · 老会话的迁移**：`cwd` 是 git 仓库（向上找 `.git`）或含 `AGENT.md` / `AGENTS.md` → `task` + 自动项目（取仓库根）；其余 → `chat`，但 cwd 不改
  （事件里记录的是历史事实，不能假装它在沙盒里跑过）。迁移只写表，不追加事件；首次打开老会话时补一条 `session.kind{migrated:true}`。
- **取舍-4 · 自由会话的沙盒是「范围」不是「chroot」**。复用子 agent 与计划模式的 `scope` 机制：路径类能力的参数在沙盒内 → 走正常规则；
  在沙盒外 → 强制 `ask`（不是 deny，用户可以一次性放行），`source:'scope'`、`matchedRule:'chat-sandbox'`。`shell.exec` 在会话里一律 `ask`，
  因为命令能触达的路径无法静态判断。反悔成本低。
- **取舍-5 · 执行形态由模型建议、策略裁决**。`plan.submit` 增加 `shape: single | dag`（模型给）；运行时再按「步骤数 ≥ 3 且存在可并行步骤」校正。
  审阅策略 auto 的阈值：`shape=dag` 或计划里声明的写文件数 > 5 → 要人审。模型可以撒谎说 single，代价是少了并行，不影响安全（写操作仍过权限）。
- **取舍-6 · 自动隔离的判据**：auto 时 git 仓库 且（`git status --porcelain` 非空 或 `shape=dag` 或 由定时触发）→ 隔离。
  理由：工作区干净时直接改 + 步级快照足够安全，且用户能在自己的编辑器里实时看到改动；脏工作区、并行节点、无人值守才是会踩的场景。
- **取舍-7 · 调度器在 daemon 进程内**，不用系统 cron / launchd：跨平台一致、能直接建会话、测试能注入时钟。
  cron 解析自己写（5 段、`*` `,` `-` `/`、月份与星期名；不支持 `L` `W` `#` 与秒），约 150 行，抄 cron-parser 的匹配算法。
  时区用 `Intl.DateTimeFormat` 换算，不引依赖。补跑只补一次（取最近的一个错过时点）。
- **取舍-8 · 已读位置进 daemon**，不放浏览器：用户明确要跨端一致；按「会话 → 最后已读 seq」一张表，不分客户端（单用户）。
  `unread = lastSeq > readSeq 且 最后一条不是用户输入`。当前被任一客户端订阅并处于前台的会话，新事件到达即推进已读。
- **取舍-9 · 配置回写用 `yaml`（eemeli/yaml 2.x）的 Document API**：只改 patch 里的节点，注释与顺序保留。现在读配置用的是 Bun 内置 YAML，它不保留注释；
  自己写行级补丁器要处理流式写法、锚点、多行字符串，出错就是毁用户配置。这是 M8 唯一的后端新依赖，记在 ADR-027。
  反悔条件：Bun 内置 YAML 提供保留注释的写回。
  白名单是**显式列表**（见 SPEC-M8-011），不是黑名单——新加的配置项默认不可从 Web 改。
- **取舍-10 · 附件不进事件流正文**：事件只记 `{id, name, mime, size, sha256}`，内容在 `~/.domi/attachments/<会话>/<id>`；
  回放时附件缺失 → 以「附件已不存在」文本占位，不让回放失败。
- **取舍-11 · 前端路由用 hash**（原型就是这么做的，桌面端 Tauri 也不需要服务端配合），不引路由库。
- **取舍-12 · 轨迹时间线在 client-core 投影**：它是「事件 → 区间」的纯函数，与状态栏数字不同，不代表 runtime 的判断，放 client-core 让 TUI 以后能复用。

### SPEC-M8-003 · 项目

```ts
// protocol
const ProjectSchema = z.object({
  id: z.string(), name: z.string(), path: z.string(),
  createdAt: z.number().int(), archived: z.boolean(),
  taskCount: z.number().int(), lastActivity: z.number().int().nullable(),
  settings: z.object({
    isolation: z.enum(['auto', 'always', 'never']).default('auto'),
    planReview: z.enum(['auto', 'always', 'never']).default('auto'),
  }),
})
'project.list'    { includeArchived? }            → { projects }
'project.create'  { path, name? }                 → { project }     // PATH_NOT_FOUND / NOT_A_DIRECTORY
'project.update'  { id, name?, settings? }        → { project }
'project.archive' { id, archived: boolean }       → { ok: true }
```

- 表：`projects(id TEXT PK, name, path UNIQUE, created_at, archived INTEGER, settings TEXT JSON)`；`sessions` 加 `kind TEXT`、`project_id TEXT NULL`。
- 路径规范化：`realpath` + 去尾斜杠；macOS 大小写不敏感卷上按 `realpath` 的结果比较（不自己 lower-case）。
- 归属（取舍-2）在 `ProjectService.resolve(cwd)`；新任务与迁移共用。落 `project.assign {projectId, auto}` 事件到任务会话里（轨迹里能看到它属于哪个项目、是不是自动建的）。
- 远程安全：`project.create` 只做存在性检查与登记，不读目录内容；信任询问（M7-002）仍在第一个任务开始时发生。

### SPEC-M8-004 · 会话与任务

- `session.create { kind?: 'chat'|'task', projectId?, cwd?, goal? }`：`kind` 缺省 → 有 `projectId` 或 `cwd` 为 task，否则 chat（旧客户端行为不变：只给 cwd 的仍是任务）。
- chat：cwd = `~/.domi/scratch/<id>`（创建）；`DomiSession` 选项 `projectContext: false` → 跳过 `project.rules` 层、`SkillOverlay`、信任询问；
  `scope` = 沙盒范围（取舍-4）。
- `session.list` 的 `SessionSummary` 追加 `kind` `projectId` `cwd` `busy` `unread` `lastActivity`（全部 optional，旧客户端忽略）。
- `session.toTask { sessionId, projectId, goal }` → 新任务首条输入 = goal + `refs:[{sessionId, fromSeq:1, toSeq:MAX}]` → `{ sessionId }`。
- `session.rename { sessionId, title }` → 只改 sessions 表的 `title` 列（与软删除标记同类的元数据，不是会话内容，不落事件）。
- 回收站：沿用 `includeDeleted` 与 `session.restore`。

### SPEC-M8-005 · 目标驱动的任务

- `task.create { projectId, goal, attachments?, schedule? }`：
  1. `ProjectService` 取项目 → 隔离决策（SPEC-M8-006）→ 建 task 会话（`mode: plan`）
  2. 首条输入 = goal；模型在计划模式下读代码、`plan.submit{plan, steps, shape}`
  3. 审阅策略：需要人审 → 走 M7-005 的询问；不需要 → 直接落 `plan.decided{approved:true, source:'policy', shape}`
  4. `shape=dag` → 生成 DAG（M7-005 AC-3），`TaskService.start` 运行，节点会话挂在该任务下；`single` → 同一会话切回 act 继续
  → 返回 `{ sessionId, runId? }`
- `task.list` 统一返回 `{ id, kind: 'session'|'dag', title, projectId, status, startedAt, endedAt?, scheduleId? }`；DAG 运行详情仍用 `task.get`。
- YAML 入口：任务页「高级：粘贴 YAML」折叠区，调用原 `task.start`。
- 小任务不强制先规划：goal 少于 40 字且项目 `planReview != always` 时，plan 模式的第一轮若模型直接给出 `shape:single` 且没有写计划，按 single 处理（避免「改个错别字也要审计划」）。

### SPEC-M8-007 · 定时任务

```ts
'schedule.list'   {}                                        → { schedules: [{ id, projectId, goal, cron, tz, paused, nextRun, lastRun? }] }
'schedule.create' { projectId, goal, cron, tz? }            → { schedule }   // INVALID_CRON { field, message }
'schedule.update' { id, goal?, cron?, tz?, paused? }        → { schedule }
'schedule.delete' { id }                                    → { ok: true }
'schedule.runNow' { id }                                    → { sessionId }
'schedule.runs'   { id, limit? }                            → { runs: [{ sessionId, due, firedAt, late, skipped?, status }] }
```

- 表：`schedules(id, project_id, goal, cron, tz, paused, created_at, last_due)`、`schedule_runs(schedule_id, due, fired_at, session_id, late, skipped)`。
- `Scheduler`（注入 `now()` 与 `setTimer`）：启动时对每个计划算「上次应触发 ≤ now 且 > last_due」→ 有则补跑一次（`late:true`）；之后按最近的 nextRun 设一个定时器（上限 60s 重算，防系统休眠漂移）。
- 触发 = `task.create{trigger:'schedule'}`；同一计划上一个任务 busy → 记 `skipped:true`，不建会话。
- 界面：任务页「定时」分区（列表 + 新建表单：项目、目标、cron、时区、下一次运行预览）；侧栏「定时任务」→ `#/tasks/new?schedule=1`。

### SPEC-M8-010 · Composer

- 模型能力：`capability.vision` 为 false 时图片附件 → 提交前拒绝 `UNSUPPORTED_ATTACHMENT`，界面提示换模型。
- `skill.list {}` → `{ skills: [{name, description, source}] }`；选中的 Skill 在这一轮以 `skill.load` 同样的内容注入（记 `user.input.skills`，buildContext 渲染）。
- `model.list {}` → `{ models: [{provider, name, label, capabilities}], current }`：来自 SPEC-M8-011 的 providers 配置 + 内置价目表里的名字。
- 键盘：Enter 发送（IME 组合中不发送，`isComposing`）；`@` / `/` 在行首或空格后触发弹层。

### SPEC-M8-012 · 设置页
