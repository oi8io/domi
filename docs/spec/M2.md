## 2. 取舍记录

### 取舍-1 · fixture 落盘用 JSONL 还是单文件 JSON（回写 PRD-M2-008 AC-1）

- 候选 A：**事件流 JSONL**（PRD 原文），一行一条事件
- 候选 B：**单文件 JSON**，`{ version, sessionId, inputs, turns, toolResults, expectedCalls }`
- **选 B**。理由：JSONL 的好处是**可流式追加**——但 fixture 是冻结的测试资产，录完就不再长了，
  这个好处在这里根本不发生。而 B 换来的是真金白银的东西：
  1. **版本号有地方放**。JSONL 没有文件级头部，`version: 1` 只能塞进第一行伪装成事件，
     读的时候要先猜「这行是头还是事件」。B 里 `parse()` 一进门就能拒绝不认识的版本，
     而不是读到一半才发现格式对不上（这条已有测试）。
  2. **fixture 不等于事件流**。它是事件流的**投影**：按轮切好的模型输出 + 工具输入输出对。
     照抄 JSONL 会让人误以为可以把 `events.db` 导出的原始流直接扔进去回放，
     实际上 `record()` 做了切分。格式上就区分开，比写一行注释管用。
- **触发重新决策的条件**：单个 fixture 超过 ~5MB（大到该流式读），或需要把多条会话拼进一个文件。
- 影响：`fixtures/sessions/*.json`（PRD 验收方式一并回写）。

### 取舍-2 · AC-4 的「跳转到轨迹面板」怎么算验收（回写 PRD-M2-008 AC-4）

- AC-4 原文要求差异报告「可直接跳转到轨迹面板的对应节点（PRD-M2-005）」。
  **轨迹面板还没做**，这一半现在无法验收。
- **做法**：现在交付锚点而不是跳转——`Divergence` 带 `seq`，`formatResult()` 打印「跳转：轨迹面板 seq N」。
  `seq` 是事件流里的唯一定位符（INV-01），面板做出来的那天，跳转就是拿它查一次表。
- **不做的事**：不为「将来能跳」提前造一个假的面板协议。
- **触发重新决策的条件**：PRD-M2-005 开工时，把这条 AC 的后半段并进 M2-005 的验收一起做。
- 影响：AC-4 拆成两半验收，已回写 PRD v1.2.2。

### 取舍-3 · `domi eval` 怎么接线，才不破坏 AC-5

- AC-5 要求「删掉 `packages/eval` 后 kernel 与 store 的测试仍全绿」，但 AC-1/AC-2 又要求
  命令敲出来是 `domi eval record` —— 命令面在 `packages/cli`。这两条互相拉扯。
- 候选 A：`packages/cli` 静态 `import '@domi/eval'` —— 最省事，但删掉 eval 会让**整个 `domi` 起不来**，
  AC-5 只剩字面意义（kernel/store 的测试确实还能跑，但产品死了）
- 候选 B：命令实现留在 `packages/eval/src/cli.ts`，`packages/cli` 只做一次
  **动态 `import('@domi/eval')` + try/catch** —— 删掉之后 `domi eval` 退化成一句
  「评估层不可用」，其它命令一概不受影响
- **选 B**，并由 `scripts/check-eval-isolation.ts` 把它钉死：
  核心包（kernel/store/model/protocol/... 十一个）**一律不许提** `@domi/eval`；
  `packages/cli` 是唯一接线点，且**静态 import 会红**。守卫本身有三个红 fixture 证明它会红。
- **触发重新决策的条件**：需要把 eval 打进单文件二进制（动态 import 的字符串要让打包器看得见）。

## 3. 模块边界

```
packages/eval/
  src/normalize.ts  纯函数，零依赖 —— 抹平时间戳/路径/UUID/SHA/耗时（AC-6）
  src/fixture.ts    事件流 → fixture 的投影（AC-1）。只依赖 @domi/protocol
  src/replay.ts     MemorySink + ReplayProvider + ReplayTools，驱动**真实 kernel**（AC-2）
  src/cli.ts        domi eval record / run。唯一碰 @domi/store 与文件系统的文件
```

**方向是单向的**：eval → kernel / store，永远没有反向箭头。这就是 AC-5 与 INV-13 的同一件事：
评估不许让内核为它改形状。

## 4. 不做什么

- **不做 L2**（用真实模型跑一遍打分）——那是 PRD-M6-005，要花钱、要联网，进不了 CI（INV-08）。
- **不做「回放时重新调用工具」**：fixture 里没录到的调用返回 `not_recorded` 而**不是**静默成功。
  静默成功会让一个已经跑偏的回放显示为绿，那比没有评估更糟。
- **不做快照式断言**（把整条事件流 diff 一遍）：那种断言一改提示词就全红，没人会去看。
  判据只有一条：**工具调用序列（名称 + 归一化参数）**。

## 5. SPEC-M2-002 · 确定性上下文清理

### 取舍-4 · 清理是「删事件」还是「缩投影」

- 候选 A：把可清理的事件从上下文里**去掉**
- 候选 B：**每条事件都还在，只是文本变短**，并且留下可读的标记
  （`[已去重：…与第 N 条相同]` / `[…已截断 N 字符…]` / `[错误已解决：…]` / `[…省略 N 帧…]`）
- **选 B**。理由：A 省得更多，但代价是**排查时人会以为那一步压根没发生**。
  「这里本来有东西」必须看得见——这和 INV-01 对事件流的要求是同一条原则往上一层的延伸。
  实测十条 fixture 平均削减 **59.8%**，B 的这点额外开销根本不是瓶颈。
- **触发重新决策的条件**：标记本身占比超过削减量的 10%。

### 取舍-5 · 引用关系：推断还是显式标注

- 候选 A：从后续事件里**推断**哪些内容还在被引用（子串匹配、相似度）
- 候选 B：**只认显式标注**（事件上的 `refs: number[]`），没标注就按规则正常清理
- **选 B**。理由：这里的代价是**不对称**的——漏判一次等于把别人还要用的内容删了，
  多保留一条只是少省一点 token。在代价不对称的地方用启发式，是拿正确性换数字。
  AC-2 原文「引用关系由 fixture 显式标注」说的也正是这件事。
  兜底的是取舍-4：**没有任何规则会整条删除**，最后一次结果永远原样保留。
- **触发重新决策的条件**：真实会话里发现 `refs` 长期为空，说明 kernel 侧没写标注，
  那要补的是 kernel 的标注，不是这里的推断。

### 取舍-6 · 'clean' 策略怎么接进 kernel

- kernel 已有 `registerContextStrategy` 注册点（ADR-005）。`packages/memory` 注册一个 `'clean'`，
  内部**清理完再调 `buildContext(..., 'full')`**——不自己拼一套 messages。
- 为什么不自己拼：上下文的**形状**（哪些事件进、role 怎么分、tool 消息怎么配对）是 kernel 的知识。
  在这里复制一份，两边会慢慢长歪，而且这种走偏在测试里很难看见。
- 结果是 PRD-M2-003 AC-6「切换压缩策略实现，`packages/kernel` diff 为 0」**当场成立**：
  加这个策略，kernel 一行没改。测试里直接断言 `build-context.ts` 里搜不到 `cleanup` / `clean` / `@domi/memory`。
- 注册发生在 `packages/runtime`（组合根），不是 apps，也不是 kernel。

### 取舍-7 · schemaVersion 3 → 4

新增 `ctx.cleanup` 事件类型，按 SPEC-M0-004 的规矩：版本 +1、补 `fixtures/events/legacy-v4.jsonl`、
重新生成 `packages/protocol/.api.md`。**没有修改任何既有字段**，所以旧事件照常解析。

### 不做什么（M2-002 这一层）

- **不做 LLM 压缩**：那是 PRD-M2-003，判据完全不同（AC-5 的重放等价性）。
- **不做自动触发**：什么时候清理由调用方决定。阈值触发是 M2-003 AC-1 的事。
- **不把 59.8% 当承诺**：那是在**专门造出四种臃肿形状**的合成 fixture 上测的。
  真实会话里这个数只会更低。AC-2 的门槛是 15%，留的就是这个余量。

## 6. SPEC-M2-005 · 轨迹显示

### 取舍-8 · AC-4 的解耦守卫与 M2-008 AC-5 合并（回写 PRD 验收方式）

PRD 给 M2-005 AC-4 写的是 `scripts/check-trace-decoupling.sh`，给 M2-008 AC-5 写的是
`scripts/check-eval-isolation.ts`。两条 AC 是**同一句话的两次出现**：
「删掉这个包之后，kernel 与 store 的测试仍全绿」。

- **一份实现守两条**（`scripts/check-eval-isolation.ts`，内部是一张旁观者表）。
- 理由：同一条规则写两遍，迟早只有一遍是对的——而且错的那一遍会一直绿着。
- 顺带解决了一个真问题：守卫自己的红 fixture 测试住在旁观者包里，
  那些文件里必然出现违规写法。表驱动之后可以统一豁免「旁观者之间互相认识」，
  两份独立脚本就得各写一遍这个豁免。
- **触发重新决策的条件**：出现第三个旁观者且它的规则与前两个不同（比如允许被核心引用）。

### 取舍-9 · AC-5 用 Playwright 还是 HTMLRewriter（回写 PRD 验收方式）

- PRD 原文：Playwright 载入导出文件、断言无外部请求、断言节点可展开。
- **实际做法：导出的 HTML 里一行 JavaScript 都没有**，折叠展开用原生 `<details>/<summary>`。
- 于是「无外部请求」不再是一条需要跑浏览器去观察的**运行时**性质，
  而是文档结构上不可能违反的性质：没有 `script`/`link`/`img`，就没有任何可以发出去的请求。
  「节点可展开」同理——`<details>` 的展开是浏览器语义，不依赖任何脚本。
- 所以验收改用 **Bun 内置的 HTMLRewriter** 解析导出文件，断言这些结构事实。
  不引 Playwright 还有个附带好处：AC-5 能在 CI 里跑，不需要装浏览器。
- **触发重新决策的条件**：导出文件里开始需要 JS（比如加搜索框），
  那时「无外部请求」就重新变成运行时性质，Playwright 要补回来。

### 取舍-10 · 终端渲染在 AC-2 之外多加一道行数上限

AC-2 的阈值是 2KB。但 120 行 `(pass) case N` 只有 1.8KB，够不着阈值，
却能把一屏冲干净。所以文本渲染再加一道 40 行上限——**只会折得更多，不会折得更少**，
不违反 AC-2；HTML 导出不受影响，全文照样在文件里。

### 结构决定

- **权限决策与结果挂在工具调用底下**，不是平铺。扁平列表也能看，
  但「这次写文件是谁批准的」要靠上下扫视去对——而那恰恰是最需要一眼看清的关系。
- **连续的 model.delta 合成一个「回答」节点**。不合的话轨迹会被几百个碎片淹掉。
- **未知事件照样显示**（降级成 `other` 节点并打印原文），不静默吞掉——INV-01 在展示层的延续。
- **findBySeq** 是 PRD-M2-008 AC-4 后半段的落地：回放差异报告给的是 seq，
  这里按 seq 定位节点，HTML 里每个节点带 `id="seq-N"` 锚点，可以直接 `#seq-N` 跳过去。

## 7. SPEC-M2-007 · 事件 schema 版本与迁移

### 决定-1 · 守卫用白名单，不用黑名单

`scripts/check-migrations.ts` 把每条迁移 SQL 与一张**允许的形状**表比对：
新增列 / 新增索引 / 新增表 / 新增视图 / 写 meta 默认值。不在表里就红。

黑名单（"不许出现 DROP COLUMN"）看起来更直接，但 SQL 的花样比人想得多——
`ALTER TABLE ... ALTER COLUMN ... SET DEFAULT` 不在任何人的黑名单上，却确确实实在改既有列。
测试里专门留了这一条。

这条守卫拦的是一类**不会在测试里露面**的破坏：新写的数据一切正常，
坏掉的是别人磁盘上几个月前的会话。所以它只能在合并前静态拦住。

### 决定-2 · 回滚的判据是 byte 级还原

`migrateDatabase` 先**文件级复制**一份备份，失败时把备份原样盖回去，
测试断言的是 `readFileSync(path).equals(before)`——不是「库还能打开」。

理由：**半个迁移留在库里，比迁移失败本身更难查。**
所以还专门测了两件事：那条半途成功的 ADD COLUMN 之后不存在，版本号也退回了原值
（记着一个没真正发生的迁移，下次就再也不会重跑它）。

备份用文件级复制而不是 `.dump`：后者要经过一次 SQL 往返，
而「往返里丢了什么」恰恰是最难发现的那类损坏。备份失败后**不删**——出了事要能拿着它找人看。

### 决定-3 · AC-4 的 fixture 集合自动生长

`legacy-v{n}.jsonl` 每加一个版本就自动进混合集，`schema-compat.spec.ts` 里的长度断言
跟着 `MIXED.length` 走，不再写死数字。写死的话，加了 fixture 却忘了改断言，
测试会红；改了断言却忘了加 fixture，测试照样绿——后者才是危险的那种。

## 8. SPEC-M2-006 · 注入防护

### 决定-1 · 判据放在权限层，不放在模型行为上

十六条注入载荷，每一条断言的都是**权限层拒绝**，没有一条依赖模型是否被骗到。

靠「模型没被骗到」来证明安全，等于把安全性押在一个概率上，而且每换一次模型就要重押一次。
提示词里的 guardrail 层（AC-1）当然要写，但它的作用是降低「模型自己把事情搞砸」的概率
——比如被诱导去读一个它本来有权读、但用户根本没要的文件，那种事权限层拦不住。
**它是纵深防御的最外层，不是判据。**

模型抗性那一半走 nightly eval（PRD §0.4），不进门禁。

### 决定-2 · 边界标记用私有区字符，不用 `<tool_result>`

工具结果里可以原样写出 `<tool_result>` 这六个字符，伪造边界是注入最直接的一招。
换成 U+E000 / U+E001，并在 `markToolResult` 里把内容中的同名字符剥掉，
**可区分性才不依赖内容老实**。

那 `role: 'tool'` 不是已经结构可分了吗？是，但它只在**消息层**成立：
一旦上下文被压缩、被拼进单条 user message、或者被某个 provider 的适配层摊平，
那个区分就消失了。写在内容里的标记摊平之后仍然在。

### 决定-3 · 纵深防御的第二层是路径收口

注入用例里有四条的目标是 `fs.read`——那是**被允许**的能力，权限层会放行。
拦住它们的是 `resolveWithinRoot`（PRD-M0-003 AC-5）。
两层都得过才真的读得到，这就是 INV-06 说的纵深防御，测试里逐条断言了这个分工。

## 9. SPEC-M2-003 · LLM 压缩（保边压中）

### 决定-1 · 压缩只追加一条事件，不改写任何历史

`ctx.compact` 是**又一条追加的事件**，原始事件一条没动、一个字节没改（INV-12）。
测试里的判据是逐条 sha256 相同，不是「看起来还在」。

这样一来 **AC-5 的重放等价性是免费的**：用 `full` 策略从原始事件流重放，
压缩前后深比较相等——因为压根没有东西被改掉，不需要另写一套还原逻辑。
反过来说，任何需要「还原」的压缩实现，都是已经把历史改坏了。

### 决定-2 · 策略只做投影，不调用模型

`compact` 策略从事件流里找**最后一条** `ctx.compact`，把它覆盖的区间换成摘要消息。
它自己不调模型、不做任何 IO，所以上下文拼装保持纯函数——L1 回放（M2-008）才能确定性地重放它。

「什么时候真去压」是 runtime 的事（`DomiSession.maybeAutoCompact`，AC-1 的阈值触发），
`/compact` 是同一条路径的手动入口，只有 `trigger` 字段不同——手动不是另一套实现，测试里断言了这点。

### 决定-3 · 摘要插回去时走普通的 user.input，不走特例

摘要被包装成一条 `user.input` 事件插在最前面，再交给 kernel 的 full 策略拼装。
不给它开特殊分支，是因为**特例是将来出 bug 的地方**：
拼装路径只有一条，摘要就永远不会因为「忘了同步另一条路径」而显示不出来。

摘要文本自带「这不是用户的新指令」的说明——与 M2-006 的注入防护同一条思路：
被塞进上下文的东西必须自报身份。

### 决定-4 · 阈值是 70%，不是 75%

AC-1 给的是 70–75% 的区间。取下界，因为**每次压缩都是一次真实模型调用**：
在 75% 附近抖动的会话会反复触发。70% 触发、75% 是「最晚也该压了」的上限。

### 一条容易读错的性质

短会话压了反而更大——摘要本身也要花 token。这不是 bug，而是为什么要有阈值门：
到窗口 70% 才压，那种会话不可能短。测试里专门留了这条用例并写清楚原因，
免得哪天有人看到「tokensAfter > tokensBefore」就去改压缩函数。

## 10. SPEC-M2-004 · L2 跨会话内容检索

### 取舍-11 · 只做全文，向量那一半按 ADR-010 的时点走（回写 AC-1）

AC-1 原文要「全文（FTS5）**与**语义（向量）」。这一轮只交付全文。

不是做不动，是 `docs/adr/010` 早就写明：向量方案（sqlite-vec vs 纯 FTS5/BM25）
**要等有真实语料才能选**，「生态里四种切法都有人做完且没有胜者——没有语料就选，纯属抛硬币」。
那条 ADR 把时点定在 M4（做 `PRD-M4-001` 时）。现在为了让 AC-1 字面完整而硬塞一个向量实现，
等于明知要返工还先做一遍。

**已交付的全文检索本身是完整可用的**：跨会话、中文可搜、结果可溯源、有门槛、进了 CI 基线。
向量补上之后是**并集**，不需要重做——检索接口返回的就是 `SearchHit[]`，多一路召回只是多一个来源。

**触发**：进入 M4 做 `PRD-M4-001` 时，与向量方案一起定，届时把 AC-1 的后半段补齐。

### 取舍-12 · 分词器用 trigram，并为两字词留一条 LIKE 降级

SQLite 默认的 `unicode61` 不切中文——「数据库迁移」整条被当成一个词，搜「迁移」什么都搜不到。
换 `trigram` 解决了这个，代价是**查询串至少三个字符**。

而「减号」「超时」「回滚」这类两字问法是真实存在的。所以查询不足三字时降级成 `LIKE '%q%'` 扫描。
降级路径慢，但它只在短查询上发生，而短查询本来就少。
**明确写成一条降级路径而不是"搜不到就算了"**，因为后者会让用户以为历史里没有。

### 取舍-13 · 索引随 append 增量建，且在同一个事务里

- 不做「用的时候再建」：第一次搜索要等几秒，而那正是人最没耐心的时刻。
- 放在 append 的同一个事务里：**「事件写进去了但搜不到」比「两者都没写」更难查**。
- 索引是**派生数据**：删掉 `events_fts` 重建即可，事件流才是真相（INV-01）。
  所以它跟着建库 DDL 无条件跑，不进 MIGRATIONS。

实测（`bench/episodic-10w.ts`）：10 万条事件，写入+建索引 **~700ms**，检索 **P95 8.6ms**（门槛 300ms）。

### 取舍-14 · 找不到就说找不到（AC-3）

`searchEpisodes` 在相关度不够时返回 `{found:false}`，**不返回 top-k**。

理由不是洁癖：返回一堆不相关的结果，模型会拿它们当真，然后基于一段从没发生过的"历史"往下做。
**「我什么都没找到」是一个有用的答案，「这是三条最不离谱的」不是。**

### 取舍-15 · 检索做成工具，而不是每轮自动塞

AC-2 要求「由模型决定何时调用」。这条 AC 值得展开：
自动塞的话，每一轮都要付一次检索的 token，而十轮里有九轮用不上；
更糟的是模型会把塞进来的旧对话当成当前语境。
做成工具，「要不要回忆」的判断交给模型，判断错了也留在轨迹上看得见。

工具住在 `packages/memory` 而不是 `packages/capability`——后者是**执行原语**的家，
这个工具的实质是记忆层的读接口。由 runtime（组合根）注册。

它**仍然走权限层**：历史里有用户的原话，「能不能翻旧账」应该由配置说了算，
而不是由「它是读操作」说了算。默认配置模板里给了一条 `allow-memory-search`，删掉就是不许。
