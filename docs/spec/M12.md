## 2. 取舍记录

### SPEC-M12-003 · 改名同步已工作，只清理空标题死分支

- **实测**（2026-09-23 bu 浏览器）：点标题改名 → Enter → 右上角立即更新新名；回首页侧边栏也同步。PRD 说的「改名后右上角不更新」在当前代码已不复现——M10-001 修 titleOf 时一并修好了刷新链路（onRenamed → refreshSoon → listSessions → setSessions → activeRow?.title 更新）。
- **剩余问题**：SessionTitle 里 `title === '' ? tr('common.untitled') : title`。但 daemon `listSessions` 已做空标题回退（`r.title.trim() !== '' ? r.title : r.firstInput ?? untitled`），前端拿到的 `title` 永远非空——这个三元分支是死代码。
- **选**：删死分支，直接 `{title}`（title prop 可能 undefined 时兜底空字符串）。空标题口径以 daemon 返回的 firstInput 为准（与侧边栏同源），前端不再自己判"未命名"。
- **反悔成本**：极低。

### SPEC-M12-001 · model.resolve RPC 直接删，不留兼容

- **现状**：Web ModelSwitch 有「搜索 / 手填…」→ custom 模式 → `client.resolveModel(text)` → `model.resolve` RPC（按名字归属 provider）。TUI `/model <名字>` 走 daemon 直接接收模型名。
- **选**：Web 删 custom 分支（`<input> + datalist` 整段删），只留 `<select>`；TUI `/model <名字>` 手填路径删（只开选择器）；`model.resolve` RPC 定义 + 实现 + 测试全删。
- **理由**：PRD 定案 a「两端都不要手填」；`model.resolve` 无调用方后留着是死代码。
- **反悔成本**：低。将来要加回手填就重新加 RPC。
- **清单为空时**：select disabled + CredentialNotice 引导去设置页（AC-4）。

### SPEC-M12-002 · permissions.mode 会话级，mode 字段复用

- **现状**：M11-005 实现为全局 `permissions.review`（config schema + 白名单），Web 设置页 RuntimeTab 三档下拉，TUI SettingsOverlay 三档，runtime `session.ts` `reviewMode: () => opts.config.permissions.review`。
- **改为**：
  - config 删 `permissions.review` 全局项
  - runtime session 维护会话级 `permissionsMode`（默认 `on-demand` 写代码常量），新事件 `permissions.mode.switch`（值 `always-ask | on-demand | allow-all`）
  - 写事件流（INV-01），重开会话从事件流恢复
  - Web Composer 工具栏加三档小下拉（照图 1：标题 + 描述列表式）
  - TUI `/mode` 斜杠命令 + 补全
  - Web 设置页 RuntimeTab 删三档；TUI SettingsOverlay 删三档
  - 全仓 `review` 残留清：i18n key `web.settings.review*`、`reviewMode` 变量名、TUI 命令、文档
- **档位语义**（不回退 M11-005 硬边界）：
  - `always-ask`：编辑外部文件 + 网络始终询问（危险清单判定不变）
  - `on-demand`（默认）：只对有风险的操作询问
  - `allow-all`：不受限制（危险能力仍必须确认）
- **与 M12-004 关系**：`allow-all` 档跳过确认弹框（危险能力除外）；`always-ask` 任何确认点都弹。
- **反悔成本**：中。改名面广，但都是机械替换。

### SPEC-M12-004 · plan/act 删除，确认弹框取代 elicit 表单

- **现状**：plan/act 两模式。plan 权限分支只放行只读 + `plan.submit`；`plan.submit` 走 `ctx.elicit` 表单审批。
- **改为（B 方案）**：
  - 删：权限引擎 plan 分支（`PLAN_MODE_READONLY`、`PLAN_SUBMIT_CAPABILITY`）、session mode/setMode/AUTO_PLAN_REASON、Composer ModeToggle、`mode.switch` 事件语义
  - 新流程：系统直接产出计划 → 需要确认的点整理成弹框（每题一个 tab，abcd 选项 + 自定义输入）→ 确认后执行
  - 无确认点 + 无阻止提示 → 直接执行
  - 阻止提示判定：关键词（不要/别/禁止/先别）+ 对象，有则停下来先问
  - 转长任务能力保留（plan.submit 的 asTask 语义平移）
- **确认弹框形态**：Web 端复用现有 ask/dialog 组件，多 tab 按问题数分；TUI 端逐步展开。
- **反悔成本**：高。动权限引擎 + runtime 核心循环。
