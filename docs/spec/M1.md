## 2. 取舍记录

### SPEC-M1-001 · 能力矩阵放在哪

- 候选 A：运行时探测（发一个试探请求看 provider 支不支持）—— 准，但要花钱且慢
- 候选 B：**静态声明表**，每个 provider 自报 `toolCall`/`vision`/`reasoning`/`promptCache`/`structuredOutput`
- **选 B**。理由：AC-3 要求"**在发出 HTTP 请求之前**抛错"——这直接排除了 A，探测本身就是请求
- 代价：声明会过时（provider 上线新能力而我们的表没改）。缓解：矩阵放在 provider 实现文件里紧挨着构造函数，改 provider 时一眼能看到
- **触发重新决策的条件**：出现"同一 provider 不同 model 能力不同"且差异多到静态表维护不动（典型是 OpenAI-compatible 网关后面挂几十个模型）→ 届时改为 `provider × model` 两级表，仍不探测

### SPEC-M1-002 · 重试退避的边界

- 只重试**幂等失败**：429、5xx、网络超时。4xx（除 429）不重试——那是请求本身有问题，重试三次只是把同一个错误犯三遍
- 退避：`base * 2^n + jitter`，默认 base=500ms、3 次。**jitter 必须有**，否则多个会话同时被限流会同时重试，把 429 变成雪崩
- 重试**不产生事件**（它是实现细节），但重试耗尽产生 `error{recoverable:true}`，消息里带上试了几次
- **触发重新决策的条件**：出现需要按 provider 区分退避策略的情况（某家的 429 带 `Retry-After`）→ 届时把退避参数下放到 provider 声明

### SPEC-M1-003 · 切换模型如何不丢历史

- `model.switch` 是**新事件类型**，不改既有事件（INV-01）。上下文按新模型窗口重拼是 `buildContext` 的事，事件流一条不动
- AC-3 的"事件总数不变"因此是自动成立的——这正是选事件流架构换来的
- **触发重新决策的条件**：无。这条是 INV-01 的推论

### SPEC-M1-004 · 提示词分层与 cache 边界（M1 最要紧的一条）

- 层 = `{ id, role, priority, cacheable, render() }`。拼装顺序**只由 priority 决定**，与注册顺序无关
- **硬约束**：任一 `cacheable` 层排在非 `cacheable` 层之后 → **构建期抛错**。
  原因是 prompt cache 按**前缀**匹配：一旦前面混进会变的内容，后面所有 cacheable 层的缓存全部作废。
  这个错误在运行时表现为"缓存命中率莫名其妙很低"，极难排查——所以必须在构建期就炸
- 动态内容（时间戳、状态数据、剩余 token）**只允许出现在最后一条 user message**（AC-3）。
  这条是 M2「压缩 × prompt cache 交叉」的地基：压缩点选在哪，取决于前缀到哪里为止是稳定的
- **触发重新决策的条件**：provider 支持多个 cache breakpoint（不只前缀）→ 届时层模型要引入显式断点标记

### SPEC-M1-005 · 结构化输出的降级路径

- 支持原生的走 `response_format`；不支持的降级为"提示词约束 + 解析 + 重试 ≤3 次"
- **接口签名与返回类型对上层完全一致**（AC-3）——上层不该知道底下走的哪条路，否则每个调用点都要分支
- 3 次失败抛 `StructuredOutputError`，`raw` 带最后一次原文。**不静默返回 null**：调用方拿到 null 会当成"模型说没有"，而不是"我们没解析出来"
- **触发重新决策的条件**：降级路径的成功率在真实使用中低于 80% → 考虑改用 grammar/GBNF 约束（仅本地模型可用）

### SPEC-M1-006 · 会话分支语义

- 分支 = 新 sessionId + `parentSeq` 指向源会话的某个 seq。**事件不复制**：分支会话只存自己的新事件，读取时沿 parent 链拼接
- AC-3 的"另一分支事件集合不变"因此也是自动成立的
- 软删除：`sessions.deleted_at` 置位，**事件一条不删**（INV-01）。`domi session restore` 就是清掉这个字段
- **触发重新决策的条件**：沿链拼接在深分支下变慢（> 100ms）→ 届时做分支物化视图，与 SPEC-M0-002 的策略注册点同一套路

### SPEC-M1-007 · 指标是纯投影

- 状态栏的每一个数字都必须能从事件流算出来。AC-3 的断言方式（删掉状态栏模块 kernel 测试仍绿）是这条的机器判据
- 花费：价目表放配置，未知模型显示 `—` **且不参与累计**——显示 0 会让人以为免费，比显示"不知道"更糟
- **触发重新决策的条件**：无。这条是 INV-13 的前身

### SPEC-M1-008 · CLI 命令面

- 参数解析用 `util.parseArgs`（ADR-008 已定不引库）
- `domi doctor` 的每条问题**必须带一条可复制执行的命令**（AC-4 的正则断言）。
  "检测到 X 有问题"而不给命令，等于把排查工作原样退回给用户
- **触发重新决策的条件**：子命令超过 8 个（ADR-008 已写明）

### SPEC-M1-009 · 日志与事件流的分工

- ADR-008 决定不引 logger，理由是"事件流本身就是结构化日志"。M1-009 要的是**另一种东西**：
  与会话无关的进程级诊断（启动、配置装载、provider 连接、重试）
- 所以 `packages/observability` 只做这一类，**不记录会话内容**——会话内容在事件流里，记两遍必然不一致
- 脱敏**复用 `packages/store/src/redact.ts` 的同一份正则**，不另写
- **触发重新决策的条件**：M3 拆 daemon 后出现跨进程日志关联需求 → 那时才需要 trace id，也才可能真的需要 pino

### SPEC-M1-011 · 影子仓库（M1 第二要紧的一条）

- 候选 A：`isomorphic-git` —— 纯 JS，用户没装 git 也能用。缺点：大、慢、行为与真 git 有细微差异
- 候选 B：**spawn 系统 git**，`--git-dir` 指向 `~/.domi/shadows/<hash>`、`--work-tree` 指向工作目录
- **选 B**。理由：零依赖；行为与用户自己的 git 完全一致（这点在"回滚了什么"要给用户看时很关键）；
  且 domi 的目标用户是"有 CLI 习惯的开发者"（PRD-VISION §2），没装 git 的概率极低
- 没装 git 时：**功能降级并明确告知**，不是静默不快照——用户以为有安全网而实际没有，比没有安全网更危险
- **不污染用户 .git 的机器判据**（AC-1）：快照前后比对工作目录 `.git` 的 `HEAD`、index mtime、reflog 三者
- 回滚产生 `revert` 事件而非删除事件（INV-01/INV-12）；被 revert 区间标记 dead 但可读
- **回滚前先对当前工作区打快照**（AC-4），所以回滚可回滚。这条容易漏，漏了用户误点一次就回不去
- **触发重新决策的条件**：① 出现必须支持"用户机器没有 git"的真实诉求；② 大仓库下 `git add -A` 每步耗时 > 500ms

## 3. 接口契约（增量）

```ts
// packages/model/src/capability.ts
export interface ModelCapabilities {
  toolCall: boolean
  vision: boolean
  reasoning: boolean
  promptCache: boolean
  structuredOutput: boolean
}
export class UnsupportedCapabilityError extends Error {
  constructor(readonly provider: string, readonly capability: keyof ModelCapabilities) { super(...) }
}

// packages/prompt/src/layer.ts
export interface PromptLayer {
  id: string
  role: 'system' | 'user'
  priority: number
  /** 会变的内容必须声明 false，否则它后面所有 cacheable 层的缓存都作废 */
  cacheable: boolean
  render(ctx: PromptCtx): string
}
export function assemble(layers: PromptLayer[], ctx: PromptCtx): AssembledPrompt  // 违反 cache 边界时抛错

// packages/checkpoint/src/shadow.ts
export interface Snapshot { id: string; createdAt: number; files: number }
export interface ShadowRepo {
  available(): boolean                       // git 没装时返回 false，调用方必须明确告知用户
  snapshot(label: string): Promise<Snapshot>
  diff(from: string, to?: string): Promise<FileDiff[]>
  restore(id: string): Promise<void>         // 内部先给当前状态打一个快照（AC-4）
}
```

新增事件类型（SCHEMA_VERSION → 3）：
- `model.switch { from, to, reason }`
- `snapshot { id, label, files }`
- `revert { toSeq, snapshotId, scope: 'files'|'conversation'|'both' }`
