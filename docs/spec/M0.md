## 2. 取舍记录

> 本章是这份文档最有价值的部分。**每条必须写"触发重新决策的条件"，否则取舍会固化成教条。**

### SPEC-M0-001 · 事件存储引擎

- 候选 A：**SQLite（`bun:sqlite`，WAL）** —— 单文件零运维；FTS5 与 sqlite-vec 为 M2/M4 铺路；事务保证 PRD-M0-001 AC-4 的"无半条事件"。缺点：二进制格式，用户无法直接 `cat`
- 候选 B：JSONL 追加文件 —— 人类可读、天然 append-only、`tail -f` 即轨迹。缺点：无事务（AC-4 做不到）、检索要全量扫、并发写要自己做锁
- **选 A**。理由：AC-4 要求崩溃后无半条事件，这是**事务语义**，B 只能靠 fsync + 校验和近似，代价比换库高。B 的"人类可读"诉求由 `domi data export`（PRD-M1-010 AC-1）满足——**导出为 JSONL，不是存储为 JSONL**
- 反悔成本：**中**。事件读写全部收敛在 `packages/store` 的 `EventLog` 接口后，换实现不影响 kernel；但已有用户数据需要迁移工具
- **触发重新决策的条件**：① `bun:sqlite` 在目标平台出现 native 兼容问题（由 spike ADR-001 的 native 模块兼容清单判定）；② 单会话事件数超 100 万时插入 P95 > 5ms

### SPEC-M0-002 · 上下文拼装策略

> **2026-09-14 回写（`docs/adr/005`）**：本条从"一次性取舍"改为"运行期可选项"。
> 原文保留在下方划线处，因为它记录了当初为什么选 A——那个理由今天仍然成立。

- 候选 A：**全量拼装** —— `buildContext` 每次遍历全部事件重建 messages。简单、纯、易测
- 候选 B：增量物化视图 —— 维护一个随事件推进的 messages 缓存。快，但要处理失效与回滚，复杂度高
- ~~**选 A**~~ → **改为：策略是 `ContextPolicy.strategy` 上的可选项，默认 `'full'`，经注册表挂载。**
  理由不变（M0 的目标是打通链路不是性能），变的是**决策的形态**：不再需要一次压测来裁决，
  加增量实现变成"挂一个策略"而不是"改 `buildContext`"
- **限定（ADR-005 的重点）**：option 只是**注册点，不是两套实现**。M0 只实现 `'full'`，
  `'incremental'` 占位且调用即报错——**不得静默降级为 `'full'`**，静默降级会让这条限定失效且无人察觉
- `'full'` 是 `'incremental'` 的**正确性基准**：将来实现增量时，验收标准是它的输出与 `'full'` 逐字节相同。
  这一条从"将来做 B 时的现成测试"升级为**硬约束**
- 反悔成本：**低** → **更低**（从"替换一个实现"降为"注册一个策略"）
- ~~**触发重新决策的条件**：spike ADR-002 实测 5 万事件 > 200ms~~ →
  **触发重新激活压测的条件**（见 ADR-005）：① TUI 出现可见卡顿；② 会话事件数超 2 万；③ M2 要做压缩策略 A/B
- **已知代价**（ADR-005 §Consequences 详列）：少了一个可判定的数字；多了一个可配置面；
  策略注册表在 M0 没有第二个使用者，是为 M2 压缩策略 A/B 付的首付

### SPEC-M0-003 · 模型层边界

- 见 `docs/adr/004-model-layer-ai-sdk.md`（已采纳）。此处只钉边界：
- **`packages/kernel` 不得 import AI SDK 或任何 provider SDK**，只 import `packages/model` 导出的类型（守 INV-02，由 dependency-cruiser 规则 `no-io-in-kernel` 阻断）

### SPEC-M0-004 · 事件 schema 的前向兼容策略

> 这条直接守 INV-01 的"**任意历史事件永远可解析**"，是 M0 最容易被做漏的一条。

- 候选 A：严格 zod 解析，未知事件类型抛错 —— 类型安全，但**违反 INV-01**：将来新增事件类型后，旧版本 domi 读新会话必崩
- 候选 B：**判别联合 + 未知类型降级为 `UnknownEvent`** —— 已知类型走严格 schema，未知 `t` 保留原始 JSON 并标记 `parsed:false`，渲染层显示为"未知事件（v{n} 产生）"
- **选 B**。理由：INV-01 承诺的是"可解析"不是"可理解"。降级保留原文，既不丢数据也不崩
- 配套硬规则：**事件字段只增不改不删**；新增字段必须可选且有默认值。由 `packages/protocol` 的契约快照（`.api.md` 提交进仓库）在 CI 中暴露任何契约变更
- **回写（2026-09-14，TASK-M0-009 触发）**：判别联合的每个分支必须 `.passthrough()`。
  zod 默认 strip 会让「已知类型 + 未来新增字段」在 `read()` 时静默丢字段——payload 还在磁盘上，内存里没了，
  轨迹与 `domi data export` 都看不到。这是 INV-01 的另一种违反方式，光靠「未知类型降级」堵不住
- **回写（同上）**：`.api.md` 原计划 dump tsc 的类型字符串，实测 zod schema 展开有 7 万字符，人看不了、diff 也读不了。
  改为**语义快照**：事件类型集合 + 每类型字段与可选性 + 信封字段，约 1.1k 字符。
  判据是「这份 diff 人会不会真的读」，不是「信息是否完整」
- **回写（2026-09-14，`docs/adr/006`）**：升到 zod 4 后 `.passthrough()` 改写为 `z.looseObject()`，语义不变；
  `gen-api-snapshot.ts` 的内省入口从 `_def.typeName` 改为 `_zod.def.type`。
  升 zod 大版本时这个脚本必然先红——这是它该做的，不是缺陷
- 反悔成本：**高**（一旦有用户数据就改不动）
- **触发重新决策的条件**：无。这条是不变量的实现，不接受重新决策；要改需改 INV-01，走 ADR

### SPEC-M0-005 · 权限引擎

- 结构：`PermissionEngine.check(capabilityId, ctx) → Decision`，**默认分支返回 `deny` 而非 `ask`**（PRD-M0-003 AC-4 fail-closed）
- 决策来源三级：`default`（deny）< `config`（用户配置文件规则）< `user`（本次会话的交互式回答）。每次决策产出事件，**必含** `capabilityId` / `decision` / `source` / `matchedRule`
- 路径穿越防护统一在**一个函数** `resolveWithinRoot(root, p)`：先 `realpath` 再 `relative`，`relative` 以 `..` 开头或为绝对路径即拒。8 类用例（`../`、绝对路径、符号链接、`..%2f`、NUL 截断、大小写变体、UNC、`~` 展开）作为该函数的单测表驱动
- **触发重新决策的条件**：接入 MCP（M2）后出现"同一 capabilityId 需要按 server 区分授权"的需求 → 届时把 capabilityId 扩展为带 scope 的结构

### SPEC-M0-006 · Tool 注册与 Capability 类型

- `Tool` 是唯一执行原语（INV-05）。每个 Tool 声明 `capability: CapabilityId`，**类型系统保证无 capability 的 Tool 无法注册**（编译期守 INV-05）
- Skill 在 M0 不存在，但类型上先把 `Skill` 定义为**不含 `execute` 成员**的结构，防止 M4 时被顺手加上
- M0 三个内置 Tool：`fs.read` / `fs.write` / `shell.exec`
- **触发重新决策的条件**：M2 接入 MCP 时，若 MCP tool 无法自然映射为同一 `Tool` 接口 → 重新评估"MCP 是 tool 的来源"这一决策（DESIGN 决策三）

### SPEC-M0-007 · Agent loop 的终止条件

- 三个独立计数器，任一触发即停并产出 `error{recoverable:true}`：
  - 单轮工具调用次数 ≥ **20**（PRD-M0-002 AC-2）
  - 同一 `tool.call` 的参数解析重试 ≥ **3**（AC-3，第 4 次终止）
  - 单轮墙钟时间 ≥ **10 分钟**（M0 新增护栏，防止 spike 期挂死）
- 计数器状态**不进事件流**（它是投影，由事件流算出），但触发时的终止事件必须含三个计数器的当时值，供轨迹排查
- **触发重新决策的条件**：M5 长任务需要突破 20 次上限 → 届时改为按 token 预算而非次数

### SPEC-M0-008 · TUI 选型

- **留白**：OpenTUI vs Ink 由 spike ADR-001 决定（PRD-M0-007 AC-1），本 SPEC 不预设
- 无论选哪个，**渲染层零业务逻辑**（INV-02）：TUI 只消费 `client-core` 暴露的 store 快照；`apps/tui` 不得 import `packages/kernel|store`
- golden 快照测试在 40/60/80/200 四种宽度下跑（PRD-M0-005 AC-4），**快照文件提交进仓库**

### SPEC-M0-009 · 配置装载与脱敏边界

- 优先级：环境变量 > `~/.domi/config.toml` > 内置默认
- **脱敏发生在事件写入边界**（`EventLog.append` 的前置钩子），不是在渲染层。理由：渲染层脱敏挡不住 `domi data export` 和日志文件
- 5 类凭据正则集中在 `packages/store/src/redact.ts` 一处，`scripts/scan-secrets.ts` 与运行时共用同一份常量——**两处各写一份必然漂移**

## 3. 接口契约

> 可直接复制进代码。`packages/protocol` 是唯一契约来源，其余包只 import 不重定义。

### 3.1 事件信封与事件类型

```ts
// packages/protocol/src/event.ts
import { z } from 'zod'

export const SCHEMA_VERSION = 1 as const

export const RefSchema = z.object({ kind: z.string(), id: z.string() })

/** 已知事件。新增类型只允许追加，不允许改既有字段（INV-01 / SPEC-M0-004） */
/** 每个分支都用 z.looseObject（zod 4 里 .passthrough() 的替代）：已知类型 + 未来新增字段时字段必须留下来 */
export const DomiEventSchema = z.discriminatedUnion('t', [
  z.looseObject({ t: z.literal('user.input'),    text: z.string(), attachments: z.array(RefSchema).optional() }),
  z.object({ t: z.literal('model.request'), provider: z.string(), model: z.string(), tokensIn: z.number().int().nonnegative() }),
  z.object({ t: z.literal('model.delta'),   text: z.string() }),
  z.object({ t: z.literal('model.reason'),  text: z.string() }),
  z.object({ t: z.literal('model.usage'),   raw: z.record(z.unknown()) }),        // ADR-004：原始 usage 原样透传
  z.object({ t: z.literal('tool.call'),     id: z.string(), name: z.string(), args: z.unknown() }),
  z.object({ t: z.literal('tool.result'),   id: z.string(), ok: z.boolean(), payload: z.unknown(), ms: z.number().int().nonnegative(), reason: z.string().optional() }),
  z.object({ t: z.literal('permission'),    capabilityId: z.string(), decision: z.enum(['allow','deny','ask']), source: z.enum(['default','config','user']), matchedRule: z.string().nullable() }),
  z.object({ t: z.literal('error'),         scope: z.string(), message: z.string(), recoverable: z.boolean() }),
])
export type DomiEvent = z.infer<typeof DomiEventSchema>

/** 未知事件降级壳：保留原文，永不丢弃（INV-01 的"永远可解析"） */
export const UnknownEventSchema = z.object({
  t: z.string(),
  __unparsed: z.unknown(),
  __schemaVersion: z.number().int(),
})
export type UnknownEvent = z.infer<typeof UnknownEventSchema>

export const EventEnvelopeSchema = z.object({
  seq: z.number().int().positive(),
  sessionId: z.string(),
  parentSeq: z.number().int().positive().nullable(),
  ts: z.number().int(),
  schemaVersion: z.number().int(),
  ev: z.union([DomiEventSchema, UnknownEventSchema]),
})
export type EventEnvelope = z.infer<typeof EventEnvelopeSchema>
```

## 4. 数据契约

### 4.1 表结构

```sql
-- 事件表：append-only。没有 UPDATE / DELETE 语句（PRD-M0-001 AC-3，AST 扫描）
CREATE TABLE IF NOT EXISTS events (
  session_id     TEXT    NOT NULL,
  seq            INTEGER NOT NULL,
  parent_seq     INTEGER,
  ts             INTEGER NOT NULL,
  schema_version INTEGER NOT NULL,
  type           TEXT    NOT NULL,       -- ev.t，冗余出来便于索引与未知类型统计
  payload        TEXT    NOT NULL,       -- ev 的 JSON 原文
  PRIMARY KEY (session_id, seq)
) STRICT;

CREATE INDEX IF NOT EXISTS idx_events_type ON events(session_id, type, seq);

CREATE TABLE IF NOT EXISTS sessions (
  id         TEXT PRIMARY KEY,
  created_at INTEGER NOT NULL,
  cwd        TEXT NOT NULL
) STRICT;

CREATE TABLE IF NOT EXISTS meta (k TEXT PRIMARY KEY, v TEXT NOT NULL) STRICT;  -- 存 schema_version
```

- **PRAGMA**：`journal_mode=WAL` / `synchronous=NORMAL` / `foreign_keys=ON`
- **seq 分配**：在同一事务内 `SELECT COALESCE(MAX(seq),0)+1` 后插入，靠主键唯一约束兜底；并发写在 M0 由单进程保证（daemon 拆分是 M3）

### 4.2 迁移策略

- `meta.schema_version` 记录当前版本。启动时若磁盘版本 < 代码版本，跑迁移；若磁盘版本 **>** 代码版本，**只读打开并警告**，不拒绝启动（守 INV-01）
- 迁移只允许：补默认值、新增列、新增索引。**禁止修改或删除既有事件字段**（PRD-M2-007 AC-2）
- `fixtures/events/legacy-v{n}.jsonl` 每次版本升级追加一份，CI 混合加载并重放（PRD-M0-001 AC-5）
