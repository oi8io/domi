# SPEC-M10 · 会话体验与运行控制

> PRD：`docs/prd/M10.md`（COMMITTED）· 复核：`docs/qa/M10-prd-review.md` · 状态：`COMMITTED` · 2026-09-19
> 覆盖：PRD-M10-001（标题接入运行时）· PRD-M10-002（默认模型互斥确认）· PRD-M10-003（运行时护栏可配置）· PRD-M10-004（TUI 语言切换）· PRD-M10-005（思考折叠）
> 决策：loop 默认值 100（M0-002 AC-2 走回写门，见 PRD v1.13）；TUI 语言「下次启动生效」（M10-prd-review D-2）

## 1. 要解决的问题

五个独立的小需求，均不触碰事件流格式与 kernel 语义：
- 侧边栏可读标题：`generateTitle()` 已存在却从未被生产代码调用，列表空标题回退显示会话 id。
- 护栏可配置：`DEFAULT_LIMITS` 硬编码在 kernel，用户不能在不改代码的情况下调一轮的上限。
- TUI 设置：TUI 只有 `/lang` 一键切换与命令行参数，没有正式的设置入口。
- 思考折叠：长 `reason` 条目淹没对话流，纯展示层问题。

## 2. 取舍记录

### 取舍-1（M10-001）标题触发点：submit 完成后 fire-and-forget，判据三重
- **位置**：`runtime/src/session.ts` 的 `submit()` 成功路径末尾（`finally` 中 `this.pump()` 之后），`void this.maybeAutoTitle()`，不 await（LLM 调用不阻塞用户侧返回，与 `memory.afterTurn` 同模式）。
- **判据**（三者全满足才触发，防重复）：`sessions.get(id)?.title` 为空（trim 后）· 事件流已含 `assistant` 事件（第一轮已产出，沿 parent 链不算）· 会话内存标记 `titleTried` 未置位（本次 daemon 生命周期内不重复尝试）。
- **失败不重试**：`generateTitle` 内部已有 `try/catch` 降级（失败 = 空标题不产生错误）；daemon 重启后 `titleTried` 清零，下一轮自然再试。PRD §7「不重试」由此满足。
- 为什么不在 append 首条 assistant 时触发：append 是 store 层，无 session 对象上下文，且可能来自回放/导入（不应触发 LLM）。

### 取舍-2（M10-001 AC-2）列表空标题 fallback：store `list()` SQL 派生列，非端上逻辑
- **不迁移、不加列**：`SessionRepo.list()` 的 SELECT 加一个子查询派生列：
  `(SELECT substr(json_extract(e.payload, '$.text'), 1, 40) FROM events e WHERE e.session_id = s.id AND e.type = 'user.input' ORDER BY e.seq LIMIT 1) AS first_input`
  事件表已有 `idx_events_type(session_id, type, seq)` 索引，`ORDER BY seq LIMIT 1` 走索引；最多 500 行列表，可接受。
- **投影层语义**（INV-01 精神）：事件是唯一真相，`first_input` 是读时算的派生值，删库重建也能算出来；不写库 = 不需要迁移 = 不碰 guard:migrations。
- **daemon 投影**（`runtime-host.ts list()`）：`title: r.title.trim() !== '' ? r.title : (r.firstInput ?? '')`。fallback 只取**本会话**首条 user.input（不含祖先链，分支场景极少且标题生成会覆盖）。
- **端上**：Web `titleOf` 改为直接返回 `title`（daemon 已保证非空）；TUI 会话列表用同一 `session.list` 数据，自动受益。AC-2「不再显示会话 id」由此成立。
- 注意：`generateTitle` 的 fallback 也是 40 字首条输入（`title-gen.spec.ts` 既有断言），与派生列口径一致（`slice(0, 40)` + `trim()` 前后处理一致即可，SPEC 不强求同字符索引）。

### 取舍-3（M10-003）loop 配置：schema 加节 + runtime 传入，kernel 零改动
- **kernel 不动**：`loop.ts:113` 已是 `{ ...DEFAULT_LIMITS, ...deps.limits }`，AC-3「kernel 只收 LoopLimits、不读配置」现状成立。
- **config**：schema `loop` 节 `{ maxToolCalls: 100, maxArgParseRetries: 3, maxWallClockMs: 600_000 }`；`write.ts` 白名单加 `loop.maxToolCalls` / `loop.maxArgParseRetries` / `loop.maxWallClockMs`，`readSettings` values 加三项（`config.get` 能返回）。
- **runtime**：`submit()` 构造 `runTurn` deps 时 `limits: { maxToolCalls: cfg.loop.maxToolCalls, maxArgParseRetries: cfg.loop.maxArgParseRetries, maxWallClockMs: cfg.loop.maxWallClockMs }`。默认值与 `DEFAULT_LIMITS` 一致 → 不配置时行为完全不变（AC-4 回归）。
- **验证值域**：schema 的 `z.coerce.number().int().min(1).max(1000)`（wallclock 用 `.min(1_000)`）；非法值被 schema 拒绝，Web 提示（AC-2）。
- 与 M0-002 AC-2 的关系：回写后 M0 AC-2 引用 `loop.maxToolCalls` 默认值；`20-tool-loop` fixture 注入 `limits: { maxToolCalls: 20 }` 验证行为，不依赖默认值（已核实 loop.spec.ts 写法，SPEC 阶段再确认一次）。

### 取舍-4（M10-004）TUI 语言切换：`/settings` 命令 + 「下次启动生效」
- **不做热切换**：TUI locale 在 `main.tsx` 启动时 `setLocale(resolveLocale(...))` 定死；热切换需重建 Ink 树（reconciler 单例，易碎），成本收益不成比例。
- **入口**：新增 `/settings` 命令（`commands.ts` 注册，命令补全可见），渲染一个简单选择层：跟随系统 / 简体中文 / English。选择后 `config.set({ 'ui.locale': value })` 并提示「下次启动生效」。
- **与 `/lang` 的关系**：`/lang` 是 M9 的一键切换（写 `ui.locale`，同样下次启动生效），`/settings` 是正式入口；两者写同一配置键，行为一致，不冲突（`/lang` 保留）。
- Web 设置页的「语言」本来就即时生效（re-render），不回退。

### 取舍-5（M10-005）思考折叠：纯展示层，截断复用 summarizeArgs 口径
- **Web**（`apps/web/src/Transcript.tsx` `case 'reason'`）：默认折叠态——单行「思考 · `truncate(text, 80)`」，点击行展开/收起全文。局部 state（`collapsed: Set<eventId>`），会话内可反复切换，不持久化（AC-3）。
- **TUI**（`apps/tui/src/components/Transcript.tsx`）：reason 行默认折叠，`Enter` 切换展开/收起（不占滚动键）；折叠态显示前缀与截断文本。
- **截断口径**：`packages/client-core/src/store.ts` 的 `summarizeArgs` 用的 `ARG_SUMMARY_LIMIT`（80 字符）原则——单行摘要用同一常量/原则（新增 `summarizeReason` 或复用 truncate 工具），**渲染层不自行二次截断**（AC-4）。实现时统一放 client-core 导出的截断函数，Web/TUI 共用。
- 事件流零改动（INV-01 天然满足，AC-1 后半句）。

### 取舍-6（M10-002）默认模型互斥：零代码，回归验证
- M9 已实现（`model.provider + model.name` 单一来源、`ConfigWriteError(DEFAULT_PROVIDER)`）；本册只在收口时跑既有测试 + 一条新回归断言（如果缺就补），不做任何实现改动。

## 3. 协议增量

**无新 RPC 方法、无方法参数变化。** 三处响应/行为变化：
1. `config.get` 返回的 values 里新增 `loop.*` 三项（readSettings 扩展）。
2. `session.list` 的每个 session 若 `title` 为空则返回首条输入 fallback 标题（响应字段 `title` 本身变化，字段集不变）。
3. `config.set` 白名单新增 `loop.*` 三键（非法值被 schema 拒绝，与既有 `ConfigWriteError` 路径一致）。

## 6. 风险与回退

- **标题触发会调真实 LLM**：只在「无标题且第一轮已产出」时触发一次；测试全用注入替身（INV-08）；用户可接受第一次对话多一次模型调用（约几千 token）。
- **first_input 派生列性能**：子查询走 `idx_events_type`，500 行上限；若实测慢可缓存，但预期无问题。
- **M0-002 AC-2 回写影响**：`20-tool-loop` fixture 按注入 limits 验证（不依赖默认值）→ 无测试改动；实现时先确认再动手。
- **TUI `/settings` 与 `/lang` 并存**：同一配置键，行为一致，无冲突。
- **预算 3 天**：超 20% 先砍 Web 运行时 tab 的装饰（单位标注等），保核心输入与保存。
