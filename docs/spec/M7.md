## 2. 取舍记录

- **取舍-1 · 后台 job 的查询归 fs.read**（回写 PRD v1.9.1）。候选：归 `shell.exec`（原 AC）/ 新能力 `shell.job` / 归 `fs.read`。
  选 `fs.read`：查询只读已产生的输出；归 `shell.exec` 在默认 ask 下每次轮询都弹框；新能力违反「不新增类别」。
  反悔成本：改一个工具的 capability 字段。重新决策的条件：出现能从输出里读到用户没授权内容的途径。
- **取舍-2 · 过期写保护只拦「读过之后被外部改了」**。`fs.edit` 必须先读（不读没法给出 old）；
  `fs.write` 覆盖一个本会话**从没读过**的文件仍然放行——M0 起的行为与测试不变。反悔成本低：`FileStamps.requireRead` 一个开关。
- **取舍-3 · 文件清单用 `git ls-files`**。候选：自己解析 .gitignore（`ignore` 包）/ 调 git。在 git 仓库里用
  `git ls-files -co --exclude-standard`（与用户的 git 行为完全一致，嵌套 .gitignore、全局 excludes 都对）；
  不是 git 仓库时退回内置排除表（与步级快照同一张）。
- **取舍-4 · ripgrep 有则用、无则退回 TS 实现**（用户拍板）。两个后端输出同一个结构；doctor 显示用的是哪个。
- **取舍-5 · 钩子在权限之后、执行之前**。先过权限：被拒的调用不该触发任何用户命令；pre 钩子是「允许之后的额外否决」。
- **取舍-6 · 验证的判定靠命令模式匹配**，不靠模型自报。`verify.command`（配置）或默认模式表
  （`test` `check` `tsc` `lint` `pytest` `cargo test` `go test` `vitest` `jest`）命中且退出码 0 = 验证成功。
  会误判「跑了一个不相干但名字像的命令」，代价是少追一次提示；反过来靠模型自报则可以被模型编出来。
- **取舍-7 · 计划模式是权限的一种范围**，和子 agent 的 `scope` 同一个机制，只是拒绝来源标 `mode`。
- **取舍-8 · worktree 的「带回」只做三种**：squash（默认）、merge、只留分支。不做 rebase、不处理冲突——
  原仓库在相关文件上有未提交改动时直接拒绝并说明。
- **取舍-9 · codeintel 懒加载 TypeScript**。它 ~9MB，单文件发行版会变大，但只在第一次调用 `code.*` 时才加载，冷启动不受影响（NFR-01）。
- **取舍-10 · 出题只支持「能用一条命令跑指定测试文件」的仓库**：`--test-cmd "bun test {files}"`，缺省按锁文件猜（bun / pnpm / npm / pytest）。

## 3. 条目

### SPEC-M7-001 · 编码工具

| 工具 | 能力 | 参数 | 结果要点 |
|---|---|---|---|
| `fs.edit` | fs.write | `path` `old` `new` `replaceAll?` | 0 次 → `not_found` + 最相近的 3 行（行号）；多次且非 replaceAll → `ambiguous` + 各处行号；成功 → 替换次数、前后指纹事件 |
| `fs.glob` | fs.read | `pattern` `path?` `limit?`(200) | `files[]`、`total`、`truncated` |
| `fs.grep` | fs.read | `pattern` `path?` `glob?` `ignoreCase?` `context?` `limit?`(100) | `matches[{path,line,text,before?,after?}]`、`total`、`truncated`、`backend: rg|builtin` |
| `shell.exec` | shell.exec | 新增 `background?` | 后台时立刻返回 `jobId` |
| `shell.output` | fs.read | `jobId` `wait?`(ms，≤30s) | 自上次查询以来的新输出、`running`、`exitCode` |
| `shell.kill` | shell.exec | `jobId` | 杀进程组并确认回收 |

- **过期写保护**：`FileStamps`（每个 ToolRegistry 一份）记「本会话最近一次读到 / 写出的内容哈希」。
  `fs.read` 记整文件哈希（哪怕只读了几行）；`fs.write` / `fs.edit` 写完更新。覆盖已有文件时：有记录且与磁盘不同 → `stale`，文件不动。
- **输出落盘**：前台与后台超过 100KB 时，全文写到 `~/.domi/outputs/<会话>/<调用 id>.log`，结果里给 `fullOutput` 路径（可以用 fs.read 读——它在工作目录外，所以 fs.read 对这个目录单独放行只读）。
- 后台 job 随会话关闭、daemon 退出一起杀掉。

### SPEC-M7-002 · 规矩文件、项目目录、信任

- 仓库根：从 cwd 向上找 `.git`（目录或文件）。找不到就把 cwd 当根。
- 规矩层 `project.rules`（system、priority 320、cacheable）：根 → cwd 每一级，`AGENT.md` 优先、否则 `AGENTS.md`；
  每段前写 `# 来自 <相对路径>`；总长上限 32KB，超出截断并标注。每轮现读（改了下一轮生效）。
- 项目目录 `<根>/.domi/`：`skills/<名字>/SKILL.md`。会话的 Skill 清单 = 共享的 SkillRegistry 叠一层项目 Skill（`SkillOverlay`），
  同名时项目的覆盖，`source: 'project'`。
- 信任：`~/.domi/trust.json` 记 `{ 根路径: { trusted, at } }`。有东西可加载（规矩文件或 `.domi/`）而没有记录时，第一轮开始前问
  （询问的能力 id 是 `workspace.trust`）；回答落 `workspace.trust {root, trusted, source}` 并写回 trust.json。
  没人能回答 → 本会话不信任、**不写回**（下次有人时再问）。`domi trust <路径> [--revoke]` 手动改。
- `domi init --project`：在仓库根建 `.domi/skills/`、`.domi/README.md`，没有 `AGENT.md` 时写一份模板。domi 在别处从不创建 `.domi/`。
- 本仓库的 `.gitignore` 从忽略整个 `.domi/` 改成只忽略 `.domi/*` 里除 `skills/`、`README.md` 以外的东西。

### SPEC-M7-003 · 钩子

```yaml
hooks:
  - name: no-coauthor
    on: pre                 # pre | post | stop
    match: shell.exec       # 能力 id，支持 前缀.*；stop 不看它
    run: domi-hook-commit-msg   # sh -c 执行，工作目录 = 会话 cwd
    timeoutMs: 10000        # 默认 10s
```

- 环境变量：`DOMI_HOOK`（pre/post/stop）`DOMI_TOOL` `DOMI_CAPABILITY` `DOMI_SESSION` `DOMI_CWD`，
  参数里有 `path` / `cmd` 时另给 `DOMI_PATH` / `DOMI_CMD`；stdin 是 `{tool, args, result?}` 的 JSON。
- pre：退出码非 0 → 不执行，结果 `ok:false reason:'hook_blocked'`，stdout+stderr（截断 4KB）作为理由。超时 = 拦截。
- post：输出附在结果的 `hooks` 字段；超时或非 0 只记录，不改 ok。
- stop：一轮结束后跑，只记录。
- 每次执行一条 `hook.run {name, on, capabilityId?, ms, exitCode, blocked, timedOut, output}`。
- 钩子**只从 `~/.domi/config.yaml` 读**。仓库里没有任何读取点。
- `domi init` 模板附两个示例（注释状态）：提交信息拦截与暂存区密钥扫描，脚本随包放在 `hooks/` 下由 `domi hook <名字>` 调用。

### SPEC-M7-004 · 完成前验证

- `kernel/verify.ts`：`verifyState(events, matcher)` → `'clean' | 'unverified' | 'verified' | 'failed'`，只看**本轮**
  （最后一个 `user.input` 之后）：有 `fs.snapshot{phase:'after'}` 之后没有成功的验证运行 = unverified；最近一次验证失败 = failed。
- loop 新端口 `beforeComplete(events) → string | null`：模型要结束时调用，返回提示就落 `verify.required {attempt, message}` 并再来一轮；
  `buildContext` 把 `verify.required` 渲染为一条 user 消息（标注「运行时提示」）。
- 上限 `verify.maxNudges`（默认 2），到了落 `verify.required {attempt, final:true}`，TurnResult 带 `verify:'unverified'`。
- `verify.enabled: false` 关掉。指标快照与轨迹加 `verify` 字段。

### SPEC-M7-005 · 计划模式

- `mode.switch {to: plan|act}`；协议 `session.mode`；TUI `/plan` `/act`；Web 输入框旁的开关。
- plan 模式下 `PermissionConfig.mode` 只放行只读能力（`fs.read` `memory.*` `skill.load` `code.*` `plan.submit`），
  其余 `deny`，`source:'mode'`，`matchedRule:'plan-mode'`。
- `plan.submit {plan, steps?[{id, goal, dependsOn?}]}`（只在 plan 模式下注册）：落 `plan.proposed`，问用户（表单：批准 / 驳回 / 意见 / 转成长任务），
  落 `plan.decided {approved, comment?, asTask?}`；批准 → 追加 `mode.switch{to:act}`；转长任务 → 步骤生成 agent-step 节点的 DAG，经 `parseDagSpec` 校验后由宿主启动。

### SPEC-M7-006 · worktree

- `session.create {isolate:true}`：cwd 所在仓库 → `~/.domi/worktrees/<仓库哈希>/<会话>`，分支 `domi/<会话>`，基于 HEAD；
  落 `worktree.create {repo, path, branch, base}`；会话的 cwd 就是 worktree。非 git → `NOT_A_REPO`。
- `worktree.diff` → `[{path, status, patch}]`（相对 base，含未跟踪文件）。
- `worktree.discard {path}` → 文件内容先存进 `~/.domi/worktrees/.trash/<会话>/<n>`，再恢复成 base；落 `worktree.discard {path, trash}`；
  `worktree.restore {trash}` 放回并落事件。
- `worktree.apply {mode}` → 问人（`worktree.apply` 询问）→ 在 worktree 里提交未提交的改动 → squash / merge 到原仓库当前分支，或只留分支；
  原仓库在涉及的文件上有未提交改动 → 拒绝。落 `worktree.apply {mode, commit?, ok, message}`。
- 删除会话：worktree 有未提交改动 → 拒绝；否则 `git worktree remove`，分支保留。

### SPEC-M7-007 · codeintel

- `code.outline {path}`：文件或目录（目录经 file-list，最多 50 个文件）；每个导出：种类、名字、签名（声明文本去掉函数体，单条 ≤ 300 字符）、行号；总长 ≤ 16KB。
- `code.diagnostics {path}`：找最近的 tsconfig，每个 tsconfig 一个 LanguageService 常驻；文件版本按 mtime。返回 `[{file, line, col, code, message}]` 与 `ms`。
- 两个都归 `fs.read`；非 `.ts/.tsx/.js/.jsx/.mts/.cts/.mjs/.cjs` → `unsupported`。

### SPEC-M7-008 · 出题

- `domi eval mine <仓库> [--since <日期>] [--limit N] [--test-cmd "..."] [--setup "..."] [--out eval/mined]`。
- 候选：非合并提交，改动同时含测试文件（`*.test.*` `*.spec.*` `test/` `tests/` `__tests__/`）与非测试源码。
- 每题：`workspace/` = 父提交的 `git archive`；`tests/` = 该提交版本的相关测试文件；`check.ts` 把 tests 拷进工作区后跑 test-cmd；
  `solution/` = 该提交里改动的非测试文件（删除的列进 `.delete`）；`task.yaml` 的 prompt = 提交说明去掉 trailer 行（`Co-Authored-By` `Signed-off-by` `Claude-Session` 等）+ 失败测试文件名。
- 验证：父提交 + tests → 必须失败；再放 solution → 必须通过；否则丢弃并在 `mine-report.md` 写原因。

### SPEC-M7-009 · 预算

- `budget: {tokens?, costUsd?, toolCalls?}`（配置默认值；协议 `session.budget` 按会话覆盖；DAG spec 顶层 `budget`）。
- `ToolRegistry` 新端口 `gate()`：每次工具调用之前算用量（aggregate 投影）；过 80% 落一次 `budget.warn`；
  到 100% 问人（`budget.exceeded` 询问，表单：继续 / 停止 / 新上限）→ `budget.decided`；停止 = 本次调用 `ok:false reason:'budget_stop'` 并结束这一轮。

### SPEC-M7-010 · 审阅

- `domi review [--base <ref>] [--spec <文件>]...`（协议 `review.start {cwd, base?, specs[]}`）：
  新会话 `review-*`，`spawnedBy` 指向发起会话（轨迹嵌套），范围 `fs.read` `code.*` `review.report`；
  首条输入 = diff（base..工作区）+ 需求文档全文 + 审阅要求，**不带发起会话的任何事件**。
- `review.report {findings[{file, line?, severity, problem, basis}]}` 落 `review.findings`；Web 按文件分组展示。
